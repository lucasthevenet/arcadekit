# arcadekit glossary

The words the packages, docs, specs and findings use. One vocabulary for the whole workspace.

**Declaration**: one part of a game as a named class, made by a builder: `class LevelSolved extends Game.Event("LevelSolved", { ... }) {}`. It carries its definition and its types and runs nothing by itself; a Layer or a loop hosts it. The kit's declarations are `Game.Event`, `Game.Command`, `Game.Rejection`, `Game.Simulation` (`arcadekit/game`), `Game.Engine` (`arcadekit/game/browser`), `Content` and `Asset` (`arcadekit/content`), `Coop` (`arcadekit/net/browser`), `Save` and `Setting` (`arcadekit/save`), and `CueTable` (`arcadekit/audio`) ([ADR-0020](docs/adr/0020-a-game-is-declared.md)). _Avoid_: definition, for the class; a definition is the object a builder takes.

**Simulation**: the DOM-free half of a game, its rules, declared with `Game.Simulation`: what a run's state is made from (`create`), how one step advances it (`step`), its step input as a Schema, the events it reports, the commands it takes with a handler for each (`apply`), and its sample. Its functions are plain code. Push-puzzle's is `PushPuzzle` and survivors' is `Survivors`. `Game.Loop` steps one, `Game.Engine` runs it in the browser, a lockstep session runs it on every peer, and a scenario checks it.

**Command**: a decision a player makes outside what their device holds, named in the imperative and declared with `Game.Command`: an upgrade pick, "continue lesson". An app sends one (`engine.send`, or the Co-op client's `send`, which has the same type), and the loop applies it at the start of the next step, before `step`, through the simulation's `apply` handler of its tag. A run changes only at a step: by its input and by commands. The rules may refuse one, with a rejection. Its sender hears the rules' answer after a listener of the same engine, lockstep session or Co-op client (`listen`, or a session's `subscribe`) has heard what the command's step reported, except from an engine whose frame threw (a crash) before its listeners had heard it all. In a lockstep run it rides its sender's step payload, so every peer applies it at the one step the host confirmed, with the sender's slot as its `player`. Not a Foldkit Command, which is how an app causes a side effect.

**Rejection**: a reason the rules refuse a command, named for what is wrong and declared with `Game.Rejection`: "offer closed". A command lists the rejections it can end with, its `apply` handler returns one in place of changing the state, and the sender's `send` fails with it. Nothing happened in the run, so it is not an event and only the sender hears of it: in a lockstep run every peer's rules refuse the command alike, and only the sender's peer has a sender to tell. A command that never reached the rules (no run, or the run ended first) is **dropped**, which is not a rejection: `CommandDropped`. In a lockstep run a drop speaks for the sender's own peer: its run stopped before its rules answered, whatever the other peers applied. _Avoid_: error, for a rejection; a refused command is the rules working.

**Scenario**: a specification of a simulation that runs it (`arcadekit/game/scenario`): given a run, after these steps and commands, it reported these events and refused these commands. It steps the real rules through `Game.Loop`, and fails if the run reported an event or refused a command the scenario didn't check, or if a command it sent was never applied. _Avoid_: story, which is Foldkit's `Story`, the test of an app's `update`; and scenario for survivors' long run, the fixed 20,000-step run its determinism tests pin.

**Loop**: what steps a simulation: a `Game.Loop` (`arcadekit/game`), made from a declared simulation with `Game.makeLoop`. It is a host with a `TypeId`, so `Game.isLoop` tells one from a look-alike, and its capabilities are its methods. It runs one run at a time, with its fixed clock, its commands, its events and its sample, and it owns the step order and the time policy; time and input come from its caller, so it needs no DOM and reads no clock. Its `frame` is the seam where every host plugs in: the browser engine's frame loop, tests and replays, and a lockstep session. The engine's `FrameSource` (`Game.Frames`) is its own frame clock: it times the engine's frames, which step by real time and then draw. It is not where stepping adapters plug in ([ADR-0010](docs/adr/0010-a-game-is-a-simulation-and-a-presentation.md)). In the kit's source, a loop stands on a kernel, the class `Kernel` (`packages/arcadekit/src/game/internal/kernel.ts`), which steps a `KernelSimulation`: the plain object a loop makes from a declared simulation. No entry exports either. The decisions before [ADR-0020](docs/adr/0020-a-game-is-declared.md) call them `GameLoop` and `GameSimulation`, as what a game wrote and ran. _Avoid_: `GameSimulation` and `GameLoop` for what a game declares and steps; those are `Game.Simulation` and `Game.Loop`.

**Run**: one play-through, from `start` to `stop`, the next `start` or a crash. A survivors run is one attempt to survive; a push-puzzle run is one attempt at one level. Restarting starts a new run with the same config. Each run has its own state object, made by the genre's `create`, so a view can tell runs apart by identity. A genre can end its run itself (survivors' `RunEnded` event, push-puzzle's `LevelSolved`). The loop keeps stepping the run until `stop`, the next `start` or a crash, and those steps do nothing.

**Step**: one fixed-length tick of the simulation (1/60 s by default), run by `Game.Loop`. Steps are numbered from 0 in each run (`stepIndex`), and an input source reads each one's input by that number. A slow frame can run several steps to catch up; an input source's `endStep` runs after each one, and its `endFrame` once per frame that ran at least one step. A step must be deterministic: the same state and input give the same result, in every JavaScript engine. It changes the state in place and returns nothing, may allocate what it reports (an event is rare), and allocates nothing per entity. So a genre's step uses only exact arithmetic (`+ - * /`, `Math.sqrt`, `Math.floor` and the like), never an implementation-approximated `Math` function or `**`; `arcadekit/core` has exact `hypot2`, `sin`, `cos` and `powInt`, and a lint rule enforces it ([ADR-0011](docs/adr/0011-a-step-uses-only-exact-math.md)). A step is plain code: it runs no Effect and reads no clock or random source of its own, so its time comes in as an argument and its randomness from the run's `Rng` ([ADR-0017](docs/adr/0017-effect-at-the-edges-plain-code-inside.md)).

**Turn**: one player action in a turn-based genre: a move or an undo in push-puzzle. A step holds at most one turn; most steps hold none. Don't use "step" for a turn or "turn" for a step.

**Frame**: one call of `Game.Loop`'s `frame`: zero or more steps, then one `endFrame` (if it stepped), the event flush and the sample check. With time for a budget, the loop counts at most 0.25 s of one frame and runs at most five steps in it. In the browser it is one animation frame (`requestAnimationFrame`), after which the view draws once. In a replay it is usually one step. Don't call a step a frame.

**Event**: a rare, meaningful fact a run reports to the outside ("level solved", "leveled up"), reported by a step and delivered by the loop after the frame's steps. Never per-entity data. An event's **payload** is the data it carries. Each genre declares its events once, in its root entry's `events.ts`, and apps use them in their Model and Messages. A declared simulation's events are `Game.Event` classes, each also its own Schema, reported with the step's `report` (push-puzzle's `LevelSolved`, survivors' `LeveledUp`, `HeroLeft` and `RunEnded`). A **sample** is the loop's read of the state for the UI (a HUD), also delivered as an event: every so many milliseconds on the time `Game.Loop`'s caller passes in (wall-clock time in the browser), or right after the game's **version** number changes (a turn-based HUD). Push-puzzle's sample is its `Hud` event, read after every turn; survivors' is its `Hud` event, read every 100 ms and, since its version moves when the run ends, once more right after the frame that ended the run: after `RunEnded`. _Avoid_: snapshot for a sample.

**Snapshot**: a copy of a run's whole state that could be restored. The kit has none (see finding 11). Don't call a sample a snapshot.

**Replay**: a deterministic re-run: the same config, seed and input script, with the same commands at the same steps, give the same run. Both genres' replay tests check it, running the simulation through the loop the demos run (`Game.Loop`); survivors' pins a recorded state hash and push-puzzle's a recorded end state. The push-puzzle demo's "Replay" button only starts the level again.

**State hash**: a 32-bit digest of the numbers a game lists from a run's state, in a fixed order, folded with `StateHash` (`arcadekit/core`): FNV-1a over each number's float64 bytes. Two runs that will play out differently should differ in it; what only a view reads is left out. _Avoid_: snapshot, checksum; hasher, for the value being folded.

**Input source**: where each step's input comes from (`Game.StepInput`): a device, a script or, for #25, a buffer of confirmed inputs. `read(step)` gives one step's input before that step, and may send `Game.Loop` a command, which the loop then applies in that same step. A genre's browser `Game.InputSource` is a `StepInput` that owns resources, usually wrapping an input controller, and ignores the step number; a script indexes by it. A source that reads presses forgets them after each step (`endStep`), so one press reaches one step.

**Input controller**: a player's devices on one element, read as a game's named axes and buttons (`InputController`, `arcadekit/input`): the keys, the gamepads, a drag on the element and a swipe. It is made from the viewport and the game's **bindings** (`InputController.Bindings`), each of its axes and buttons by name with the keys, gamepad buttons or stick, drag or swipe it is read from; `InputController.moveAxes` binds a pair of movement axes on every device. A genre's input source wraps one: it reads it in `read`, forgets its presses in `endStep` (`InputController.consumePresses`), so one press reaches one step, and disposes it in `dispose`. _Avoid_: controller alone, which players say of a gamepad; input source, which is what wraps one.

**Player inputs**: the step input of a simulation that several players can play (`PlayerInputs`, `arcadekit/game`): each player's input by **slot**, or null for a player with none this step, and the slots of the players leaving at this step. A slot is a player's place in the run's player order, host first in lockstep, fixed for the whole run. A simulation declares it as its `input` with `Game.PlayerInputs(OnePlayersInput)`, a Schema made from the Schema of one player's input, and every host then seats players the same way: `soloInput` puts one player's source at slot 0, and a lockstep session sends each player's own input, as that one-player Schema encodes it, and puts each at its slot. A struct with the same two fields written by hand is not one, since no host could read the one-player Schema from it: a host that seats several players refuses a simulation declared with it by throwing, and as a type error first where it infers the step input from the simulation it is handed (a lockstep session's options, and a Coop, which infers it from its engine's simulation; a type that names the step input has the throw alone). Survivors' is `SurvivorsInput`, of `HeroInput`.

**View**: a genre's `Game.View` (`arcadekit/game/browser`), made on each attach by its engine's `view`, for one player and in co-op alike. It draws a run into the viewport once per browser frame, after the frame's steps, and never changes the run's state. It is told the **local player** (`{ local }`: this browser's player, by slot, with every player's name) and reads `local.slot` when it draws, so a view of a run several players share follows its own player: the engine seats its one player at slot 0, and a Coop at the slot its lobby gave. A test or replay that steps a loop has no view. Not Foldkit's `view` function, which draws the app's UI. _Avoid_: renderer, which is `Stage`'s `WebGLRenderer`.

**Cue counter**: a running total in a genre's state of one moment that makes a sound, such as survivors' `hits` (in `World.cues`) or push-puzzle's `pushes` (in `Puzzle.cues`). The step bumps it and never reads it; it only goes up during a run (push-puzzle's undo leaves it alone and bumps `undos`), and the genre's state hash leaves it out (push-puzzle has no hash; its replay test checks the end state without them). A **sound view** (`SurvivorsSoundView`, `PushPuzzleSoundView`) is a second `Game.View` that compares each counter with the value it saw last frame and plays a sound for each one that rose ([ADR-0014](docs/adr/0014-sounds-come-from-cue-counters-read-by-the-presentation.md)). Not an event.

**Cue**: something in a run that makes a sound: a moment (a push, a kill), or a state that holds a sound while it lasts (survivors' aura hum). A genre names its cues once, in its cue table (`move`, `push`, `auraHum`), and its sound view decides when each plays: a moment when its cue counter rose, a state from the state itself. So `cues` is read by where it stands: in a cue table it is the cues by name, and in a run's state (`Puzzle.cues`, `World.cues`) their counters. Not an event.

**Cue table**: which of the app's sounds each of a genre's cues plays, declared by the genre with `CueTable` (`arcadekit/audio`): its cues by name, each with the Schema of what the app gives for it (`AudioSystem.SoundId`: a sound id of the app's sound list). The genre ships no sound. The app, which owns the files, gives the table its **sounds** (`MyCueTable.layer({ move: "step", ... })`, which refuses a cue left out and a sound for no cue); the class is the key of the service that gives them back (`sounds`, typed `CueSoundsOf<typeof MyCueTable>`); and the genre's engine names the class in `uses`, so its sound view plays `sounds.move`. A survivors weapon may name its shot sound in content, which the view plays in place of the table's `shot`. A table exists to hand a genre package the app's sounds: a game that keeps its sounds beside its rules, as grimbonk does, declares none, and its view takes a plain object. Push-puzzle's is `PushPuzzleCueTable` and survivors' is `SurvivorsCueTable` ([ADR-0014](docs/adr/0014-sounds-come-from-cue-counters-read-by-the-presentation.md)). _Avoid_: cue sounds, sound map, for the table; the sounds are what the app gives it.

**Audio system**: what an app and its sound views play sound through (`AudioSystem.AudioSystem`, `arcadekit/audio`), and the key of the service an app provides, bound to `audio` (`uses: { audio: AudioSystem.AudioSystem }`). Playing is a plain call that never fails: a sound before the first gesture unlocks audio, while the tab is hidden, past its voice cap or sooner than its minimum gap is dropped. Every sound plays through the `sfx` or `music` **bus**, and both through `master`. Its sounds are the app's **sound list** (`AudioSystem.SoundList`), loaded once with `load`, and a **sound id** (`AudioSystem.SoundId`) names one. In a browser it is `BrowserAudioSystem.layer` (`arcadekit/audio/browser`), an audio mixer over Web Audio; the **silent** one plays nothing (`AudioSystem.silent`, provided by `AudioSystem.layerSilent`), and a test makes one that records what it is asked with `AudioSystem.make`. A sound view puts it beside the drawing view with `combineViews`. The app owns the sound files and gives each genre's cue table its sounds; a genre ships none. _Avoid_: sound manager; `Audio`, which is the browser's `HTMLAudioElement`.

**Audio mixer**: the audio system behind the browser's (`AudioMixer.AudioMixer`, `arcadekit/audio`): sounds by id, the buses, each sound's voices, loops and music, playing into the **output** its host unlocks it with (`AudioMixer.unlock`: Web Audio's on the player's first gesture, a fake in a test) and silent while its host says the page is hidden (`AudioMixer.setHidden`). A game plays through its `system`, never through the mixer. It is made for the life of a scope (`AudioMixer.make`), which stops its voices when it closes, and draws its jitter from Effect's `Random`, since it is presentation and no step. _Avoid_: audio engine, which is a `Game.Engine`'s word.

**Viewport**: the DOM element the view draws a run into and the input source reads input from. The engine calls it `element` in `attach`; the view gets it as `container` and the input source as `surface`. In a Foldkit app, `gameViewport` (`arcadekit/foldkit`) renders it, and `engineEntry` keeps the engine attached to it while it is in the document. `engineEntry` takes `onError`, the Message sent if the engine fails to load or to attach, or crashes. One per document.

**Manual frames**: a frame source a test runs by hand (`ManualFrames`, `arcadekit/game/testing`): `ManualFrames.make()` makes one, a test provides it as `Game.Frames`, and `ManualFrames.runFrameAt(frames, ms)` runs the frame an engine or a Co-op client asked for, at that time, inside the test's own call. `ManualFrames.waiting(frames)` says whether a frame was asked for and hasn't run. _Avoid_: clock, for it: it gives a frame's time only when a test runs the frame.

**Lockstep**: how peers play one run together (#25, `arcadekit/net`): each sends only its input, and every peer runs step N once it has every player's input for step N, so all runs stay identical without sending state. The kit's lockstep is delay-based: no prediction, no rollback and no snapshots; a step whose inputs haven't arrived waits. Anything that changes a lockstep run arrives at a step the host confirmed, the same on every peer: each player's input, the commands a player sent with it (an upgrade pick, a pause) and a player's removal. Peers compare a state hash every so many steps, and a mismatch (a **desync**) stops the run with an error naming the step and the hashes ([ADR-0012](docs/adr/0012-delay-based-lockstep-over-a-host-star.md)).

**Host**: the peer at the centre of a lockstep run's star. It runs the lobby, sends the seed and content hash at the start, receives every peer's input, decides when a step's inputs are complete and relays the merged input to everyone. It alone removes a player stepping has stalled on for about 10 s (silent, closed, or too slow to keep up), by scheduling the removal as input. It also removes a peer whose input doesn't decode. It never ends a run on a peer's word: a peer's desync claim counts only as that peer's own hash, which the host compares with its own. A hidden tab on a desktop browser isn't one: its worker keeps it stepping. A page the browser freezes or suspends (a mobile browser in the background) is. The host is also a player, and a peer. Not a host of a declaration, which is what runs one: `Game.Loop`, an engine, a lockstep session, a scenario.

**Peer**: one player's browser in a lockstep run, the host included. A peer that isn't the host connects only to the host: it sends its own input there and steps on the merged inputs the host relays. _Avoid_: client, which suggests the host simulates for it; every peer runs the whole simulation.

**Input delay**: how many steps ahead a peer schedules its local input: input sampled now is for step `N + inputDelay`, so it usually reaches every peer before that step is due and stepping doesn't wait. A few steps (2 to 6 steps is 33 to 100 ms at 60 Hz), tuned by measurement. Not latency, which is how long a message takes to arrive.

**Lockstep session**: one peer's side of a lockstep run (`LockstepSession`, `arcadekit/net`), made with `hostLockstep` or `joinLockstep`. In an Effect program, `hostLockstepScoped` and `joinLockstepScoped` make one its scope owns (`ScopedLockstepSession`): closing the scope stops it listening, its time is Effect's `Clock`, and `run(ticker)` ticks it on a `Ticker` (`(onTick) => stop`) until it stops, failing with its `LockstepError`. It is a host of a declared simulation, as an engine is: it owns a `Game.Loop` over the `Game.Simulation` class it is given and steps it on a timer: the caller calls `tick(nowMs)`, and each tick runs the steps that time says are due and whose inputs are all confirmed. In the browser the Co-op client runs that timer in a dedicated Web Worker (the run's scope terminates the worker and frees its script), so a hidden tab on a desktop browser keeps stepping at full rate and holds no one up; only drawing stops. The Co-op client ticks its session on that worker and again on each animation frame, before drawing. A page the browser freezes or suspends stops its worker too, and the drop rule handles it. It reads the local player's input `inputDelay` steps ahead and reports `waitingFor` while a step waits. Its `subscribe(listener)` hears the run's events and samples, from a tick and from nowhere else: a guest's run starts in a tick, and a host's, which starts as the session is made, has what its start reported (what `create` reports, then the first sample) told at the session's first tick, so a listener in place before that tick hears a run from its start on either ([ADR-0022](docs/adr/0022-a-lockstep-session-reports-only-from-its-ticks.md)). Its `send(command, settled?)` is `Game.Loop`'s without the slot: the command rides the local player's next scheduled step as part of its step payload, every peer hands the confirmed step's commands to its loop with each sender's slot, and `settled` is told how this peer's rules answered, or `CommandDropped` when the session stops, is disposed or throws first. The scoped session's `send` is that as an Effect, in the shape of an engine's. Its seam is a `Transport`. The simulation's step input must be a `Game.PlayerInputs`: from it the session takes the Schema of one player's input, which is what it sends for each player and decodes on every peer, and it makes each step's input itself, every player's input at its slot and the removed players' slots in `leaving`. The slots are the run's player order as the lobby agreed it: the host has it (itself, then its `peers`) and a guest is given it (`players`), since the host's start message lists only who is still in the run. Its caller gives it the genre's `hash`.

**Step payload**: what one player sends for one step of a lockstep run (`StepPayload`): its input, or null while nothing is attached on its peer, then the commands it sent for that step, four at most, in the order sent. On the wire it is a JSON list, `[input]` on nearly every step and `[input, command, ...]` otherwise, decoded by a Schema made from the simulation's declaration. One that doesn't decode is its sender's bad input. _Avoid_: input, for the whole payload; the input is its first part.

**Confirmed step**: what the host decided for one step (`ConfirmedStep`): every remaining player's input and commands, in player order with the host first, and the players removed at that step. Every peer, the host included, steps on confirmed steps only, decoded from the same wire form, and reads them by step number through `StepInput.read`.

**Transport**: how a lockstep session's messages travel (`Transport`, `arcadekit/net`): text to a peer by id, and a listener for what arrives. It may lose, delay, duplicate and reorder messages; the session resends what isn't acknowledged. It has two adapters: the in-memory network for tests (`createMemoryNetwork`, with seeded latency, jitter and loss), and WebRTC in the browser (`linksTransport` in `arcadekit/net/browser`), which sends over each **peer link**'s unreliable, unordered data channel. Not the signalling worker, which only introduces peers.

**Peer link**: one WebRTC connection between two peers of a lockstep run, open (`PeerLink`, `arcadekit/net/browser`): an unreliable, unordered `lockstep` channel for the Transport, and a reliable, ordered `messages` channel for what is said around the run (a lobby's picks, its start). The **signalling client** (the scoped `hostRoom` and `joinRoom`) makes them through the signalling worker: a host gets one per guest, a guest one to the host. The room's scope owns every link, the run's too, so closing it closes them; `PeerLink.closed` succeeds once a link has closed or its connection has failed. _Avoid_: connection, for the whole link.

**Signalling worker**: the hosted service that introduces a lockstep run's peers so they can open WebRTC data channels (`arcadekit/net/worker`, ADR-0012). It is the kit's, for Cloudflare, and an app's Worker is a few lines over it: for the survivors demo, the same Cloudflare Worker that serves the site, on the same origin (`apps/survivor-demo/worker`). The host opens a **room** and gets its **join code**; each guest joins with the code; the worker relays WebRTC offers, answers and ICE candidates between the host and each guest (never guest to guest, as in the star) until the host starts the run. A room holds at most its **room size**, which the app sets where it sets up the worker (4 unless it says otherwise, 16 at most), admits no one after the start (no late join), and ends when the host leaves or after 10 minutes. It never carries game input. Its messages are the Schemas of `arcadekit/net/signalling`. If it can't set a new room's expiry alarm, it refuses the host (503) and keeps no room. One Cloudflare Durable Object per join code, declared by the app (the demo's `alchemy.run.ts`, with Alchemy). _Avoid_: server, lobby server, matchmaker.

**Lobby**: where a co-op run's players gather before it starts: the host's room and its peer links, each player's lobby pick, and the host's start. It is the Co-op client's, with its messages on each peer link's reliable channel; its screens are the app's. The host can start once there are at least two players and at most the game's limit, each with a pick. No one joins a run after the lobby (no late join).

**Lobby pick**: what a player chooses in the lobby, as a string id from the list the game's Coop gives for its content (`picks`): a hero, in survivors. At the start the host replaces an empty or unknown one with the first in the list, and a guest whose content lacks one of the run's picks refuses to start. The picks, in player order, make the run's config. Not a **pick**, which answers a survivors offer.

**Coop**: a game as several players play it, each in their own browser, declared with `Coop` (`arcadekit/net/browser`): the game's engine, played in lockstep from a lobby. The engine's simulation, what its view is made from and the view serve both hosts; the declaration adds what only a shared run needs: one player's input source (`input`, where the engine's reads the whole step's), the content every peer loads (JSON data, since peers compare its hash), the lobby picks and the config they make, the state hash, the most players, and the events that end a run (`ends`). Every type comes from the engine's simulation, whose step input is a `Game.PlayerInputs`. The class is the key of the Co-op client and its `layer` provides it over the app's rooms (`CoopRooms`); its `match` turns everything a seat reports into an app's Messages; and what every peer must agree on is on it as plain functions (`definition`), for a test in Node. Survivors' is `SurvivorsCoop` ([ADR-0021](docs/adr/0021-co-op-is-declared-from-the-games-engine.md)). _Avoid_: Co-op rules, `CoopRules`, `CoopGame`; the older shape had two objects where there is one declaration.

**Co-op game**: a game that declares a Coop: one several players can play together, each in their own browser. It is the game, as players and the docs speak of it ("survivors is a co-op game"), and not a value in code: there the game is its declarations, and co-op is its Coop. _Avoid_: Co-op game for the `Coop` class or for the client that runs it.

**Co-op client**: one player's side of a co-op game, running: the service a Coop's class is the key of (`CoopClient`, `arcadekit/net/browser`; `yield* SurvivorsCoop`). It runs the lobby, then the lockstep run, drawn into the viewport while attached. The app drives it with its methods (host, join, choose, start, send, leave) and hears one ordered stream of events: `LobbyChanged`, one `RunStarted`, then the run's own events and `WaitingChanged` (who stepping waits on, once the run has stood at one step for 300 ms), and at most one `SeatFailed`, with a reason an app can re-word. The four are the client's own, Schema classes an app puts in a Message as they are; a run's events come as every peer's rules reported them, from the run's start on the host's seat as on a guest's (what `create` reports, then the first sample, after `RunStarted`), each with the local player of the seat that heard it, and the Coop's `match` handles both, the run's under `run`, and refuses a case for an event that doesn't exist. Who a run waits on to decide something is the game's to say, in its sample, as survivors' HUD flags each hero that is choosing. Its `send` carries a command of the game's to the run, as an engine's does: it rides the local player's next step, and fails with the rejection the rules refused it with, or with `CommandDropped` when there is no run or the run stopped first. A Foldkit app hands it to `engineEntry` as it would an engine ([ADR-0019](docs/adr/0019-the-kit-owns-co-op-and-the-app-keeps-the-screens.md), [ADR-0021](docs/adr/0021-co-op-is-declared-from-the-games-engine.md)). _Avoid_: co-op engine; the engine is the game's `Game.Engine`, which a Coop plays, and the client is what runs it for several. _Avoid_: answer, for what a player tells a run; it is a command.

**Seat**: this player's place in one room, from its host or join to the next host, join or leave: its lobby, then its run. The Co-op client has one current seat, which owns the room, the lobby, the lockstep session and the ticker; hosting or joining again, or leaving, closes it before the next one speaks, and a seat that fails says so last (`SeatFailed`). In its run the seat has a slot: the local player's place in the run's player order. A host seats a player when it gives it a slot: the Co-op client from the lobby's order, an engine always at 0. _Avoid_: seat for the slot itself, or for a hero.

**Leave**: what a player does to end its seat: the Co-op client's `leave` closes the room, the links, the session and the ticker, and returns once they have closed. No event of that seat follows. To the others the player stops sending: the host removes it once stepping has stalled on it, and the rules see its slot in a step's `leaving` (in survivors, its hero has **left**). A failed attach leaves too. Not an engine's `stop`, which ends a single-player run: a co-op run is no one player's to stop.

**Join code**: the six letters a host reads out so guests can find its room, such as `K7MQ2X`; letters and digits that can't be confused (no 0/O, 1/I/L), typed in any case. The worker picks it; it names the room only while the room lives.

**Hero**: one player's character in a survivors run (`Hero`, `hero.ts`). Each player has one, at its **slot**: the player's place in player order, host first in lockstep (`SurvivorsConfig.heroIds`, 1 to 4). A hero owns its body, stats, weapons, passives and upgrade offer; the run owns everything else (clock, team XP, horde, gems, projectiles, `Rng`). Survivors' rules visit heroes in slot order, and an enemy chases the nearest **playing** hero, the lowest slot winning a tie ([ADR-0013](docs/adr/0013-survivors-co-op-shares-the-run-and-splits-the-heroes.md)). _Avoid_: player for the hero; the player is the person or peer.

**Team XP**: survivors' one XP pool and level for the whole run (`World.level`, `xp`, `xpNext`). Any hero's gem feeds it, and each level gained is a level-up for every hero.

**Offer**: the upgrade choices a survivors hero picks from after a level-up (`Hero.offer`). Every playing hero gets its own, numbered together by `World.offerSeq`. The run is frozen while any hero has one open and resumes in the step that closes the last, by a pick or by its player leaving. A hero with one open is **choosing**: the HUD says so for each hero (`Hud.heroes[slot].choosing`), which is how a co-op app names who the run waits on to pick. A **pick** answers one: the `ChooseUpgrade` command, which names the offer and the index of a choice in it, so a late or repeated one changes nothing. The rules refuse it with `OfferClosed` (the offer it names is not open for its sender) or `NoSuchChoice` (the offer has no choice at that index). A single-player app sends it to the engine (`engine.send`) and a co-op app to the Co-op client (`send`), where it rides the player's next step to every peer ([ADR-0020](docs/adr/0020-a-game-is-declared.md)).

**Co-op pause**: a survivors hero holding the run paused for everyone, by the `HoldPause` command (`held: true`, then `false` to let go). The run is frozen in its rules while any playing hero holds one, and still steps, so the peers stay in touch. Only a playing hero of a run that is still on holds one: going down or leaving lets go, so a run ends holding none, and the rules refuse the command from a hero that is not playing, and once the run is over, with `NotPlaying`, so the sender's app can stop showing the run as paused. Not the engine's pause (`engine.setPaused`), which stops a single-player run's steps.

**Down**: a survivors hero at 0 HP. It stays where it fell, does nothing and isn't chased; there is no revive. The run is lost once no hero is playing. With one hero, down is dead.

**Left**: a survivors hero whose player left the run, at the step lockstep removed them (`SurvivorsInput.leaving`, from a confirmed step's removed players). It is no longer drawn or chased, and its open offer closes.

**Engine**: the Effect-facing API of a running game: attach to an element, listen to events, start, pause, stop, and send a command. A genre declares one with `Game.Engine` (`arcadekit/game/browser`): its simulation, the `view` and `input` that draw it and read its input, and what those are made from (`uses`: Effects run on each attach, such as the app's audio or a sprite sheet's load). The class is the engine service's key and its `layer` provides it, so the engine exists before its assets and an attach loads them. Push-puzzle's is `PushPuzzleEngine` and survivors' is `SurvivorsEngine`. `attach` runs its frame loop for as long as it stays attached. It fails with what one of its `uses` fails with (a sheet that can't be loaded), with `AttachError` if the view or the input source can't be made, and with `GameCrashed` if a frame throws (a **crash**: a bug in the game, reported to the player like a failed attach). A crash ends the run, as `stop` does.

**Content**: what a game is played with, as data: its levels, heroes, weapons. A genre declares it with `Content` (`arcadekit/content`): its Schema, the file each part comes from, and the checks the Schema can't express. The class is the key of the service that loads it once per app (`MyContent.layer(source)`, `MyContent.load`); `MyContent.read(source)` loads it for a test with the same checks. Push-puzzle's is `PushPuzzleContent`.

**Asset**: something a game draws or plays from that the app loads once, such as a sprite sheet, declared with `Asset` (`arcadekit/content`). The genre declares it with how to free it, the app says where it comes from (`MySheet.layer(load)`), and `MySheet.load` gives it: the first success is kept, a failed load can be run again, and the app's end frees it. Its service, like a content's, is a `Loaded`: that one `load`. Push-puzzle's is `PushPuzzleSheet`, and survivors' is `SurvivorsSheet`, which its engine draws from for one player and in co-op.

**Content source**: where content files come from, read one file at a time by its name (`ContentSource.ContentSource`, `arcadekit/content`): `ContentSource.fromRecord` serves files from a record of them, in tests, `ContentSource.make` makes one from a read of the app's own, and a **fetch content source** (`FetchContentSource.fromUrl`, `arcadekit/content/browser`) fetches them over HTTP in the browser. A source gives a file's parsed contents and checks nothing, and every source and every load of content fails with a `ContentSource.ContentError`, whose message names the file or the problem. A genre's **content definition** (`ContentDefinition`) is its schema, the file each part comes from, and the checks the schema can't express, as one value. A genre declares its content with `Content` over that definition (`PushPuzzleContent`, `SurvivorsContent`): the service, provided with `MyContent.layer(source)`, loads and checks the files once per app, and a failed load isn't kept, so it can be retried. Tests read the same definition with `MyContent.read(source)`, so they run the same checks. _Avoid_: loader, for a source; a declaration's `layer` is what loads and keeps.

**Entity pool**: a fixed-capacity set of entities stored as one typed array per field (`EntityPool`, `arcadekit/core`), called a **pool** for short in prose. A new entity's fields start at 0. Removing swaps the last entity in, so pool indices are not stable. An **identified pool** (`EntityPool.makeIdentified`, an `EntityPool.Identified`) also gives each entity a stable id, for a genre that must name one entity across removals (undo, tweening). _Avoid_: `Pool` as a name in code, which is Effect's pool of resources.

**Layout**: what each record of an entity pool, a ring or a tile map holds: an object of typed array constructors a game writes once, `{ x: Float32Array, hp: Float32Array }` (`Layout`, `arcadekit/core`). Each field is then one typed array, its **fields** (`Layout.Fields`). _Avoid_: schema, which is Effect's.

**Ring**: a fixed number of records stored as one typed array per field, where a new record overwrites the oldest (`Ring`, `arcadekit/core`). A ring only views read carries what a step did, such as a hit or a hole filled: the step pushes and never reads it, the state hash leaves it out, and each view takes what is new with a ring reader. A ring the rules pop, such as push-puzzle's undo history, is state. _Avoid_: event buffer (an event buffer holds a frame's events), queue, log.

**Ring reader**: how far one view has read one ring (`RingReader`, `arcadekit/core`). A view keeps one for each ring it reads, and `RingReader.take` gives the first record it has not taken: on its first look, what the ring has written then. _Avoid_: cursor, subscription.

**Event buffer**: what holds the events a run reports during a frame's steps until its loop delivers them (`EventBuffer`, `arcadekit/core`). `Game.Loop` keeps one. _Avoid_: ring, for this.

**Spatial grid**: a uniform grid in `arcadekit/core` (`SpatialGrid`) for "which points are near here?", rebuilt every step from continuous positions. `within` and `nearest` answer with the distance tested; `query` gives the candidates of the cells a circle overlaps. Not a tile map.

**Tile map**: a genre's grid of static cells (wall, floor, hole), stored in typed arrays and indexed by column and row (`row * cols + col`). It describes the level, not where entities are. Made with `TileMap.make` (`arcadekit/core`), whose module also gives a cell's neighbour on each **side** (`TileMap.Side`) and a flood fill.

**Fixed-step clock**: what turns a frame's time into a whole number of fixed steps, carrying what is left to the next frame and dropping a backlog past five steps (`FixedStepClock`, `arcadekit/core`; [ADR-0003](docs/adr/0003-one-fixed-step-clock.md)). `Game.Loop` steps every game with one, and its time comes from the loop's caller. _Avoid_: clock, alone, as a name in code: Effect's `Clock` is the time Effect reads.

**Rng**: a run's seeded random number generator, mulberry32 (`Rng`, `arcadekit/core`). The same seed gives the same draws on every peer and in every replay, so a step makes every random choice with its run's `Rng`, made from the seed `create` is given. _Avoid_: random, which is Effect's `Random` and not the run's.

**Exact math**: the arithmetic a step may call, which gives the same bits in every engine: `ExactMath.hypot2`, `sin`, `cos` and `powInt` in place of the `Math` functions each engine approximates, with `clamp`, `lerp` and `hashCell` (`ExactMath`, `arcadekit/core`; [ADR-0011](docs/adr/0011-a-step-uses-only-exact-math.md)). _Avoid_: `Math` as a name in code, the platform's.

**Point2**: two numbers, x and y, that a function writes for its caller, who owns the point (`Point2`, `arcadekit/core`), so a step that asks for two numbers per entity allocates nothing: `Point2.clampLength` and `Point2.moveToward` write into one.

**Timer**: a number in a run's state that a step lowers each step and that is ready at 0 (`Timer.countDown`, `arcadekit/core`), so it pauses, replays and hashes with the run, and nothing calls back. A **rate** is a budget a step adds to, whose whole units `Timer.takeWhole` gives.

**Tween**: a value a view computes each frame from when something started, with no object holding it: `Tween.progress` toward its end, then an ease (`Tween.easeOut`) (`Tween`, `arcadekit/core`). _Avoid_: animation, for a tween.

**Tile layer**: a grid of cells drawn from a sprite sheet's frames, only the cells on screen (`TileLayer`, `arcadekit/render-three`). It belongs to the view: it takes a function of the cell, and knows no tile map. _Avoid_: tilemap, for the layer.

**Mesh instances**: copies of one mesh drawn in a single draw call (`MeshInstances` in `arcadekit/render-three`), for a 3D view that draws one mesh many times, such as a crowd of enemies or a floor of tiles. Both demos draw pixel art instead, with **sprites**. Each instance gets a matrix, a color and the attributes its view declares. Not a pool: mesh instances belong to the view and hold only what it draws. The view sets them from the state it reads.

**Sprite sheet**: one PNG of pixel art plus the JSON Aseprite exports for it (`SpriteSheet`, `loadSpriteSheet` in `arcadekit/render-three`): its frames, each with a rect and a duration, and its **tags**, named runs of frames that are animations (`slime/move`). `frameAt` gives the frame a tag shows at a time. `resolveTags` picks each tag a view draws, with its fallbacks, and lists what the sheet lacks. A genre declares its sheet as an asset (`PushPuzzleSheet`, `SurvivorsSheet`), and the app says where it comes from. `LoadContent` loads it with the content and shows a failure on the loading screen, whose "Try again" runs `LoadContent` again. The asset keeps it, and the app's end frees it: a view draws from a sheet but never frees it, and `disposeObject` skips its texture ([ADR-0015](docs/adr/0015-pixel-art-sprites-loaded-by-the-app.md)). A content entry's `sprite` names a tag (a survivors hero's names the prefix of its `walk`, `idle` and `down` tags); without one, a generic sprite is drawn in the entry's `color`. _Avoid_: atlas, texture for the whole sheet.

**Sprites**: copies of frames from one sprite sheet drawn in a single draw call (`InstancedSprites` in `arcadekit/render-three`), as quads facing a **pixel camera** (`PixelCamera`): an orthographic camera looking straight down, with a whole number of screen pixels per sprite pixel and its position snapped to screen pixels, so the art never shimmers. Each sprite gets a position on the ground, a frame, a flip, a tint, a flash, an alpha, a lift (drawn higher, sorted at its feet) and a layer; within a layer, lower on screen draws in front. A view pushes the sprites it draws each frame, and the batch grows to hold them. Like mesh instances, they belong to the view.

**Gait**: whether a character a view draws is walking, worked out from the positions it is shown at (`Gait`, `arcadekit/render-three`). The rules hold no animation. _Avoid_: animation state.

**Save**: what an app keeps between sessions: records by level or hero id, such as a level's best move count or a hero's best time. It is UI state, not simulation state, so no genre package knows about it. An app declares it with `Save` (`arcadekit/save`): its storage key (the demos' are `arcadekit/<game>/save`), one record's Schema and its **record merge** (`mergeRecord`: how two records for one id become one). The class is the key of the service that reads and writes it (a **stored** value, `Stored.Stored`, bound to `save`), and `MySave.layer` provides it over the app's **save storage**. A write merges into what it could read: `write(records)` re-reads the stored save, merges the records into it by id and keeps the best of both, so the other ids and another tab's record aren't lost; `MySave.merge` is the same merge as a plain function, for an app's `update`. `read` reads storage each time and keeps nothing. The app reads it once at startup and writes it on the genre's end-of-run event (survivors' `RunEnded`, push-puzzle's `LevelSolved`), never per frame and never from a step. It is stored as `{ version: 1, records }`, and a save that fails to decode (corrupt, an unknown version, or another shape) is copied to `<storageKey>/corrupt` and read as empty. Push-puzzle's demo has `PushPuzzleSave` and survivors' `SurvivorsSave`. See [ADR-0009](docs/adr/0009-a-save-package-is-earned.md). _Avoid_: snapshot, which is a whole run's state; save store, for the service.

**Setting**: one value an app keeps between sessions under its own storage key, apart from its save: the player's volume and mute, their controls, and progress that is no record by id, such as whether the tutorial was offered. An app declares it with `Setting` (`arcadekit/save`): its storage key, its Schema and its `default`, which a missing or unreadable one reads as. The class is the key of the service that reads and writes it (a `Stored.Stored`, bound to `setting`: `read`, `write`), as a save's is, and is named for the game and the thing, since a game has several. The last write wins, unless the setting declares a `merge`, for a value that only grows: its write then re-reads what is stored and stores the two as one. The **audio settings** are one setting: the kit has their Schema and default (`AudioSettings.AudioSettings`, `AudioSettings.defaults` in `arcadekit/audio`), an audio system takes them with `AudioSystem.applySettings`, and each app declares where it keeps them (`PushPuzzleAudioSettings`, `SurvivorsAudioSettings`). _Avoid_: preference, option; settings store, for the class or its service.

**Stored**: what a save's or a setting's service gives (`Stored.Stored`, `arcadekit/save`): `read`, which reads storage on every run and gives what is there (a missing or unreadable value reads as the declaration's own), and `write`, which stores a value and gives what it stored: a save's merges into what it could read, a setting's replaces what is there unless it declares a `merge`. Neither fails, since play goes on without what couldn't be kept: a storage problem is logged. A declaration's writes run one at a time, and a trace shows each read and write under the declared name (`PushPuzzleSave.write`). A test of an app's own code can give it one with no storage (`Stored.make`). _Avoid_: store, which is the save storage under it.

**Save storage**: where an app keeps its saves and settings: an Effect `KeyValueStore`, which each declaration's `layer` takes. In a browser it is `BrowserSaveStorage.layer` (`arcadekit/save/browser`): localStorage, or memory for the session, with a warning, where the browser refuses localStorage. A test provides `KeyValueStore.layerMemory`. _Avoid_: save store, for this or for the service.

**Kit**: the shared code that genre packages and demo apps build on, published as one package, `arcadekit`. A **primitive** is one of the kit's building blocks, such as an entity pool or an input controller.

**Entry**: one subpath export of a package, and what an import names: `arcadekit/core`, `arcadekit/game/browser`. The kit has twenty, in nine groups: `core`, `input`, `content`, `save`, `audio`, `render-three`, `game`, `net` and `foldkit`, some with a `./browser` entry for what needs the DOM and a `./testing` entry for what only tests import, `game` with a `./scenario` entry for scenarios, and `net` with a `./worker` entry for what needs Cloudflare. An entry imports only the entries below it ([ADR-0018](docs/adr/0018-one-package-with-entries.md)). A genre package's **root entry** is its DOM-free one.

**Module**: one file of an entry's source, shaped and documented as a module of Effect is: a **namespace** an entry exports (`Ring`, `Rng`), with its data type (`Ring.Ring`), its `make`, its guard and its functions ([ADR-0024](docs/adr/0024-the-kit-is-written-as-effect-modules.md), `docs/code-style.md`). An entry a game imports whole, such as `arcadekit/game`, is one module. A namespace's name is the glossary's word for what the module holds.

**Genre package**: a package that implements one kind of game on the kit (`@arcadekit/survivors`, `@arcadekit/push-puzzle`). Each entry exports what an app uses and nothing else; rules internals stay in their modules. The root entry has the genre's declarations: its events, its commands with their rejections (survivors' `ChooseUpgrade`), its simulation and its content, with the state, config and step input an app names, and no DOM or Three.js (its `tsconfig.root.json` checks it with no DOM types; keeping Three.js out is a convention). Its `./browser` entry has its engine, with the sheet asset and the cue table the app provides. A genre with co-op declares its Coop there too, over that engine (`SurvivorsCoop`), and its root entry has what co-op needs with no DOM: the simulation, whose step input is a `Game.PlayerInputs` and whose commands a co-op pick and pause are, and the state hash.

**Finding**: a place where a genre had to change, work around, copy or bypass a shared primitive, or where a shared primitive's name or docs assume one genre. A primitive a genre simply doesn't use is not a finding. See `docs/push-puzzle-findings.md` and `docs/co-op-findings.md`.

Message, Command, Subscription, Mount and `resources` are Foldkit's words, used in the apps. An app turns events into Messages, so a Message is not an event.
