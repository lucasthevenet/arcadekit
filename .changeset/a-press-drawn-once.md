A frame system sees each press and release of `Input.Keyboard`, `Input.Pointer` and `Input.Gamepad` once, in the first frame drawn after its tick. Before, `pressed` compared with the game's tick, so it was true on every frame until the next tick, and a frame of two ticks missed a press in the first: a page that draws at 144 Hz over 60 ticks toggled a menu two or three times for one key. The app keeps which ticks no frame has drawn yet, and the frame stage reads `pressed` and `released` against them. After `Timeline.rewind`, the ticks run again are new to the frame stage, as their events are. After a rewind with `{ again: true }`, as a rollback session makes on a wrong prediction, a press the last frame showed isn't shown again, and one that only the ticks run again have is shown once. After `Save.load`, what the save holds of before its tick isn't shown. A tick, an action's handler and the input stage read them as before.

**Breaking**: the world keeps every button that has been down, with the ticks it last went down and up in, where it forgot a button at the first report after the tick it went up in. The hash now holds a button that went up long ago, so a game in which a key was pressed and let go hashes differently from one in which it never was, and a recording made before this release whose hash checks follow a release of a key fails `Replay.verify` with `Replay.Diverged`. The save format stays 4: a save from before, of format 3 or 4, loads as it was, holding the buttons down and those let go in its last tick, and the game keeps every button that goes down from then on.
