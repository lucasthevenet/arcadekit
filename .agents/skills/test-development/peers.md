# Peers, other machines and platforms

- **Peers are tested in one process, joined by a network made by hand**: every session in one scope, each with the app it makes, and a list of messages in flight that the test delivers late, shuffled and as text, with delays drawn from a seeded generator so that a failure repeats. A test of a game uses `Transport.makeHub`, which is that network as a transport, as [Testing a game](../../../website/src/content/docs/guides/testing.md#connect-several-peers) says. `test/peers.ts` has a network of its own, for the tests of the sessions themselves. What is compared is the world's hash after every tick, peer against peer, and the logs whole. `test/peers.ts` is the game and the network they share. Peers that predict are compared once the game has come to rest, with each other and with a game of one that is given the same log by `Journal.replay` and never goes back.
- **What speaks to another machine is tested over real sockets on this one.** `test/Relay.test.ts` runs the relay behind a WebSocket server (`ws`, a dev dependency) on a port the system picks, and opens `Transport.layerWebSocket` to it. Such a test waits for what it expects, a few milliseconds at a time with a limit, and never for a fixed time; and it is run several times over before it is trusted. An example that hosts the relay on a platform is checked by hand with `pnpm --filter arcadekit relay:check <address>`, against the platform's own emulator where it has one, and what it was not run against is said in the guide to hosting a relay.
- **What a platform forbids is tested in a process that forbids it.** `test/Policy.test.ts` plays the game of `test/policyGame.ts` in a Node started with `--disallow-code-generation-from-strings`, which is what a page under a strict Content Security Policy is to V8, and compares it with the same game played in the test's own process. Such a test also shows that the flag was in force there, and that it would be noticed if it were not. A Node module a test needs is imported and typed in the test, since the tests are compiled with no types but their own.
