# Sprites

`survivors.png` and `survivors.json` are generated by `scripts/generate-sprite-sheets.mjs` (run `pnpm sprites`): pixel art painted in code, ported from the art prototype on branch `prototype/24-art` ([ADR-0015](../../../../docs/adr/0015-pixel-art-sprites-loaded-by-the-app.md)). The script is deterministic, so running it again rewrites the same bytes.

The JSON is Aseprite's export format with frames as a hash (`--format json-hash --list-tags`). Frame keys are `<tag> <index>`, like `spark/walk 0`; `meta.frameTags` names each animation with its `from`/`to` frame and `direction: "forward"`; each frame has its `duration` in ms. Frames sit in the PNG with 1 px of transparent padding.

Conventions:

- Every frame in a tag has the same size.
- Characters stand with their feet on the frame's bottom row, centred across. Heroes face right; the view flips them for left. Bats float, so they are centred.
- Gems, projectiles, the trail, the aura, the marker and the shadow are centred.
- White and grey sprites (`hero/*`, `enemy/move`, `bolt/generic`, `trail`, `aura/ring`, `marker/ring`) are meant to be tinted: content without a `sprite` uses `hero/*` or `enemy/move` in its `color`, and the marker takes the player slot's colour.

## Tags

| Tag | Size | Frames | What |
| --- | --- | --- | --- |
| `spark/walk`, `ember/walk`, `tide/walk` | 24x24 | 4 | Hero walk: stand, step, stand, step |
| `spark/idle`, `ember/idle`, `tide/idle` | 24x24 | 1 | Hero standing |
| `spark/down`, `ember/down`, `tide/down` | 24x24 | 1 | Hero lying down |
| `hero/walk`, `hero/idle`, `hero/down` | 24x24 | 4, 1, 1 | Generic hero, white and greys |
| `slime/move`, `golem/move`, `wraith/move` | 16x16 | 2 | Enemies |

| `bolt/arc` | 12x12 | 2 | Arc Bolt |
| `bolt/bubble` | 12x12 | 2 | Bubble Shot |
| `bolt/generic` | 12x12 | 2 | Generic projectile, white |

## Replacing the art

Draw the sheet in Aseprite (or LibreSprite) with these tag names and sizes, then export with `File > Export Sprite Sheet`: "Hash" JSON data, "Tags" meta, 1 px border or shape padding, and the output named `survivors.png` / `survivors.json`. From the CLI: `aseprite -b art.aseprite --sheet survivors.png --data survivors.json --format json-hash --list-tags --shape-padding 1 --filename-format "{tag} {tagframe}"`.

To use a CC0 pack, pack its frames into one PNG and write the JSON with the same tag names (TexturePacker's "JSON (Hash)" plus tags, or a small script). A new enemy or hero only needs frames under a new tag and that tag in the content's `sprite` field. Running `pnpm sprites` again overwrites these files, so stop using the script once you have real art.
