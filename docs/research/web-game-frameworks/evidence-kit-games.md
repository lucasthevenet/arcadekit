# What survivors and push-puzzle write for themselves

Paths are relative to this repository's root, at arcadekit 0.6.0. "survivors" is `packages/survivors/src` (the genre) and `apps/survivor-demo/src` (its app). "push-puzzle" is `packages/push-puzzle/src` and `apps/push-puzzle-demo/src`. Line counts are the lines of the ranges named, from `cat -n`. A range counted under one need is not counted again under another, except where a bullet says so. Test files were read for the helpers the games wrote in them, not for their assertions.

## Needs

### loop

- **Countdown timers and cooldowns counted inside the step**: each timer is a field the step lowers by `dt` (or by one step) and compares with zero, written out at every place: a weapon's cooldown, a hurt timer, a hit flash, a projectile's life and its re-hit delay, and push-puzzle's steps until a held move repeats. Where: survivors `packages/survivors/src/world.ts`:378, 462, 509, 526-538, 640-642, 660, 675 and `hero.ts`:19-22, 55 (about 26 lines); push-puzzle `packages/push-puzzle/src/world.ts`:38-42, 139-140, 200, 209-213 (about 13 lines). Both games. Sits on: `Game.StepContext`'s `dt`; nothing in the kit for timers. General: yes, every timer is the same three operations (set, lower, test) on a number in the state.
- **A run's end kept as a flag the step checks**: the rules set a status when the run is won, lost or solved, and every later step returns at once; survivors also moves its HUD sample's version so the last numbers reach the UI. Where: survivors `world.ts`:48, 108, 206-211, 246-248, 332-343 and `simulation.ts`:57-64 (about 31 lines); push-puzzle `world.ts`:136-137, 188-190, 223 (6 lines). Both games. Sits on: `Game.Simulation`'s `sample.version`; a `Coop`'s `ends` (`packages/survivors/src/browser/coop.ts`:26). General: yes, `docs/architecture-review.md`:119 records that both genres end a run with a private flag while the loop keeps stepping.
- **A pause that any player of a shared run holds for everyone**: a command sets a flag on the sender's hero, the step returns early while any playing hero holds it, going down or leaving lets go, and the app keeps its own flag for the menu and corrects it when the rules refuse. Where: survivors genre `commands.ts`:33-51, `simulation.ts`:42-55, `world.ts`:256, 283-286, 313, 318-330, 201, `hero.ts`:61-65, `events.ts`:16-17 (about 60 lines); survivors app `apps/survivor-demo/src/app/commands.ts`:223-243, `update.ts`:114-129, 206-209, 280-283, 318-324, `model.ts`:71-83, 109-117, `message.ts`:46, 48-49, `view.ts`:420-424, 464-493 (about 112 lines). Survivors only. Sits on: `Game.Command`, `Game.Rejection`, the Co-op client's `send`. General: partly, `packages/arcadekit/src/net/README.md`:551 says "The kit knows nothing of pausing", so any co-op game writes this rule and this screen again.
- **A pause screen for one player**: a key toggles a `Paused` phase, a Command calls the engine's pause, and a panel offers Resume and Quit. Where: survivors app `update.ts`:210-227, `commands.ts`:109-119, `view.ts`:51-71 (about 50 lines; the key is under input). Survivors only: push-puzzle has no pause. Sits on: `engine.setPaused`. General: yes, the phase, the Command and the panel carry nothing of the game.

Nothing found for: time scale or slow motion, delayed calls, pausing when the tab loses focus (neither app handles `visibilitychange` or `blur`).

### scenes

- **The app's screens as a tagged union of phases with guarded transitions**: each app declares `Phase` (Loading, LoadFailed, a menu, Starting, Playing, an end screen), moves between them in `update` only from the phase a Message belongs to, starts and stops the run with Commands, and draws one overlay per phase. Where: survivors app `model.ts`:23-48, `update.ts`:104-107, 131-134, 178-180, 184-194, 199-205, 228-229, `view.ts`:32-33, 48-50, 72-80, 295-314, `commands.ts`:68-83, 121-128 (about 115 lines); push-puzzle app `model.ts`:19-28, `update.ts`:62-70, 115-119, 123-133, 141-144, `view.ts`:31-32, 47-51, 163-177, `commands.ts`:56-71, 73-80 (about 85 lines). Both games. Sits on: Foldkit (`defineTaggedUnion`, `Update`), `engine.start`, `engine.stop`. General: partly, Loading, LoadFailed, Starting, Playing and an end screen with "play again" and "back" are in both apps; the other phases are each game's.
- **A backdrop drawn while no run is active**: both views take `null` for the state and draw a menu scene: survivors pans slowly over the empty arena, push-puzzle fills the camera's window with dim floor tiles and crates that drift. Where: survivors `packages/survivors/src/browser/scene.ts`:50-51, 179-180, 255-260, 278-286 (19 lines); push-puzzle `packages/push-puzzle/src/browser/board.ts`:38-48, 99-100, 151-153, 322-371 (66 lines). Both games. Sits on: `Game.View`'s null state, `PixelCamera.follow` and `setViewHeight`, `InstancedSprites`. General: partly, both write a "no run" scene and its camera drift; what it shows is the game's.
- **A view notices a new run and resets what it keeps**: each of the four views compares the state object with the one it saw last frame, and on a change clears its per-run memory (looks, phases, slides, last-seen counters). Where: survivors `browser/scene.ts`:504, 521-532 and `browser/sound.ts`:134-144 (24 lines); push-puzzle `browser/board.ts`:97-98, 164-166, 374-376, 394-416 and `browser/sound.ts`:49-50, 64-71 (41 lines). Both games. Sits on: the `Game.View` contract (`packages/arcadekit/src/game/README.md`:347: "a view tells runs apart by identity"). General: yes, the check is the same in all four views and a view has no start or end hook.

Nothing found for: transitions between screens (fades, wipes), parallel scenes.

### entities

- **Following pool entities across frames when slots are reused**: `StablePhases` matches this frame's entities to last frame's by slot, kind and distance moved, so each enemy and gem keeps its own animation phase after the pool moves it to another slot. Where: survivors `browser/phases.ts`:1-116 and `browser/scene.ts`:176-178, 396-397, 402, 429-430, 437, 521-528 (about 133 lines). Survivors only. Sits on: `createPool`, whose indices are not identities. General: yes, nothing in the class knows the game; see Workarounds.
- **A spawn schedule: windows of the run's clock, each spawning at a rate**: for each wave whose window holds the clock, a budget grows by `perSecond * dt` and one entity spawns per whole unit, on a ring at a random angle and distance around a target, clamped to the arena. Where: survivors `world.ts`:126, 166, 397-423 and `schema.ts`:111-117 (about 36 lines). Survivors only. Sits on: `Pool.add`, `Rng.next` and `range`. General: yes, the rate accumulator and the ring placement hold for any spawner; which hero is next (`world.ts`:382-395) is the game's.
- **Steering: chase a target, push overlapping bodies apart, fly to a collector**: enemies move toward the nearest hero at their speed, each overlapping pair is moved half the overlap apart, and a gem in range flies to its hero at a capped speed. Where: survivors `world.ts`:448-463, 464-488, 709-724 (57 lines). Survivors only. Sits on: `SpatialGrid.query`; the game's `hypot2`. General: yes, seek, separation and move-toward are stock steering.
- **Setting every field of a reused pool slot at spawn**: each spawn calls `add`, handles -1 for a full pool, then writes every field, including zeros for fields left over from the slot's last entity. Where: survivors `world.ts`:410-413, 419-421, 594-597, 603-611, 689-698 (about 30 lines); push-puzzle `world.ts`:161-164 (4 lines). Both games. Sits on: `Pool.add` (`packages/arcadekit/src/core/pool.ts`:31: "Field values in the slot are stale: set them all"). General: partly, which fields is the game's; a spawn with defaults and a full-pool answer is the same each time.

Nothing found for: components, tags or groups, state machine helpers (a hero's `playing`, `down`, `left` is a string field tested inline, `hero.ts`:35-42).

### render

- **A tile layer: a grid of cells drawn from sheet tags, only the window the camera sees**: survivors draws the arena floor as one-unit tiles around the camera, picks wall and corner tiles by position, and refills only when the camera crosses a tile; push-puzzle draws its board cell by cell, picks a wall face where floor lies below, and maps a cell to a world position. Where: survivors `browser/ground.ts`:36-64, 71-123, 140-148 and `browser/scene.ts`:198-211, 261-267 (about 112 lines); push-puzzle `browser/board.ts`:173-219, 491-501 (58 lines; its backdrop's window fill, 331-369, is counted under scenes). Both games. Sits on: `InstancedSprites.set` and `commit`, `frameAt`. General: yes, `docs/adr/0001-kit-changes-need-two-genres.md`:15 keeps "Push-puzzle's tile map" in its genre until a second genre needs one, and survivors' `ground.ts` is a second.
- **Animation tags looked up by name with a fallback, and the list of tags a view needs**: each view resolves its tags once, takes a near tag or frame 0 when the sheet lacks one, warns once, and exports the tags it draws so a test can check a sheet. Where: survivors `browser/scene.ts`:67-74, 191-192, 567-600 and `browser/art.ts`:19-92 (about 116 lines); push-puzzle `browser/board.ts`:12-26, 66-80, 125-142 (48 lines). Both games. Sits on: `SpriteSheetData.tags`. General: yes, both wrote "this tag, or that one, or nothing" and "which of my tags does this sheet lack".
- **A sprite batch sized for the run**: a batch has a fixed capacity, so each view works out the capacity a run needs and disposes and remakes the batch when it differs. Where: survivors `browser/scene.ts`:602-636 and `browser/ground.ts`:149-158 (44 lines); push-puzzle `browser/board.ts`:377-386, 419-439 (31 lines). Both games. Sits on: `InstancedSprites` (`capacity` is "Fixed", `instanced-sprites.ts`:78). General: yes, the same "make it bigger" code five times; both views also keep their own write cursor into each batch (`scene.ts`:184-185, 293-300; `board.ts`:168-170).
- **A shape drawn at any radius in whole pixels, with its own instanced shader**: `AuraRings` is an instanced quad with per-instance position, radius, pulse and colour, and a fragment shader that maps each ground pixel to the nearest art pixel of a ring. Where: survivors `browser/aura.ts`:1-161 and `browser/scene.ts`:219-227, 366-384 (189 lines; the batch without its shader text, `aura.ts`:55-161, is 107). Survivors only. Sits on: `SpriteSheet` (its texture and frame rectangles); nothing in the kit draws a scaled sprite or a shape. General: partly, the attribute buffers with `set`, `commit` and `dispose` are what any custom-shader batch repeats; the shader is this ring's. See Workarounds.
- **Layers and blend order chosen by hand**: a table of layer numbers, a `setLayer` call per sprite, a separate blended batch for soft shadows, and a render order so it draws after the rings. Where: survivors `browser/scene.ts`:40-48, 339, 351, 357-358, 411, 420-421, 439, 466, 477, 628-632 (about 24 lines); push-puzzle `browser/board.ts`:423, 433 (2 lines). Both games, survivors far more. Sits on: `InstancedSprites`' `layer` and `transparent`. General: partly, the kit has layers; a batch is either opaque or blended, so shadows need a second batch.
- **A trail of fading puffs behind a moving thing**: three sprites behind each projectile, spaced by its speed, each on an older frame of a tag that is held on its last frame. Where: survivors `browser/scene.ts`:56-57, 117-119, 456-469 (19 lines). Survivors only. Sits on: `InstancedSprites`. General: partly, it is the only particle-like effect in either game, and it is drawn from the state each frame with no particle of its own.

Nothing found for: text or numbers drawn in the canvas (all text is DOM), damage numbers, particles with a life of their own, masks, post effects, render textures, nine-slice, lights, meshes (`MeshInstances` is used by neither game).

Nothing found for: shake, flash, fade, zoom changes during a run, several cameras, world-to-screen conversion.

### physics

- **Circle against circle: a grid query, then the exact distance**: hero against enemies, an aura against enemies and a projectile against enemies each query the grid with a padded radius into a shared buffer and test `distance < r1 + r2` themselves; the grid is rebuilt twice a step. Where: survivors `world.ts`:35, 128, 172, 264-268, 497-512, 617-630, 644-663 (58 lines). Survivors only. Sits on: `SpatialGrid.build` and `query` (`packages/arcadekit/src/core/grid.ts`:45-48: "Callers still check the exact distance"). General: yes.
- **Nearest and k-nearest search by a full scan**: the nearest playing hero to a point, and the `shots` nearest enemies in range without repeats, each a loop over every candidate; the view has its own copy for facing. Where: survivors `world.ts`:426-446, 559-586 and `browser/scene.ts`:121-135 (64 lines). Survivors only. Sits on: nothing in the kit (`SpatialGrid` has no nearest query). General: yes.
- **A tile grid in the rules: cell index, the neighbour in a direction, blocked cells, a flood fill**: cells are `row * cols + col` in typed arrays, `neighbor` steps a cell in a direction or gives -1 off the map, a linear scan finds the box on a cell, and a flood fill from the player marks what is outside the walls. Where: push-puzzle `world.ts`:116-123, 229-250 and `level.ts`:3-12, 72-118 (87 lines). Push-puzzle only. Sits on: nothing in the kit (`SpatialGrid` indexes points, not tiles). General: yes for the grid arithmetic; which tile blocks is the game's.
- **Bodies moved by velocity and kept inside the world's bounds**: `x += vx * dt` with a life that runs out, and positions clamped to the arena. Where: survivors `world.ts`:359, 376-377, 400, 417-418, 638-642 (11 lines). Survivors only. Sits on: `clamp`. General: yes, small.

Nothing found for: raycasts, triggers as a notion of their own, rigid bodies.

## Workarounds

- **Entities followed by position, beside identified pools.** `packages/survivors/src/browser/phases.ts`:1-4: "A pool moves its last entity into a removed one's slot, so a slot index isn't an entity ... View-only; the simulation has no ids for these." The kit has `createIdentifiedPool`, which push-puzzle uses (`packages/push-puzzle/src/world.ts`:161); survivors' enemies and gems are plain pools (`world.ts`:163-165), so its view matches entities across frames by slot, kind and distance (116 lines).
- **A shader of its own, beside `InstancedSprites`.** `packages/survivors/src/browser/aura.ts`:4-8: "A sprite scaled by a fraction would break the whole-pixel rule, so the shader works out each whole sprite pixel of the ring on the ground". `InstancedSprites` sets a place, frame, flip, tint, alpha, flash, lift and layer per sprite (`packages/arcadekit/src/render-three/instanced-sprites.ts`:188-219) and no size, so the ring has its own geometry, attributes and material (161 lines).
- **The batch's snapping turned off, and done by the view.** `packages/push-puzzle/src/browser/board.ts`:434-435 passes `snap: false` with the comment "Slides snap to screen pixels (`snap`), finer than sprite pixels at any scale above 1", and 461-464 snaps each slide itself with `snapToPixel(value, this.camera.screenPixelsPerUnit)`. The kit's `snap` option rounds to whole sprite pixels.
- **A view that guesses the run is paused.** `packages/survivors/src/browser/sound.ts`:86-90 and 121-123: the sound view remembers the run's time and the render time it last changed, "a run that stops stepping (a single-player pause) stops the hum". A view is not told that the engine is paused, so it watches `world.time` and waits 0.25 s (lines 145-149).
- **A drawing view that reads a sound counter.** `packages/push-puzzle/src/browser/board.ts`:279-280 compares `puzzle.cues.undos` with the last value it saw to learn that the last move was an undo, so the player keeps facing the same way (285-288). The cue counters are declared as "Sound triggers, read by the presentation only" (`packages/push-puzzle/src/world.ts`:98-102).
- **A view that compares the state with last frame to see what a step did.** `packages/push-puzzle/src/browser/board.ts`:115-120, 180-183, 244-253, 441-459 keep each cell's last tile, which boxes were on the board and when each hole was filled, because a box that fills a hole is gone in the same step ("A box that left the pool fell into a hole next to where it was", line 244). `docs/push-puzzle-findings.md`:126-131 recorded this as finding 12 with no action.
- **A sample version moved to get the HUD's last numbers.** `packages/survivors/src/world.ts`:206-211: "it moves when the run ends, so the loop reads the HUD right after the frame that ended the run and the UI shows the run's last numbers." The loop does not know a run ended; the version is how the rules make it sample once more.
- **Rule tests that call `step` themselves, beside scenarios.** `packages/survivors/src/world.test.ts`:336-338: "The tests above and below arrange a state by hand, which a scenario can't, so they call `step` themselves." Both genres write a literal step context for it (`world.test.ts`:114-126; `packages/push-puzzle/src/world.test.ts`:20-22; `packages/push-puzzle/src/browser/board.test.ts`:28-30).
- **The engine entry held back until the app's own load is done.** `apps/survivor-demo/src/app/subscriptions.ts`:81-91 and `apps/push-puzzle-demo/src/app/subscriptions.ts`:16-25: "attaching loads the sheet, and an entry that reported a failed load wouldn't run again after a retry". Each app adds `isLoaded(model.phase)` to `isViewportMounted` and keeps an `isLoaded` function for it (`model.ts`:50-55; `model.ts`:30-35).
- **Two loads kept from cutting each other short.** `apps/survivor-demo/src/app/commands.ts`:33-40 and `apps/push-puzzle-demo/src/app/commands.ts`:26-33: "Both loads run to the end, so one failing doesn't cut the other short: what loaded is kept for a retry." Each app runs `Effect.all` in `result` mode and unwraps the two results by hand.
- **A pause written into the rules, beside the engine's.** `packages/survivors/src/commands.ts`:39-46: "A single-player app pauses its engine instead (`engine.setPaused`), which stops the steps themselves." A co-op run has no such call (`packages/arcadekit/src/net/README.md`:551), so the same game has two pauses: the engine's for one player and the `HoldPause` command for several, and the app has two pause screens (`apps/survivor-demo/src/app/view.ts`:51-71 and 464-493).
- **The debug read cut down before it leaves the page.** `apps/survivor-demo/src/app/coop.ts`:20-28: "The client's debug read without the World, which is too big to copy out of the page."
