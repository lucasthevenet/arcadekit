## Shape

PixiJS is a 2D renderer with a retained scene graph, an asset loader, a pointer event system and a frame ticker; its own docs say "PixiJS itself is just a rendering engine" (https://pixijs.com/8.x/guides/getting-started/ecosystem). A program creates an `Application`, awaits `app.init(options)`, which picks a WebGL, WebGPU or Canvas renderer, and adds `app.canvas` to the page. Everything drawn is a `Container` subclass in one tree rooted at `app.stage`; a plain `Container` holds children, and `Sprite`, `Graphics`, `Text`, `Mesh` and `ParticleContainer` are leaves. Files are loaded first with the `Assets` singleton (`await Assets.load(...)`, or bundles declared in a manifest), and the objects that use them are created afterwards, because `Texture.from` and `Sprite.from` only read the cache. Per-frame logic is a callback on `app.ticker` that receives the `Ticker`; the same ticker calls `app.render()` after the callbacks. Input is pointer events on scene objects: the author sets `eventMode = 'static'` on an object and listens with `.on('pointertap', ...)`, and events bubble up the tree as in the DOM. Objects persist between frames until they are removed or destroyed; the author changes their properties and the renderer redraws. There are no scenes or states, no physics, no audio, no keyboard or gamepad input, no tweens, no camera and no save system in the package. The docs point to companion libraries for some of these (`@pixi/sound`, `@pixi/ui`, `@pixi/layout`, `pixi-filters`, AssetPack, Spine, the DevTools extension) and to a scaffolded "creation template" whose own source adds screens, audio and resize handling. Every subsystem is registered through one global `extensions` registry, which is also how an app adds a plugin, a loader parser or a renderer system.

The docs show no complete game. Their tutorials are "Getting Started", "Fish Pond", "Choo Choo Train" and "Spine Boy Adventure" (https://pixijs.com/8.x/tutorials). The smallest complete program is the README's (comments removed here):

```ts
import { Application, Assets, Sprite } from "pixi.js";

(async () => {
  const app = new Application();
  await app.init({ background: "#1099bb", resizeTo: window });
  document.body.appendChild(app.canvas);

  const texture = await Assets.load("https://pixijs.com/assets/bunny.png");
  const bunny = new Sprite(texture);

  bunny.anchor.set(0.5);
  bunny.x = app.screen.width / 2;
  bunny.y = app.screen.height / 2;
  app.stage.addChild(bunny);

  app.ticker.add((time) => {
    bunny.rotation += 0.1 * time.deltaTime;
  });
})();
```

Source: README.md:52-90.

## Features

### loop

PixiJS owns a variable-step frame loop. It has no fixed step, no accumulator, no interpolation, no timers and no delayed calls (no such declaration in `lib/**/*.d.ts`).

- **Frame callbacks** [core]: A function added to a ticker runs once per animation frame and receives the `Ticker` itself, not a delta number. An optional context becomes `this`. API: `app.ticker.add(fn, context?, priority?)`. Source: lib/ticker/Ticker.d.ts:296 (callback type at :17).
- **One-shot callback** [common]: A function that runs on the next frame and is then removed. The package's skill uses it to defer a destroy out of a render-time hook. API: `ticker.addOnce(fn, context?, priority?)`. Source: lib/ticker/Ticker.d.ts:332; skill:scene-container.md:110.
- **Removing a callback** [core]: A callback is removed by passing the same function and the same context it was added with. API: `ticker.remove(fn, context?)`. Source: lib/ticker/Ticker.d.ts:375; skill:ticker.md:40.
- **Callback priorities and frame order** [common]: Callbacks run in descending priority: `INTERACTION` 50, `HIGH` 25, `NORMAL` 0 (default), `LOW` -25, `UTILITY` -50. `app.render()` is registered at `LOW`, so a `HIGH` callback (physics) runs before normal ones and a `UTILITY` callback runs after the frame is drawn (pixel readback). API: `UPDATE_PRIORITY`. Source: lib/ticker/const.d.ts:9-34; skill:ticker.md:22-38.
- **Three time values** [core]: `deltaTime` is a dimensionless factor, about 1.0 at 60 fps and 2.0 at 30 fps; `deltaMS` is milliseconds, capped and scaled; `elapsedMS` is the raw milliseconds, never capped or scaled. API: `ticker.deltaTime`, `ticker.deltaMS`, `ticker.elapsedMS`. Source: lib/ticker/Ticker.d.ts:135, :160, :173; skill:ticker.md:42-50.
- **Time scale** [common]: One factor multiplies `deltaTime` and `deltaMS` for every listener of that ticker (slow motion, fast forward). It does not change `elapsedMS`. API: `ticker.speed`. Source: lib/ticker/Ticker.d.ts:208.
- **Delta cap** [common]: `minFPS` (default 10) caps the reported delta, so a long frame or a tab coming back from the background reports at most 100 ms. API: `ticker.minFPS`. Source: lib/ticker/Ticker.d.ts:505-508; skill:ticker.md:54.
- **Frame-rate cap** [niche]: `maxFPS` skips updates to hold a ceiling; 0 means no cap. Setting it below `minFPS` lowers `minFPS` to match. API: `ticker.maxFPS`. Source: lib/ticker/Ticker.d.ts:535-536.
- **Start, stop, pause** [core]: Stopping the ticker stops callbacks and rendering; starting resumes. The ticker does not pause on blur or `visibilitychange`; the author listens for that and calls `app.stop()` and `app.start()`. API: `ticker.start()`, `ticker.stop()`, `app.start()`, `app.stop()`. Source: lib/ticker/Ticker.d.ts:413, :426; lib/app/ApplicationMixins.d.ts:129, :142; skill:ticker.md:122.
- **Manual loop** [common]: With `autoStart: false` the ticker stays stopped but `app.render` stays registered, so the author drives frames from their own `requestAnimationFrame` with `app.ticker.update(time)`, or calls `app.render()` alone to draw without running callbacks. API: `app.init({ autoStart: false })`, `ticker.update(currentTime?)`, `app.render()`. Source: lib/app/TickerPlugin.d.ts:55; lib/ticker/Ticker.d.ts:463; lib/app/Application.d.ts:249; skill:ticker.md:99-120.
- **Several tickers** [common]: `app.ticker` is per application, `Ticker.shared` is a global one that starts itself, `Ticker.system` drives engine work (hover ticks, GC, prepare uploads), and `new Ticker()` makes a private one. `sharedTicker: true` makes the app use `Ticker.shared`. API: `Ticker.shared`, `Ticker.system`, `new Ticker()`, `app.init({ sharedTicker })`. Source: lib/ticker/Ticker.d.ts:258, :580, :591; lib/app/TickerPlugin.d.ts:80; skill:ticker.md:88-97.
- **Per-object render hook** [common]: A function assigned to an object runs once per render while the object is attached to the rendered scene, with the renderer as its argument. It replaces v7's per-frame `updateTransform` override. It also runs while the object is invisible or culled, and it runs twice if the stage is rendered twice in a frame. API: `container.onRender = (renderer) => { ... }`. Source: lib/scene/container/container-mixins/onRenderMixin.d.ts:25; skill:ticker.md:58-86.
- **FPS readout and listener count** [common]: `FPS` is `1000 / elapsedMS` of the last frame, unsmoothed; `count` is the number of listeners. API: `ticker.FPS`, `ticker.count`. Source: lib/ticker/Ticker.d.ts:479, :397; skill:ticker.md:56.
- **Target frame constant** [niche]: The static that defines what "one frame" means for `deltaTime` (0.06 frames per ms, i.e. 60 fps). API: `Ticker.targetFPMS`. Source: lib/ticker/Ticker.d.ts:90; skill:ticker.md:50.
- **Renderer scheduler** [niche]: A renderer system that runs a function every N milliseconds and returns an id to cancel it. It is marked advanced and is what the engine's garbage collection uses; it is the only interval facility in the package. API: `SchedulerSystem.repeat(func, duration, useOffset?)`, `cancel(id)` (extension name `scheduler`). Source: lib/rendering/renderers/shared/SchedulerSystem.d.ts:8-31; lib/rendering/renderers/shared/GCSystem.d.ts:100.

### scenes

No scene, state or screen manager, no transitions, and no scene lifecycle hooks. The docs' creation template (`npm create pixi.js`, template `creation-web`) scaffolds a "Creation Engine" into the project's own source: `engine.navigation.showScreen(ScreenClass)`, `presentPopup` and `dismissPopup`, a `Screen` interface with optional `show`, `hide`, `pause`, `resume`, `prepare`, `reset`, `update`, `resize`, `blur`, `focus`, and a static `assetBundles` list loaded before a screen is shown (https://pixijs.io/create-pixi/docs/guide/creations/engine/; skill:create.md:27). That code is a template, not part of `pixi.js`. What the package itself gives a game that builds its own screens:

- **One stage root** [core]: The application owns one root container; a screen is a `Container` the game adds to it and removes from it. API: `app.stage`. Source: lib/app/Application.d.ts:178.
- **Subtree teardown** [core]: Destroying a container with `{ children: true }` destroys its whole subtree and keeps shared textures; the files are released separately with `Assets.unload` or `Assets.unloadBundle`. API: `container.destroy({ children: true })`. Source: lib/scene/container/Container.d.ts:1343; skill:scene-container.md:96-112.
- **Attach and detach events** [common]: A container emits `added` and `removed` when it joins or leaves a parent, its parent emits `childAdded` and `childRemoved`, and `destroyed` and `visibleChanged` fire on the container itself. These need no `eventMode`. API: `container.on('added', (parent) => ...)`. Source: lib/scene/container/Container.d.ts:59; skill:scene-container.md:77-90.
- **Assets per screen** [common]: A bundle groups the files of one screen or level, is loaded with one call and unloaded with one call; the next screen's bundle can load in the background. API: `Assets.loadBundle(name, onProgress)`, `Assets.unloadBundle(name)`, `Assets.backgroundLoadBundle(name)`. Source: lib/assets/Assets.d.ts:577, :809, :677.
- **Any container as a render root** [niche]: The renderer draws any container as a root, to the screen or to a texture, with or without clearing first, so a game can keep several independent trees and choose which to draw. API: `renderer.render({ container, target?, clear?, transform? })`. Source: lib/rendering/renderers/shared/system/AbstractRenderer.d.ts:64-97, :262.

### entities

A game object is a `Container` or one of its subclasses. There are no components, no ECS, no tags or groups beyond a string label, no prefabs or factories, no state machines and no AI helpers.

- **Container as the base object** [core]: Every display object extends `Container`, which carries the transform, colour, visibility, events and child list. v7's separate `DisplayObject` base is gone. API: `new Container(options?)`. Source: lib/scene/container/Container.d.ts:599, :843.
- **Options-object constructors** [core]: Every scene class takes one options object, and the constructor copies every field onto the instance except `children`, `parent` and `effects`, so any public property is a valid option. API: `new Sprite({ texture, anchor: 0.5, x: 100, y: 200, tint: 0xffcc00 })`, `ContainerOptions`. Source: lib/scene/container/Container.d.ts:186; skill:scene-core-concepts/constructor-options.md:5-28.
- **Parent and child tree** [core]: Children are added, inserted, reordered, swapped, replaced and removed; `reparentChild` moves a child to another parent while keeping its world transform. API: `addChild(...children)`, `addChildAt`, `removeChild`, `removeChildAt`, `removeChildren(begin?, end?)`, `setChildIndex`, `getChildIndex`, `swapChildren`, `replaceChild`, `removeFromParent()`, `reparentChild`, `reparentChildAt`. Source: lib/scene/container/container-mixins/childrenHelperMixin.d.ts:11-249.
- **Leaves cannot hold children** [core]: `Sprite`, `Graphics`, `Text`, `Mesh`, `ParticleContainer`, `DOMContainer` and `GifSprite` have `allowChildren = false`; `sprite.addChild` logs a deprecation warning. A game object made of several parts is a plain `Container` that holds them. API: `allowChildren`. Source: lib/scene/container/container-mixins/childrenHelperMixin.d.ts:10; skill:scene-core-concepts.md:9-11.
- **Transform properties** [core]: Position, scale, rotation in radians or `angle` in degrees, skew, `pivot` (a local point mapped to the position, which shifts the drawing) and `origin` (a local point to rotate and scale around without shifting, since 8.11). The point properties are `ObservablePoint`s, so `obj.position.set(x, y)` marks the transform dirty. API: `x`, `y`, `position`, `scale`, `rotation`, `angle`, `skew`, `pivot`, `origin`, `updateTransform({ x, y, scaleX, ... })`, `setFromMatrix(matrix)`. Source: lib/scene/container/Container.d.ts:933-1088, :1195, :1223; skill:scene-container.md:23-35.
- **Inherited tint, alpha and blend mode** [core]: `alpha` and `tint` multiply down through children; the cumulative values are read with getters. API: `alpha`, `tint`, `blendMode`, `getGlobalAlpha()`, `getGlobalTint()`, `getGlobalTransform()`. Source: lib/scene/container/Container.d.ts:1226-1289; lib/scene/container/container-mixins/getGlobalMixin.d.ts:35-72.
- **Three ways to hide** [core]: `visible = false` removes the object from drawing, bounds, hit testing and accessibility; `renderable = false` stops drawing and hit testing but keeps bounds; `alpha = 0` keeps hit testing, so it makes an invisible click target. API: `visible`, `renderable`, `alpha`. Source: lib/scene/container/Container.d.ts:1303, :1323; skill:scene-container.md:37-47.
- **Labels and lookup** [common]: An object has an optional string label; a parent finds a child or all children by string or `RegExp`, optionally searching deep. This is the only naming or grouping facility. API: `label`, `getChildByLabel(label, deep?)`, `getChildrenByLabel(label, deep?, out?)`, `getChildAt<T>(i)`. Source: lib/scene/container/container-mixins/findMixin.d.ts:8, :53, :74.
- **Size as scale** [common]: `width` and `height` set the scale so the current bounds fit; `setSize` does both axes in one measurement. It is a one-time scale calculation, not a stored size. API: `width`, `height`, `setSize(w, h)`, `getSize()`. Source: lib/scene/container/Container.d.ts:1102-1151; skill:scene-container.md:73-75.
- **Bounds** [common]: World and local bounding boxes as a `Bounds` object (read `.rectangle` for a `Rectangle`); `boundsArea` replaces measuring with a fixed rectangle. API: `getBounds(skipUpdate?, bounds?)`, `getLocalBounds()`, `boundsArea`. Source: lib/scene/container/container-mixins/measureMixin.d.ts:58, :88; lib/scene/container/Container.d.ts:815.
- **Destroy options** [core]: `destroy()` unlinks one node; an options object chooses whether to also destroy children, textures, texture sources, graphics contexts and text styles. API: `destroy({ children, texture, textureSource, context, style })`. Source: lib/scene/container/destroyTypes.d.ts:25-155; skill:scene-container.md:96-112.
- **Subclass with a render hook** [common]: The documented way to give an object behaviour is a subclass that assigns `this.onRender` in its constructor, or a ticker callback that owns the object. API: `class Propeller extends Sprite { constructor() { ...; this.onRender = () => this.tick(); } }`. Source: skill:ticker.md:60-75.
- **Object pools** [niche]: A generic pool hands out and takes back instances of one class, calling `init(data)` and `reset()` on items that define them; `BigPool` is a shared group of pools keyed by class. The docs advise pooling frequently spawned objects instead of destroying them. API: `new Pool(Class)`, `pool.get(data?)`, `pool.return(item)`, `pool.prepopulate(n)`, `BigPool.get(Class, data?)`, `BigPool.return(item)`. Source: lib/utils/pool/Pool.d.ts:8-72; lib/utils/pool/PoolGroup.d.ts:15-61; skill:performance.md:20.
- **Method mixins** [niche]: A library adds methods or properties to `Container` or another class through the extension registry, and types them by augmenting the global `PixiMixins` namespace. `Container.mixin` is deprecated since 8.8.0. API: `extensions.mixin(Target, ...sources)`, `declare global { namespace PixiMixins { interface Container { ... } } }`. Source: lib/extensions/Extensions.d.ts:326; lib/scene/container/Container.d.ts:603-605; lib/events/EventsMixins.d.ts:4-16.
- **Unique ids** [niche]: Each container has a numeric `uid`; a counter function issues ids per name. API: `container.uid`, `uid(name?)`. Source: lib/scene/container/Container.d.ts:610; lib/utils/data/uid.d.ts:14.

### render

- **Three renderers behind one API** [core]: `app.init` picks WebGL (the default and the production choice), WebGPU (feature-complete, called experimental) or Canvas 2D (a reduced fallback: no filters, `Mesh` draws nothing). `preference` is a string hint or an array that excludes what it does not list. API: `app.init({ preference: 'webgl' | 'webgpu' | 'canvas' | [...] })`, `autoDetectRenderer(options)`, `renderer.name`. Source: lib/rendering/renderers/autoDetectRenderer.d.ts:10-32, :78; skill:core-concepts/renderers.md:5-46.
- **Sprite** [core]: A texture at a transform, with a normalized `anchor`, tint, alpha and optional pixel snapping. `Sprite.from` accepts a texture, a canvas, a video or a cache key. API: `new Sprite({ texture, anchor })`, `Sprite.from(source, skipCache?)`. Source: lib/scene/sprite/Sprite.d.ts:57-86, :126, :149.
- **Texture and TextureSource** [core]: A `Texture` is a frame of a `TextureSource`; many textures share one source. Sources exist for images, canvases, video, raw buffers, compressed data, cube maps and GPU textures owned by another library. A sub-region is `new Texture({ source, frame })`; a frame that changes later needs `dynamic: true`. API: `Texture`, `Texture.from(id)`, `Texture.EMPTY`, `Texture.WHITE`, `TextureSource`, `ImageSource`, `CanvasSource`, `VideoSource`, `BufferImageSource`, `texture.update()`, `texture.source.update()`. Source: lib/rendering/renderers/shared/texture/Texture.d.ts:44-72, :132-245; lib/rendering/renderers/shared/texture/sources/TextureSource.d.ts:165; skill:scene-sprite.md:24-49.
- **Sampling options** [common]: Per source: scale mode `nearest` or `linear`, address mode `clamp-to-edge`, `repeat` or `mirror-repeat`, mipmaps, resolution and alpha mode; a static sets the default for every later texture. API: `texture.source.scaleMode = 'nearest'`, `TextureSource.defaultOptions.scaleMode`. Source: lib/rendering/renderers/shared/texture/const.d.ts:54, :80; lib/rendering/renderers/shared/texture/sources/TextureSource.d.ts:29-82, :177.
- **Spritesheets (atlases)** [core]: A JSON atlas becomes a `Spritesheet` with `textures[name]` and `animations[name]`; it reads trimmed and rotated frames, a per-frame `anchor` and nine-slice `borders`, a resolution from `meta.scale`, and linked multi-pack sheets. API: `Assets.load<Spritesheet>('sheet.json')`, `sheet.textures`, `sheet.animations`, `sheet.linkedSheets`, `new Spritesheet({ texture, data }).parse()`. Source: lib/spritesheet/Spritesheet.d.ts:11-97, :206-304; skill:assets/spritesheet.md:13-62.
- **TilingSprite** [common]: A texture repeated over a rectangle, with an offset, scale and rotation of the pattern; animating `tilePosition` scrolls a background. Non-power-of-two textures and atlas frames tile correctly. API: `new TilingSprite({ texture, width, height })`, `tilePosition`, `tileScale`, `tileRotation`. Source: lib/scene/sprite-tiling/TilingSprite.d.ts:72-141, :199; skill:scene-sprite/tiling-sprite.md:19-35.
- **NineSliceSprite** [common]: A texture stretched with fixed corners and edges, for panels and buttons; borders come from options or from the texture's `defaultBorders`, which a spritesheet frame can carry. API: `new NineSliceSprite({ texture, leftWidth, topHeight, rightWidth, bottomHeight, width, height })`. Source: lib/scene/sprite-nine-slice/NineSliceSprite.d.ts:74-107, :200; skill:scene-sprite/nineslice-sprite.md:22-52.
- **Graphics shapes** [core]: Vector drawing by chained calls: draw a shape, then `fill()` and/or `stroke()` it. Shapes are rectangle, rounded, chamfered and filleted rectangles, circle, ellipse, polygon, regular and rounded polygon, rounded shape and star. API: `new Graphics().rect(x, y, w, h).fill(0xff0000).stroke({ width: 2, color: 0x000000 })`, `circle`, `ellipse`, `poly`, `roundRect`, `chamferRect`, `filletRect`, `regularPoly`, `roundPoly`, `roundShape`, `star`. Source: lib/scene/graphics/shared/Graphics.d.ts:90, :354, :406, :681-1172; skill:scene-graphics.md:5-20.
- **Graphics paths** [common]: Canvas-like path commands, including the SVG arc command; a `GraphicsPath` is built once and appended many times. API: `moveTo`, `lineTo`, `bezierCurveTo`, `quadraticCurveTo`, `arc`, `arcTo`, `arcToSvg`, `closePath`, `beginPath`, `new GraphicsPath()`, `g.path(path)`. Source: lib/scene/graphics/shared/Graphics.d.ts:463-850, :741; lib/scene/graphics/shared/path/GraphicsPath.d.ts:25.
- **Fills** [common]: A fill is a colour, a texture, a linear or radial `FillGradient`, a repeating `FillPattern`, or a style object; `textureSpace` chooses between per-shape (`local`) and shared pixel (`global`) mapping. The same inputs fill text. API: `fill(FillInput)`, `new FillGradient({ type, colorStops, start, end, textureSpace })`, `new FillPattern({ texture, repetition })`. Source: lib/scene/graphics/shared/FillTypes.d.ts:20, :71, :417; lib/scene/graphics/shared/fill/FillGradient.d.ts:185; lib/scene/graphics/shared/fill/FillPattern.d.ts:109; skill:scene-graphics.md:34-46, :89-126.
- **Strokes** [common]: Width, cap, join, miter limit, alignment (1 inside, 0.5 centred, 0 outside) and `pixelLine` for 1-pixel lines aligned to the pixel grid; a stroke also takes a texture, gradient or pattern. API: `stroke({ width, color, cap, join, miterLimit, alignment, pixelLine })`. Source: lib/scene/graphics/shared/FillTypes.d.ts:233-318, :393.
- **Holes** [niche]: `cut()` subtracts the current path from the previous fill or stroke. API: `g.rect(0, 0, 200, 200).fill(c).circle(100, 100, 50).cut()`. Source: lib/scene/graphics/shared/Graphics.d.ts:481; skill:scene-graphics.md:63-76.
- **Shared GraphicsContext** [common]: The drawing instructions live in a `GraphicsContext` that several `Graphics` draw; it is tessellated once. Swapping `graphics.context` between prebuilt contexts changes the drawing without re-tessellating. API: `new GraphicsContext().rect(...).fill(...)`, `new Graphics(context)`, `graphics.context = other`, `context.batchMode`, `context.customShader`. Source: lib/scene/graphics/shared/GraphicsContext.d.ts:68-103; skill:scene-graphics.md:159-175.
- **Draw-time transform stack** [niche]: A transform applied to points while drawing, separate from the object's transform, with `save()` and `restore()` that also push and pop the fill and stroke styles. Its order is the reverse of Canvas 2D. API: `rotateTransform`, `scaleTransform`, `translateTransform`, `setTransform`, `transform`, `save()`, `restore()`. Source: lib/scene/graphics/shared/Graphics.d.ts:1223-1469; skill:scene-graphics.md:128-153.
- **SVG in and out** [niche]: `svg(markup)` parses a subset of SVG into a context (paths, basic shapes, groups, gradients; no `transform` attributes, `<style>` blocks or text); an export function writes a context back to an SVG string. An `.svg` file loads as a rasterized texture or as a `GraphicsContext`. API: `graphics.svg(markup)`, `graphicsContextToSvg(graphicsOrContext, precision?)`, `Assets.load({ src, data: { parseAsGraphicsContext: true } })`. Source: lib/scene/graphics/shared/Graphics.d.ts:1194; lib/scene/graphics/shared/svg/SVGExporter.d.ts:15; skill:scene-graphics.md:181-190; skill:assets/svg.md:17-20.
- **SmoothGraphics and dashed lines** [niche]: A `Graphics` subclass with the same API that anti-aliases edges in the shader, so shapes are smooth without MSAA and inside render textures; `DashLineShader` gives it dashed strokes. API: `new SmoothGraphics()`, `context.customShader = new DashLineShader({ dash, gap })`. Source: lib/scene/graphics-smooth/shared/SmoothGraphics.d.ts:33; lib/scene/graphics-smooth/shared/DashLineShader.d.ts:47; skill:scene-graphics/smooth-graphics.md:1-57.
- **Canvas text** [core]: `Text` rasterizes a styled string to a texture. `TextStyle` covers font family, size, weight, style and variant, fill (colour, gradient, pattern), stroke, drop shadow, alignment, letter spacing, line height, leading, word wrap and break, white-space mode, padding, trim, baked filters, and inline tags through `tagStyles`. Each change of text or style redraws a canvas and re-uploads it. API: `new Text({ text, style, anchor, resolution })`, `TextStyle`. Source: lib/scene/text/Text.d.ts:143; lib/scene/text/TextStyle.d.ts:481-629, :691; lib/scene/text/AbstractText.d.ts:136-225; skill:scene-text/text.md:27-54.
- **Bitmap text and bitmap fonts** [common]: `BitmapText` draws glyph quads from an atlas, so changing the string only repositions quads; it is the class for scores and timers. The atlas is generated lazily from a system font, pre-generated with `BitmapFont.install`, or loaded from an AngelCode `.fnt` or `.xml` file; MSDF and SDF fonts are detected and stay sharp at any scale. ### camera

No camera object: no follow, no bounds or clamping, no zoom helper, no shake, flash or fade, no named cameras. A game moves, scales and rotates a "world" container instead. PixiJS Userland hosts `pixi-viewport`, described in its repository as "a highly configurable viewport/2D camera designed to work with pixi.js" (https://github.com/pixijs-userland/pixi-viewport, read as a search excerpt only; the ecosystem page links the Userland organization, not this package by name). What the package itself gives:

- **World container as the view** [common]: Panning, zooming or rotating the world is setting the position, scale or rotation of one container; flagged as a render group, that costs one matrix whatever the number of descendants. The docs name "a game world with thousands of entities that scrolls or zooms" as the fit. API: `const world = new Container({ isRenderGroup: true }); world.x = -cameraX`. Source: skill:scene-core-concepts/render-groups.md:5-21; lib/scene/container/Container.d.ts:188.

- **World to screen and back** [core]: `toGlobal` maps a local point to scene-root space, `toLocal` maps a root-space point (or a point of another container) into a container's space, and both are correct under rotation, scale and pivot and before the first render. ### input

PixiJS handles pointer input on scene objects: mouse, touch and pen, with wheel. It has no keyboard API, no gamepad, no pointer lock, no gesture recognition (pinch, swipe), no action bindings or remapping and no virtual sticks; the only keyboard handling is the accessibility system's (lib/accessibility/AccessibilitySystem.d.ts:232). In a Web Worker there are no pointer events at all (skill:environments.md:52).

- **Interactive objects** [core]: An object receives pointer events when its `eventMode` is `'static'` or `'dynamic'`. The five modes are `none` (the object and its subtree are skipped by hit testing), `passive` (the default: its own listeners never fire, its interactive children still work), `auto` (hit tested only when a parent is interactive), `static`, and `dynamic` (as static, plus synthetic events from a ticker while the pointer is still, for objects that move under it). API: `obj.eventMode = 'static'`, `app.init({ eventMode })`, `obj.isInteractive()`. Source: lib/events/FederatedEventTarget.d.ts:118, :225, :1062; lib/events/EventSystem.d.ts:52; skill:events.md:15-25.
- **Three ways to listen** [core]: Emitter style, DOM style with `once` and `capture` options, or a property handler per event. API: `obj.on('pointerdown', fn)`, `obj.once(...)`, `obj.off(...)`, `obj.addEventListener(type, fn, { once, capture })`, `obj.onclick = fn`. Source: lib/events/FederatedEventTarget.d.ts:317-1011, :1094-1116; skill:events.md:13.
- **Event types** [core]: Pointer, mouse and touch families: down, up, up outside the object, move, over, out, enter, leave, cancel; `click` (mouse), `tap` (touch) and `pointertap` (any pointer type); right-button variants and `contextmenu`; `wheel`. API: `'pointerdown' | 'pointerup' | 'pointerupoutside' | 'pointermove' | 'pointerover' | 'pointerout' | 'pointerenter' | 'pointerleave' | 'pointertap' | 'pointercancel' | 'click' | 'rightclick' | 'tap' | 'touchstart' | 'wheel' | ...`. Source: skill:events.md:27-36; lib/events/FederatedEventTarget.d.ts:317-1011.
- **Double click** [common]: There is no `dblclick` event; `e.detail` counts consecutive clicks on the same target within 200 ms of each other. API: `obj.on('pointertap', (e) => { if (e.detail === 2) ... })`. Source: lib/events/FederatedMouseEvent.d.ts:78; skill:events.md:30.
- **Global move events** [common]: Plain move events fire only while the pointer is over the object; the `global*move` events fire on every pointer movement, also outside the canvas, for objects that are interactive and on the rendered stage. Dragging uses them. API: `obj.on('globalpointermove', fn)`. Source: lib/events/FederatedEventTarget.d.ts:658; skill:events.md:31.
- **Bubbling, capture and delegation** [common]: An event's `target` is the deepest interactive object under the pointer, and the event bubbles through the ancestors; capture-phase listeners run first. A parent that is itself interactive can handle its children's events. API: `e.target`, `e.currentTarget`, `e.stopPropagation()`, `e.stopImmediatePropagation()`, `'pointerdowncapture'`. Source: lib/events/FederatedEvent.d.ts:123, :138, :273; skill:events.md:35-52.
- **Hit testing by geometry** [core]: Without a hit area the test uses the object's drawn geometry: a sprite's texture rectangle, a graphics' shapes, a mesh's triangles; a plain container is hit only where a child is. Invisible and non-renderable objects are skipped, `alpha = 0` objects are hit, and masks clip the test. Hit testing uses the transforms of the last render. API: none (automatic). Source: skill:events.md:54-65; skill:scene-mesh.md:55.
- **Hit areas** [core]: A hit area replaces the geometry test and clips the subtree. It is any shape class or any object with a `contains(x, y)` method, in the object's local coordinates. Clicks on empty canvas need `app.stage.eventMode = 'static'` and `app.stage.hitArea = app.screen`. API: `obj.hitArea = new Circle(50, 50, 40)`, `obj.hitArea = { contains(x, y) { ... } }`. Source: lib/events/FederatedEventTarget.d.ts:69-76, :297; skill:events.md:65-76.
- **Pruning hit tests** [common]: `interactiveChildren = false` skips an object's children, and `eventMode = 'none'` skips the object and its subtree, which also cuts the cost of hit testing large trees. API: `obj.interactiveChildren = false`. Source: lib/events/FederatedEventTarget.d.ts:261; skill:events.md:58.
- **Event object** [core]: Carries the position in scene-root space (`global`), in viewport CSS pixels (`client`), the movement delta, button and buttons bitmask, modifier keys, pointer type (`mouse`, `pen`, `touch`), pointer id, `isPrimary`, pressure, tilt, twist, contact size and the native DOM event; a method gives the position in any container's space. Event objects are reused, so points kept past the handler must be copied. API: `FederatedPointerEvent`, `e.global`, `e.client`, `e.movement`, `e.button`, `e.pointerType`, `e.pointerId`, `e.pressure`, `e.nativeEvent`, `e.getLocalPosition(container)`. Source: lib/events/FederatedMouseEvent.d.ts:50-140; lib/events/FederatedPointerEvent.d.ts:53-123; skill:events.md:133-137.
- **Multi-touch** [common]: Each touch is a pointer with its own `pointerId`, and touch events carry the modifier keys of the native event. Combining touches into gestures is left to the game. API: `e.pointerId`, `'touchstart' | 'touchmove' | 'touchend' | 'touchendoutside' | 'touchcancel'`. Source: lib/events/FederatedPointerEvent.d.ts:53; skill:events.md:33; README.md:22 ("Full Mouse & Multi-touch Support").
- **Wheel** [common]: Wheel events fire on the hit-tested object with delta x, y, z and the delta mode. PixiJS registers its wheel listener as passive, so stopping page scroll needs a native listener on the canvas. API: `obj.on('wheel', (e) => e.deltaY)`, `FederatedWheelEvent`. Source: lib/events/FederatedWheelEvent.d.ts:54-58; skill:events.md:139-145.
- **Cursors** [common]: The cursor shown is the `cursor` of the event target, a CSS cursor name or a named style registered on the event system (a CSS string, a style object or a function). API: `obj.cursor = 'pointer'`, `renderer.events.cursorStyles.hover = "url('x.png'), auto"`, `renderer.events.setCursor(mode)`. Source: lib/events/FederatedEventTarget.d.ts:39, :187; lib/events/EventSystem.d.ts:351, :430; skill:events.md:119-131.
- **Drag recipe** [common]: Dragging is not an API but a documented pattern: record the grab offset on `pointerdown`, follow `globalpointermove`, convert with `parent.toLocal(e.global)`, stop on `pointerup` and `pointerupoutside`. API: see the recipe. Source: skill:events.md:78-117.
- **Last pointer state outside a handler** [common]: The event system keeps the most recent pointer event. API: `app.renderer.events.pointer.global`. Source: lib/events/EventSystem.d.ts:454.
- **Switching event categories off** [niche]: Move, global move, click and wheel handling can each be disabled at init or at runtime to cut per-frame work. API: `app.init({ eventFeatures: { move, globalMove, click, wheel } })`, `renderer.events.features.globalMove = false`. Source: lib/events/EventSystem.d.ts:71, :119-179, :376; skill:events.md:147-162.
- **Event source element and default prevention** [niche]: The element that receives DOM events can be changed, and automatic `preventDefault` on pointer events can be turned off. API: `renderer.events.setTargetElement(el)`, `renderer.events.autoPreventDefault`. Source: lib/events/EventSystem.d.ts:298, :515.
- **Keyboard and screen-reader activation** [niche]: With the accessibility system active, Tab moves through accessible objects, and Enter or Space dispatches `click`, `pointertap` and `tap` to the object, as events without pointer fields. API: `obj.accessible = true; obj.tabIndex = 1`. Source: skill:accessibility.md:64-90.
- **Text input through the DOM** [niche]: A text field is an HTML `<input>` placed in the scene with `DOMContainer` (see ui). API: `new DOMContainer({ element: inputElement })`. Source: skill:scene-dom-container.md:5-19.

### audio

Nothing. `Assets` has no audio loader: an `.mp3` or `.wav` resolves `null`, and `.ogg` is tried as video (skill:assets.md:49; SKILL.md:33). The docs point to `@pixi/sound`, "a WebAudio API playback library, with filters" (https://pixijs.com/8.x/guides/getting-started/ecosystem). The creation template wraps it in its own source as `engine.audio.bgm.play(...)`, `engine.audio.sfx.play(...)` and `engine.audio.setMasterVolume(...)` (https://pixijs.io/create-pixi/docs/guide/creations/engine/). The one sound path inside the package is a video texture's own `HTMLVideoElement`, muted by default and unmuted from a user gesture (skill:assets/video.md:35-51).

### assets

- **One loader, one call** [core]: `Assets.load` takes a URL, an alias, a descriptor or an array, returns a promise of the parsed asset (a `Texture`, a `Spritesheet`, a font, parsed JSON, ...), caches it, and shares one request between concurrent calls. An array resolves to an object keyed by URL or alias. API: `await Assets.load<Texture>('hero.png')`, `await Assets.load([a, b])`. Source: lib/assets/Assets.d.ts:449-450; skill:assets.md:27-32; skill:assets/caching.md:5.
- **One-time init** [common]: An optional first call sets a base path, a manifest, texture preferences, default search parameters for cache busting, default load options and loader preferences. It runs once; a later call is ignored. API: `await Assets.init({ basePath, manifest, texturePreference, defaultSearchParams, loadOptions, preferences })`. Source: lib/assets/Assets.d.ts:70-245, :332; skill:assets.md:5-25, :121-131.
- **Aliases** [core]: A short name, or several, is registered for a source, then used to load and to read back synchronously. API: `Assets.add({ alias: 'hero', src: 'hero.png', data })`, `Assets.get('hero')`. Source: lib/assets/Assets.d.ts:387, :730; lib/assets/types.d.ts:216-220.
- **Bundles** [common]: A named group of assets, registered at runtime or in the manifest, loaded with one call that returns a record keyed by alias, and unloaded with one call. API: `Assets.addBundle('level1', [{ alias, src }])`, `await Assets.loadBundle('level1', onProgress)`, `await Assets.unloadBundle('level1')`. Source: lib/assets/Assets.d.ts:503, :577, :809; lib/assets/types.d.ts:258-262; skill:assets/bundles.md:17-33.
- **Manifest** [common]: One object or JSON URL that declares every bundle up front. The docs recommend generating it with the AssetPack CLI. API: `Assets.init({ manifest: { bundles: [{ name, assets: [...] }] } })`, `Assets.init({ manifest: 'assets/manifest.json' })`. Source: lib/assets/Assets.d.ts:128; lib/assets/types.d.ts:308-310; skill:assets/manifests.md:27-30; https://pixijs.download/release/docs/assets-2.html.md.
- **Background loading** [common]: Fire-and-forget loading of assets or bundles one at a time; a later foreground load of the same thing takes priority and waits only for what is not yet done. It reports no progress. API: `Assets.backgroundLoad(urls)`, `Assets.backgroundLoadBundle('level2')`. Source: lib/assets/Assets.d.ts:611, :677; skill:assets/background.md:22-25.
- **Progress** [core]: A callback receives 0 to 1 as the assets of one call complete, each asset counting one equal step. API: `Assets.load(urls, (p) => ...)`, `Assets.loadBundle(name, (p) => ...)`. Source: lib/assets/loader/Loader.d.ts:34; skill:assets/progress.md:17-21.
- **Errors, skip and retry** [common]: Per call or as a default: throw on the first failure, skip failed assets, or retry them a number of times with a delay, with an error callback per failed attempt. API: `Assets.load(urls, { strategy: 'throw' | 'skip' | 'retry', retryCount, retryDelay, onError, onProgress })`, `Loader.defaultOptions`. Source: lib/assets/loader/Loader.d.ts:34-116; skill:assets.md:73-103.
- **Resolution and format selection** [common]: A source pattern lists resolutions and formats, and the resolver picks the best match for the device and the stated preference; the resolution in the file name sets the texture's resolution so sizes stay in logical units. Format support is detected once at init. API: `Assets.add({ alias: 'hero', src: 'hero@{0.5,1,2}x.{avif,webp,png}' })`, `Assets.init({ texturePreference: { resolution, format } })`, `Resolver.RETINA_PREFIX`. Source: lib/assets/Assets.d.ts:145-149; lib/assets/resolver/Resolver.d.ts:67, :116; skill:assets/resolution.md:19-24.
- **Supported formats** [core]: Images (`.png`, `.jpg`, `.jpeg`, `.webp`, `.avif`), SVG, video (`.mp4`, `.webm`, `.ogv`, `.mov` and others), spritesheet JSON, AngelCode bitmap fonts (`.fnt`, `.xml`), web fonts (`.ttf`, `.otf`, `.woff`, `.woff2`), JSON and text. After a side-effect import each: compressed textures (`.basis`, `.dds`, `.ktx`, `.ktx2`) and animated GIF. There is no loader for audio, Aseprite files, Tiled, LDtk or glTF. API: parser ids `'texture' | 'svg' | 'video' | 'spritesheet' | 'bitmap-font' | 'web-font' | 'json' | 'text' | 'basis' | 'dds' | 'ktx' | 'ktx2'` (and `'gif'`). Source: lib/assets/types.d.ts:25; skill:assets.md:34-49.
- **Spritesheet loading** [core]: Loading the atlas JSON also loads the image it names, parses the frames, caches every frame name, and follows multi-pack links. `data` can supply an already loaded atlas texture, a cache prefix for frame names, or texture options for the image. API: `Assets.load({ src: 'a.json', data: { cachePrefix: 'a/', textureOptions: { scaleMode: 'nearest' } } })`. Source: skill:assets/spritesheet.md:13, :38, :60-62; skill:assets.md:114.
- **Fonts** [common]: A web font file is loaded and registered with the browser's `FontFaceSet`, with family, weights, style and other descriptors in `data`; a bitmap font file loads its page images and registers the font for `BitmapText`. API: `Assets.load({ src: 'inter.woff2', data: { family: 'Inter', weights: ['400', '700'] } })`, `Assets.load('arcade.fnt')`. Source: lib/assets/loader/parsers/loadWebFont.d.ts:20-41; skill:assets/fonts.md:14-45.
- **Compressed textures** [niche]: KTX2 with Basis, Basis, DDS and KTX load after their imports; listing a compressed format first in a pattern with an image fallback lets the resolver fall back where the GPU cannot sample it. API: `import 'pixi.js/ktx2'`, `src: 'bg.{ktx2,webp,png}'`, `getSupportedCompressedTextureFormats()`. Source: skill:assets/compressed-textures.md:13-16; lib/rendering/renderers/shared/texture/utils/getSupportedCompressedTextureFormats.d.ts:3.
- **Forcing a parser** [common]: The parser is chosen from the URL's extension only, so a URL without one (`blob:`, an API route, a hashed path) names its parser in the descriptor. API: `Assets.load({ src: blobUrl, parser: 'texture' })`. Source: lib/assets/types.d.ts:73; skill:assets.md:51-71.
- **Per-asset parser data** [common]: A `data` field on a descriptor is forwarded to that asset's parser: texture options for images, video options, font descriptors, spritesheet options. It applies on the first load of a source only. API: `{ alias: 'tile', src: 'tile.png', data: { scaleMode: 'nearest' } }`. Source: lib/assets/types.d.ts:65; skill:assets.md:105-119.
- **Cache-only texture factories** [core]: `Texture.from(key)` and `Sprite.from(key)` read what `Assets` has loaded and never fetch. API: `Texture.from('hero')`, `Sprite.from('hero')`. Source: lib/rendering/renderers/shared/texture/Texture.d.ts:143; skill:scene-sprite.md:18-22.
- **Unloading** [common]: Unloading removes the asset from the cache and destroys it, GPU memory included. There is no reference counting: an asset shared by two bundles is destroyed when either is unloaded. API: `await Assets.unload('hero.png')`, `await Assets.unloadBundle('level1')`. Source: lib/assets/Assets.d.ts:769, :809; skill:assets/caching.md:9-22.
- **Cache object** [niche]: The key-value store behind `Assets.get`, usable for diagnostics and by custom loaders. API: `Cache.has(key)`, `Cache.get(key)`, `Cache.set(key, value)`, `Cache.remove(key)`, `Assets.cache`. Source: lib/assets/cache/Cache.d.ts:8-88; lib/assets/Assets.d.ts:272; skill:assets/caching.md:24.
- **Preferences and fetch routing** [niche]: Images are fetched in a Web Worker and decoded with `createImageBitmap` by default; preferences turn the worker off (so a custom `fetch` with auth headers sees image requests), choose `<img>` loading, set cross-origin mode, or make SVG load as graphics. API: `Assets.setPreferences({ preferWorkers, preferCreateImageBitmap, crossOrigin, parseAsGraphicsContext })`. Source: lib/assets/Assets.d.ts:48, :846; skill:assets.md:121-141.
- **Custom loaders** [niche]: A loader parser is an object with an id, a `test(url)`, a `load(url)`, and optional `testParse`, `parse` and `unload`, registered as an extension; resolver, cache and format-detection parsers are separate extension types, and one `Asset` extension can group them. API: `extensions.add({ extension: { type: ExtensionType.LoadParser, name }, id, test, load })`. Source: lib/assets/loader/parsers/LoaderParser.d.ts:26-74; lib/extensions/Extensions.d.ts:57-65; https://pixijs.com/8.x/guides/concepts/architecture.
- **Reset for tests** [niche]: Clears the resolver, loader and cache so a fresh `init` can run. API: `Assets.reset()`. Source: lib/assets/Assets.d.ts:684; skill:assets.md:131.

The companion tool is AssetPack (`@assetpack/core`), a build-time CLI that scans an assets folder and writes a manifest in PixiJS's format (https://pixijs.download/release/docs/assets-2.html.md); the package's skill also says it generates bitmap and MSDF fonts from `.ttf` and `.otf` (skill:scene-text/bitmap-text.md:70-72).

## Ideas worth taking

1. **Bundles, a manifest and background loading as one model.** Assets are declared once by alias inside named bundles; a screen loads with `await Assets.loadBundle('level1', onProgress)`, the next one warms with `Assets.backgroundLoadBundle('level2')`, and a later foreground load of the same bundle takes priority and waits only for what is missing. The author writes no queue and no "is it loaded yet" state; the manifest is plain JSON a build tool can generate. Source: lib/assets/Assets.d.ts:503-677; skill:assets/background.md:22-25; skill:assets/manifests.md:27-30.
2. **Resolution and format chosen by a pattern in the source string.** `src: 'hero@{0.5,1,2}x.{avif,webp,png}'` with `texturePreference` lets the resolver pick the file, and the resolution in the chosen file name sets the texture's resolution, so `width` and `height` stay in logical units whichever file loads. The game never branches on device pixel ratio or codec support. Source: skill:assets/resolution.md:19-24; lib/assets/Assets.d.ts:145-149.
3. **`eventMode` as one five-valued property.** `none | passive | auto | static | dynamic` states in one place whether an object is hit tested, whether its children are, and whether it needs hover updates while the pointer is still. `none` prunes a whole subtree from hit testing, so the cost model is visible in the scene code, and the default (`passive`) makes interactivity opt-in per object. Source: lib/events/FederatedEventTarget.d.ts:118; skill:events.md:15-25.
4. **Pointer events shaped like the DOM's.** The same event names, bubbling, capture phase, `stopPropagation`, `addEventListener` options and `e.detail` click counts, plus `pointertap` as the one event that covers mouse, touch and pen. An author who knows DOM events has nothing to learn, and delegation on a parent container works the way it does on a page. Source: lib/events/FederatedEventTarget.d.ts:1094-1116; lib/events/FederatedEvent.d.ts:105-273; skill:events.md:27-52.
5. **A hit area is anything with `contains(x, y)`.** The interface has one method, the shape classes implement it, and a hit area both replaces the geometry test and clips the subtree. The same shapes serve drawing, masks, culling and hit testing, and a custom region is a three-line object literal. Source: lib/events/FederatedEventTarget.d.ts:69-76, :297; skill:events.md:65-76.
6. **The frame callback receives the clock object, with priorities.** A callback gets the `Ticker` and reads the unit it wants (`deltaTime`, `deltaMS`, raw `elapsedMS`); time scale and the long-frame cap are applied once, in the ticker. Named priorities place physics before animation and pixel readback after the render without the author ordering registrations by hand. Source: lib/ticker/Ticker.d.ts:17, :135-208, :296; lib/ticker/const.d.ts:9-34; skill:ticker.md:22-50.
7. **Draw order separated from the transform hierarchy.** `layer.attach(obj)` leaves an object under its logical parent, which still moves it, and draws it where the layer sits; a sorted layer orders objects from different parents by `zIndex`. A unit can stay inside its group and still be depth-sorted with other groups, and a HUD label can follow a world object without being reparented. Source: lib/scene/layers/RenderLayer.d.ts:159-389; skill:scene-core-concepts/layers.md:5-72.
8. **Two explicit, differently priced grouping switches.** `isRenderGroup: true` says "this subtree moves as one": children keep drawing normally and moving the root costs one matrix. `cacheAsTexture(true)` says "this subtree is visually static": it is rasterized once and refreshed only by `updateCacheTexture()`. Each is one flag or call with a stated contract, so the author picks by what changes, not by reading renderer internals. Source: skill:scene-core-concepts/render-groups.md:5-34; skill:performance.md:48-64; lib/scene/container/container-mixins/cacheAsTextureMixin.d.ts:45-55.
9. **"Shape, then style" drawing on a shareable context.** `new Graphics().rect(...).fill(...).stroke(...)` chains with no begin and end calls, so there is no open state to forget. The instructions live in a `GraphicsContext` that many `Graphics` draw after one tessellation, and assigning another prebuilt context swaps the picture cheaply. Source: lib/scene/graphics/shared/Graphics.d.ts:354-406; lib/scene/graphics/shared/GraphicsContext.d.ts:68; skill:scene-graphics.md:5-20, :159-175.
10. **Options-object constructors plus static `defaultOptions`.** Every scene class takes one object in which any public property is valid (`new Sprite({ texture, anchor: 0.5, x, y, tint })`), and classes carry their own defaults as a static (`TextureSource.defaultOptions.scaleMode = 'nearest'`, `Loader.defaultOptions`, `Particle.defaultOptions`). Construction is one statement, and a global default sits on the class it affects, which replaced v7's single global `settings` object. Source: skill:scene-core-concepts/constructor-options.md:5-28; skill:migration-v8.md:150-175; lib/assets/loader/Loader.d.ts:116.
11. **One extension contract for built-ins and third parties, with typed options.** A plugin is a class with `static extension` metadata and static `init` and `destroy`; a priority orders it against others; and its options are typed inside `app.init({...})` by declaration merging on `PixiMixins.ApplicationOptions`. The ticker, resize and culler plugins use exactly this, so nothing built in has a private door. Source: lib/app/Application.d.ts:59-67; lib/extensions/Extensions.d.ts:192-285; skill:application.md:96-141.
12. **Particles as flat structs with declared dynamic attributes.** A `Particle` has nine plain fields and is not a scene node, and `dynamicProperties: { position: true, color: true }` states which attributes are re-uploaded each frame while the rest upload once. The API makes it impossible to give a particle children, filters or events, which is what lets one container draw very many of them, and the per-frame cost is something the author declares. Source: lib/scene/particle-container/shared/Particle.d.ts:32-68; lib/scene/particle-container/shared/ParticleContainer.d.ts:106; skill:scene-particle-container.md:42-81; https://pixijs.com/8.x/guides/migrations/v8 ("ParticleContainer").

## Traps

1. **Stateful "begin, draw, end" drawing and positional constructor arguments.** v7's `beginFill(c).drawRect(...).endFill()`, `lineStyle(w, c)` and constructors such as `new BlurFilter(8, 4, 1, 5)` or `new Text('Hello', style)` were replaced in v8 by shape-then-style calls and options objects. The old names remain as deprecated shims, and ported code fails silently through them: an outline-only `lineStyle(...)` plus `drawRect(...)` with no `endFill()` draws nothing, and stroke `alignment` is inverted between the versions. Source: https://pixijs.com/8.x/guides/migrations/v8 ("Graphics API Overhaul", "Constructors have largely been changed to accept objects"); skill:scene-graphics.md:22-32; lib/scene/graphics/shared/Graphics.d.ts:1632-1672.
2. **A global mutable `settings` object, a `utils` namespace, and a library split into many packages.** v8 removed `settings` and `utils` in favour of init options, static `defaultOptions` and direct imports, and returned from `@pixi/*` sub-packages to one package because the split "led to issues, such as conflicting installations of different PixiJS versions, causing complications with internal caches". The v7 guide records the symptom: with two copies installed, "changing settings from `@pixi/settings` doesn't do anything". Source: https://pixijs.com/8.x/guides/migrations/v8 ("New Package Structure", "`settings` object has been removed"); https://pixijs.download/release/docs/migrations-1.html.md ("Exports from `@pixi/core`").
3. **Loading hidden inside constructors and factories.** v7's `Texture.from(url)` fetched the image and `new Application(options)` set everything up synchronously. In v8 textures "no longer know or manage loading of resources", `Texture.from` only reads the cache, and the application needs `await app.init()` because the renderer is chosen asynchronously. The remnants still bite: constructor options are ignored with a warning, and `app.canvas` throws before `init` resolves. Earlier, v7 replaced the callback-based `Loader` (XHR, a design "driven largely by Flash/AS3") with promise-based `Assets`. Source: https://pixijs.com/8.x/guides/migrations/v8 ("Async Initialisation", "Texture adjustments", "`Texture.from` no longer will load a texture from a URL"); https://pixijs.download/release/docs/migrations-1.html.md ("Replaces Loader with Assets"); skill:application.md:28-29.
4. **A frame callback that receives a bare delta, in a unit that is not time.** v7 passed `dt`, a dimensionless "frames at 60 fps" number; v8 passes the `Ticker` "to allow for more control over what unit of time is used". A v7 callback still runs in JavaScript and turns transforms into `NaN`. The unit confusion persists: `deltaTime` is about 1.0 per 60 fps frame, `AnimatedSprite.animationSpeed` is "frames per 60 fps tick" (1 means 60 frames a second), and the docs' own Ticker overview contradicts the type docs on whether `deltaMS` is scaled by `speed`. Source: https://pixijs.com/8.x/guides/migrations/v8 ("The `Ticker`'s callback"); skill:ticker.md:20, :42-50; skill:scene-sprite/animated-sprite.md:27; lib/ticker/Ticker.d.ts:137-160; https://pixijs.download/release/docs/ticker.html.md.
5. **Game logic hooked into an engine-internal per-frame method.** Games overrode `updateTransform()` to run code every frame; v8 removed that call "as nodes no longer contain any rendering logic" and added `onRender`. The replacement has its own traps: it runs while the object is invisible or culled, it runs once per render rather than per tick, a class method named `onRender` is never registered, and a method named `_onRender` collides with the internal slot. The official migration guide's own example names the method `_onRender`, which the package's skill says never to do. Source: https://pixijs.com/8.x/guides/migrations/v8 ("Other Breaking Changes"); skill:ticker.md:77-86.
6. **A boolean destroy shorthand that cascades, over assets with no reference counting.** `destroy(true)` sets every destroy option for every descendant: shared textures, whole atlases, shared graphics contexts and text styles are destroyed, the call raises nothing, and every later render that touches them throws. `Assets.unload` and `unloadBundle` count no references either, so unloading one bundle destroys a texture another bundle declares. Source: skill:scene-container.md:112; skill:assets/bundles.md:33; skill:assets/caching.md:20-22; SKILL.md:97.
7. **Failures that resolve instead of raising.** The package's skill opens with a list of "pitfalls that fail silently". `Assets.load` of a URL with no recognised extension, or of an audio file, resolves `null` with only a console warning; `loadBundle` of an unknown name resolves `undefined`; a second `Assets.init` is ignored, so its manifest is never registered; a filter with no program for the active renderer makes every filter on that container be skipped; an advanced blend mode without its import renders as `normal`; `new Sprite(textureSource)` type-checks and draws nothing. Source: SKILL.md:17-103; skill:assets.md:25, :53; skill:assets/bundles.md:20; skill:filters.md:116; skill:blend-modes.md:86.
8. **Objects that accept features they cannot honour.** In v7 any display object could have children and a `ParticleContainer` took `Sprite`s, which led to "Why doesn't my sprite work with filters?"; v8 made leaves childless (a deprecation that is scheduled to become an error) and particles flat structs. The same shape is still present elsewhere in v8: a `RenderLayer`'s own `visible`, `alpha`, position and `filters` silently do nothing, a `DOMContainer` accepts `tint`, `filters`, `mask` and `blendMode` that do nothing, the render root's `blendMode` is ignored, and `cacheAsTexture: true` passed as a constructor option overwrites the method. Source: https://pixijs.com/8.x/guides/migrations/v8 ("ParticleContainer", "Leaf nodes no longer allow children"); skill:scene-core-concepts.md:11; skill:scene-core-concepts/layers.md:26; skill:scene-dom-container.md:31; skill:blend-modes.md:15; skill:scene-core-concepts/constructor-options.md:39.
