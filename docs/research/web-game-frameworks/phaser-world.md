## Shape

A Phaser game is one `Phaser.Game` built from a config object (renderer type, size, scale, physics, the list of scenes); constructing it creates the renderer, adds a canvas to the page and starts the loop. All game code lives in scenes: classes that extend `Phaser.Scene` (or plain objects) with the hooks `init(data)`, `preload()`, `create(data)` and `update(time, delta)`. Each scene owns its display list, update list, cameras, input, tweens, clock and loader, reached as injected properties (`this.add`, `this.cameras`, `this.input`, `this.tweens`, `this.time`, `this.load`), while the renderer, textures, cache, animation definitions, sound, registry and scale manager belong to the game. Things on screen are game objects (Sprite, Image, Text, Graphics, TilemapLayer, ParticleEmitter and others) made by the factory `this.add.<type>(...)`, which also puts them on the scene's display list. A game object class is `GameObject` plus component mixins (Transform, Alpha, Tint, Depth, Origin and others), so every class shares the same chainable setters. Objects are organised with Group (a logical set and pool), Container (a transform parent) and Layer (a render bucket); there is no entity-component system. Change over time comes from sprite animations (global definitions played per sprite), tweens, timelines and, when the config enables one, a physics engine that moves bodies attached to game objects. Each scene's cameras draw its display list, and several scenes can run at once, drawn in scene-list order, which is how a HUD or a pause menu is usually built. Game logic is imperative code in `update` and in event callbacks, and state is held in the objects and changed in place. Phaser 4 keeps the shape of the Phaser 3 API but replaces the WebGL renderer (render nodes instead of pipelines) and merges FX and masks into one filter system.

The smallest complete game its docs show (`skills/game-setup-and-config/SKILL.md:16-33`):

```js
class MyScene extends Phaser.Scene {
  preload() {
    this.load.image("logo", "assets/logo.png");
  }

  create() {
    this.add.image(400, 300, "logo");
  }
}

const config = {
  type: Phaser.AUTO,
  scene: MyScene,
};

const game = new Phaser.Game(config);
```

## Features

### loop

Covered in phaser-systems.md.

### scenes

- **Scene class with lifecycle hooks** [core]: A scene is a class that extends `Phaser.Scene`. The Scene Manager calls `init(data)`, then `preload()` (the loader then runs), then `create(data)`, then `update(time, delta)` on every step while the scene runs. API: `class MyScene extends Phaser.Scene { init(data) {} preload() {} create(data) {} update(time, delta) {} }`. Source: types/phaser.d.ts:130440, types/phaser.d.ts:103516, skills/scenes/SKILL.md:56.
- **Scene from a plain object** [niche]: A scene can also be an object of `init`, `preload`, `create` and `update` callbacks, with `extend` holding properties copied onto the scene, so no class is written. API: `scene: { preload, create, update, extend }` (`Phaser.Types.Scenes.CreateSceneFromObjectConfig`). Source: types/phaser.d.ts:103484.
- **Scene settings** [core]: Each scene has a unique `key` and optional settings: whether it starts `active` and `visible`, a `pack` of files loaded before `preload`, a `cameras` config, its own `physics` and `loader` config, and which `plugins` it gets. API: `super({ key, active, visible, pack, cameras, physics, loader, plugins })`. Source: types/phaser.d.ts:103588.
- **Injected systems** [core]: A scene gets its own `add`, `make`, `cameras`, `input`, `tweens`, `time`, `load`, `data`, `events`, `children`, `lights` and `physics` or `matter`, plus references to the game-wide `anims`, `textures`, `cache`, `sound`, `registry`, `scale`, `plugins` and `renderer`. The property names can be changed with `map` and `mapAdd` in the settings. API: `this.add`, `this.cameras`, `this.tweens`, `super({ key, map: { add: 'makeStuff' } })`. Source: types/phaser.d.ts:130440, types/phaser.d.ts:103588, skills/scenes/SKILL.md:77.
- **Scene-owned worlds** [core]: There is no single world object. Each scene manages its own game objects, display list, cameras, input, tweens and timers, so a tween made in one scene is separate from another scene's. API: `this.children`, `this.cameras`, `this.tweens`. Source: https://docs.phaser.io/phaser/concepts/scenes ("What is a Scene?").
- **Start, stop, restart** [core]: `start` shuts the calling scene down and starts the target; `restart` does both for the caller; `stop` shuts a scene down so that it can be started again later. API: `this.scene.start('Level2', { score })`, `this.scene.restart(data)`, `this.scene.stop(key)`. Source: types/phaser.d.ts:129775, types/phaser.d.ts:129784, types/phaser.d.ts:129916.
- **Parallel scenes** [common]: `launch` starts another scene without stopping the caller, and `run` starts, wakes or resumes the target as its state requires. A HUD or a pause menu is usually a scene of its own running above the game scene. API: `this.scene.launch('UIScene', data)`, `this.scene.run(key, data)`. Source: types/phaser.d.ts:129840, types/phaser.d.ts:129856, https://docs.phaser.io/phaser/concepts/scenes ("Scene control methods").
- **Pause, sleep and switch** [common]: A paused scene stops updating but still renders. A sleeping scene neither updates nor renders and keeps its state in memory. `switch` sleeps the caller and starts or wakes the target. API: `this.scene.pause(key)`, `.resume(key)`, `.sleep(key)`, `.wake(key)`, `.switch(key)`. Source: types/phaser.d.ts:129866, types/phaser.d.ts:129886, types/phaser.d.ts:129906, skills/scenes/SKILL.md:222.
- **Timed transitions** [common]: `transition` keeps the caller and the target running together for `duration` ms, calls `onUpdate(progress)` each frame, then stops, sleeps or removes the caller. It emits transition events on both scenes. The config has no visual effect option: the author draws the effect in `onUpdate`, with a camera fade or with a Wipe filter. API: `this.scene.transition({ target, duration, sleep, remove, allowInput, moveAbove, moveBelow, onUpdate, onStart, data })`. Source: types/phaser.d.ts:129820, types/phaser.d.ts:103531, types/phaser.d.ts:129254.
- **Data passed on a scene change** [core]: The object given to `start`, `launch`, `restart`, `switch`, `wake` or `run` arrives as the argument of `init` and `create` and stays readable later. API: `this.scene.start(key, data)`, `init(data)`, `this.sys.getData()`. Source: types/phaser.d.ts:129775, types/phaser.d.ts:130335, skills/scenes/SKILL.md:186.
- **Scene order** [common]: Scenes render in list order (later ones on top) and update in reverse order, so the top scene gets input first. The order can be changed at runtime. API: `this.scene.bringToTop(key)`, `.sendToBack(key)`, `.moveAbove(a, b)`, `.moveBelow(a, b)`, `.moveUp(key)`, `.moveDown(key)`, `.swapPosition(a, b)`. Source: types/phaser.d.ts:129971, types/phaser.d.ts:130029, skills/scenes/SKILL.md:449.
- **Scenes added and removed at runtime** [niche]: `add` registers a scene (class, instance or config) under a key and can start it; `remove` destroys it. One class can be registered under several keys. API: `this.scene.add(key, sceneConfig, autoStart, data)`, `this.scene.remove(key)`. Source: types/phaser.d.ts:129830, types/phaser.d.ts:130006, skills/scenes/SKILL.md:258.
- **Scene status** [common]: A scene has one of ten statuses from `PENDING` to `DESTROYED`, and there are queries for the common ones. API: `Phaser.Scenes.RUNNING`, `this.scene.isActive(key)`, `.isPaused(key)`, `.isSleeping(key)`, `.isVisible(key)`, `.getStatus(key)`. Source: types/phaser.d.ts:128990, types/phaser.d.ts:129940, types/phaser.d.ts:130055.
- **Lifecycle events** [core]: Each scene's emitter fires `boot`, `start`, `ready`, `create`, `preupdate`, `update`, `postupdate`, `prerender`, `render`, `pause`, `resume`, `sleep`, `wake`, `shutdown` and `destroy`. `shutdown` is where a scene frees what it will make again on restart. API: `this.events.once('shutdown', fn)`, `Phaser.Scenes.Events.POST_UPDATE`. Source: types/phaser.d.ts:129037, skills/scenes/SKILL.md:369.
- **Queued scene operations** [core]: Every `this.scene.*` call is queued and carried out at the start of the next game step, so a scene never changes status in the middle of a frame. API: `Phaser.Scenes.SceneManager#processQueue`. Source: types/phaser.d.ts:129455, skills/scenes/SKILL.md:130.
- **Update and render switches** [niche]: Updating and rendering can be switched separately without a status change. API: `this.scene.setActive(value, key)`, `this.scene.setVisible(value, key)`. Source: types/phaser.d.ts:129925, types/phaser.d.ts:129933.
- **Per-scene plugin set** [niche]: `plugins: []` or a list of names limits which scene systems are created, for example a preload scene with only the loader. API: `super({ key: 'Preload', plugins: ['Loader'] })`. Source: types/phaser.d.ts:103588, skills/scenes/SKILL.md:307.
- **Talking between scenes** [common]: A scene reaches another by key and listens on its emitter, or both use the game-wide registry (the registry is covered in phaser-systems.md). API: `this.scene.get('GameScene').events.on('addScore', fn)`. Source: types/phaser.d.ts:130048, skills/scenes/SKILL.md:274.
- **Object added and removed events** [niche]: The scene emits an event when a game object joins or leaves it. API: `Phaser.Scenes.Events.ADDED_TO_SCENE`, `Phaser.Scenes.Events.REMOVED_FROM_SCENE`. Source: types/phaser.d.ts:129045, types/phaser.d.ts:129170.

### entities

- **GameObject base class** [core]: Every object extends `GameObject`, an event emitter with `scene`, `name`, `state`, `active`, `data`, `input`, `body` and `destroy()`. `isDestroyed` tells a caller the object is gone, and `ignoreDestroy` makes the object ignore destroy calls, the scene's included, so that it can outlive a scene. API: `Phaser.GameObjects.GameObject`, `obj.setActive(false)`, `obj.destroy()`. Source: types/phaser.d.ts:25659, types/phaser.d.ts:25790, types/phaser.d.ts:26162.
- **Component mixins** [core]: Object classes are built by copying component objects (Alpha, BlendMode, Depth, Flip, GetBounds, Lighting, Mask, Origin, ScrollFactor, Size, Texture, TextureCrop, Tint, Transform, Visible, PathFollower, Filters, RenderNodes, RenderSteps) onto the class prototype, so the same chainable setters exist on every class that includes a component. The set is fixed per class; components are not attached to instances. API: `Phaser.GameObjects.Components.Transform`, `sprite.setAlpha(0.5).setDepth(10)`. Source: types/phaser.d.ts:18026, skills/game-object-components/SKILL.md:47.
- **Factory and creator** [core]: `this.add.<type>(args)` creates an object and adds it to the display list. `this.make.<type>(config)` creates it from a config object whose values may be fixed, picked from an array, random in a range or computed by a callback. `this.add.existing(obj)` adds an object made with `new`. API: `this.add.sprite(x, y, key, frame)`, `this.make.sprite({ key, x: { randInt: [0, 800] } })`, `this.add.existing(obj)`. Source: types/phaser.d.ts:26890, types/phaser.d.ts:26400, types/phaser.d.ts:27155, types/phaser.d.ts:148335, skills/game-object-components/SKILL.md:369.
- **Custom object types** [common]: An author extends a built-in class (usually Sprite) and may register a factory function so that `this.add.myThing()` works in every scene. API: `Phaser.GameObjects.GameObjectFactory.register('laserBeam', function (x, y) { ... })`. Source: types/phaser.d.ts:27163, types/phaser.d.ts:26518, skills/game-object-components/SKILL.md:348.
- **Per-object update** [common]: An object with a `preUpdate(time, delta)` method is put on the scene's update list and called every frame while it is `active`. Sprite uses this to advance its animation; Image has no per-frame update. API: `preUpdate(time, delta)`, `obj.addToUpdateList()`, `obj.removeFromUpdateList()`. Source: types/phaser.d.ts:75994, types/phaser.d.ts:26105, types/phaser.d.ts:66497.
- **Display list membership** [common]: An object is on one display list at a time (the scene's or a Layer's) and is not drawn when it is on none. API: `obj.addToDisplayList(list)`, `obj.removeFromDisplayList()`, `this.children`. Source: types/phaser.d.ts:26092, types/phaser.d.ts:26119, types/phaser.d.ts:23003.
- **Group** [core]: A logical set of game objects with creation, lookup, counting and batch setters. It is not on the display list and has no transform, and an object may be in several groups. API: `this.add.group(children, config)`, `group.add(obj)`, `group.getChildren()`, `group.getMatching('active', true)`, `group.countActive()`. Source: types/phaser.d.ts:30677, types/phaser.d.ts:30888, skills/groups-and-containers/SKILL.md:37.
- **Object pool** [common]: A group with `classType` and `maxSize` returns its first inactive member or creates one, and `killAndHide` puts a member back. API: `group.get(x, y)`, `group.getFirstDead(createIfNull, x, y)`, `group.killAndHide(obj)`, `group.getTotalFree()`, `group.isFull()`. Source: types/phaser.d.ts:30974, types/phaser.d.ts:31007, types/phaser.d.ts:31272, types/phaser.d.ts:30728.
- **Bulk creation** [common]: One config creates many members with stepped position, scale, rotation, alpha and depth, a grid layout and hit areas. API: `group.createMultiple({ key, quantity, setXY: { x, y, stepX }, gridAlign: { width, cellWidth, cellHeight } })`. Source: types/phaser.d.ts:30798, types/phaser.d.ts:97456.
- **Group callbacks and child update** [niche]: `createCallback` and `removeCallback` run as members join or leave, and `runChildUpdate` calls each active member's `update`. API: `this.add.group({ runChildUpdate: true, createCallback, removeCallback })`. Source: types/phaser.d.ts:30746, types/phaser.d.ts:97404.
- **Batch operations (Actions)** [common]: Stateless functions take an array of objects and set, increment or spread a property, place the objects on a circle, line or rectangle, rotate them around a point, wrap them in a rectangle, shuffle them or lay them out in a grid. Group has many of them as methods. API: `Phaser.Actions.SetXY(items, x, y, stepX, stepY)`, `Phaser.Actions.PlaceOnCircle(items, circle)`, `Phaser.Actions.Spread(items, 'alpha', 0, 1)`, `group.incX(5)`. Source: types/phaser.d.ts:41, types/phaser.d.ts:372, types/phaser.d.ts:962, skills/actions-and-utilities/SKILL.md:48.
- **Container** [common]: A display-list parent whose position, rotation, scale and alpha apply to its children. A child belongs to one container by default, containers nest, and children can be found by name, property or index. API: `this.add.container(x, y, children)`, `container.add(child)`, `container.getByName(name)`, `container.setExclusive(false)`, `container.getBounds()`, `container.pointToContainer(point)`. Source: types/phaser.d.ts:20994, types/phaser.d.ts:21170, types/phaser.d.ts:21213, types/phaser.d.ts:21125, skills/groups-and-containers/SKILL.md:171.
- **Layer** [common]: A display-list bucket with its own depth, alpha, blend mode, visibility and filters but no transform; its children sort by depth inside it. Since 4.1 it is a full GameObject. API: `this.add.layer(children)`, `layer.add(obj)`, `layer.setDepth(n)`. Source: types/phaser.d.ts:32794, types/phaser.d.ts:33008, changelog/v4/4.1/CHANGELOG-v4.1.0.md:8.
- **Per-object data store** [common]: Any game object has a key and value store, created on first use, with set, get, increment and toggle. API: `obj.setData('hp', 10)`, `obj.getData('hp')`, `obj.incData('hp', -1)`, `obj.toggleData('alive')`. Source: types/phaser.d.ts:25838, types/phaser.d.ts:25882, types/phaser.d.ts:25938.
- **Name and state fields** [niche]: `name` is a free string and `state` a free number or string that Phaser never changes; the docs suggest `state` for values such as 'moving' or 'dead'. There is no state machine class. API: `obj.setName('boss')`, `obj.setState('attacking')`. Source: types/phaser.d.ts:25692, types/phaser.d.ts:25713, types/phaser.d.ts:25832.
- **Zone** [niche]: A game object with position and size and nothing drawn, used for hit areas, drop zones, overlap checks or as a base for objects that do not render. API: `this.add.zone(x, y, width, height)`. Source: types/phaser.d.ts:78270, types/phaser.d.ts:28089.
- **Objects made from map data** [common]: A tilemap turns the objects of a Tiled object layer, or chosen tiles, into sprites of a given class, matched by id, gid, name or type. API: `map.createFromObjects('Enemies', { gid: 26, classType: Enemy })`, `layer.createFromTiles(indexes, replacements, spriteConfig)`. Source: types/phaser.d.ts:138658, types/phaser.d.ts:104160, types/phaser.d.ts:142466.
- **Object events** [niche]: A game object emits `addedtoscene`, `removedfromscene` and `destroy`. API: `obj.once(Phaser.GameObjects.Events.DESTROY, fn)`. Source: types/phaser.d.ts:24252, types/phaser.d.ts:24261.
- **JSON form of an object** [niche]: An object can write out a JSON description of itself. API: `obj.toJSON()`. Source: types/phaser.d.ts:26032, types/phaser.d.ts:99559.
- **Deferred lists** [niche]: `Phaser.Structs.ProcessQueue` holds additions and removals until a fixed point between updates, so a list is not changed while it is iterated; the update list is one. `Phaser.Structs.List` is the ordered list under the display list. API: `Phaser.Structs.ProcessQueue`, `Phaser.Structs.List`. Source: types/phaser.d.ts:133237, types/phaser.d.ts:132774.

Not provided: an entity-component system, tags, a state machine class and AI helpers. The README names the third-party Rex plugins for finite state machines (`README.md:186-190`).

### render

- **Renderer choice** [core]: The config picks WebGL, Canvas, automatic choice or headless. v4 treats WebGL as the target and calls the Canvas renderer deprecated, since almost nothing new in v4 works in it. API: `new Phaser.Game({ type: Phaser.AUTO })`, `Phaser.WEBGL`, `Phaser.CANVAS`, `Phaser.HEADLESS`. Source: types/phaser.d.ts:5602, changelog/v4/4.0/CHANGELOG-v4.0.0.md:90.
- **Image** [core]: A static textured quad with no animation and no per-frame update. API: `this.add.image(x, y, key, frame)`. Source: types/phaser.d.ts:31314, types/phaser.d.ts:27219, skills/sprites-and-images/SKILL.md:43.
- **Sprite** [core]: An Image plus an animation state, updated every frame. API: `this.add.sprite(x, y, key, frame)`, `sprite.play(key)`. Source: types/phaser.d.ts:66456, types/phaser.d.ts:27888.
- **Textures, frames and atlases** [core]: A texture is a keyed image with named or numbered frames. Frames come from sprite sheets, JSON array or hash atlases, XML atlases, Unity atlases and the Phaser Compact Texture format, and textures can be made at runtime from a canvas, base64 data, raw bytes or a flat colour. API: `this.textures.addAtlas(key, source, data)`, `.addSpriteSheet(key, source, config)`, `.addSpriteSheetFromAtlas(key, config)`, `.createCanvas(key, w, h)`, `.addFlatColor(key, w, h, color)`, `sprite.setTexture(key, frame)`, `sprite.setFrame(frame)`. Source: types/phaser.d.ts:135231, types/phaser.d.ts:135469, types/phaser.d.ts:135623, types/phaser.d.ts:20109.
- **Texture filter and wrap** [niche]: A texture can be set to nearest or linear filtering and to clamp, repeat or mirrored-repeat wrapping (repeat modes need power-of-two sizes). API: `texture.setFilter(Phaser.Textures.FilterMode.NEAREST)`, `texture.setWrap(Phaser.Textures.WrapMode.REPEAT)`. Source: types/phaser.d.ts:135182, types/phaser.d.ts:135210, changelog/v4/4.0/CHANGELOG-v4.0.0.md:425.
- **Pixel reading** [niche]: The colour or alpha of a pixel of a texture frame can be read on the CPU. API: `this.textures.getPixel(x, y, key, frame)`, `this.textures.getPixelAlpha(x, y, key, frame)`. Source: types/phaser.d.ts:135705, types/phaser.d.ts:135717.
- **Transform, origin, size, flip** [core]: Every drawn object has position, scale, rotation in radians or degrees, a normalised origin, a display size and mirroring, with local and world matrix and point conversion. API: `setPosition(x, y)`, `setScale(x, y)`, `setRotation(rad)`, `setAngle(deg)`, `setOrigin(0.5, 1)`, `setDisplaySize(w, h)`, `setFlip(x, y)`, `getWorldTransformMatrix()`, `getLocalPoint(x, y)`. Source: types/phaser.d.ts:20391, types/phaser.d.ts:19586, types/phaser.d.ts:19910, types/phaser.d.ts:19277.
- **Depth and draw order** [core]: Objects draw in display-list order. `depth` sorts them, and list-position methods reorder without changing depth. Layers and Containers scope the ordering to their children. API: `obj.setDepth(n)`, `obj.setToTop()`, `obj.setToBack()`, `obj.setAbove(other)`, `obj.setBelow(other)`. Source: types/phaser.d.ts:18313, types/phaser.d.ts:23003, skills/game-object-components/SKILL.md:405.
- **Alpha and visibility** [core]: An object has one alpha or one per corner (WebGL). An invisible object skips drawing but still updates. API: `setAlpha(topLeft, topRight, bottomLeft, bottomRight)`, `setVisible(false)`. Source: types/phaser.d.ts:18038, types/phaser.d.ts:20931.
- **Tint and tint modes** [common]: An object has a tint colour per corner and a separate tint mode: MULTIPLY, FILL, ADD, SCREEN, OVERLAY, HARD_LIGHT and, from 4.2, MULTIPLY_TWO with a second colour. v4 split colour from mode; v3's `setTintFill` remains as a method that does nothing. API: `sprite.setTint(0xff0000).setTintMode(Phaser.TintModes.FILL)`, `sprite.setTint2(color)`. Source: types/phaser.d.ts:20233, types/phaser.d.ts:128073, types/phaser.d.ts:20361, changelog/v4/4.2/CHANGELOG-v4.2.0.md:40.
- **Blend modes** [common]: In WebGL an object can draw with NORMAL, ADD, MULTIPLY, SCREEN or ERASE (ERASE only into a framebuffer); the other Canvas modes are reached in WebGL through the Blend filter. A change of blend mode ends the current batch. API: `obj.setBlendMode(Phaser.BlendModes.ADD)`, `filters.internal.addBlend(texture, blendMode, amount, color)`. Source: types/phaser.d.ts:18130, types/phaser.d.ts:120870, types/phaser.d.ts:18624, changelog/v4/4.0/MIGRATION-GUIDE.md:58.
- **Crop** [niche]: Only a rectangle of the frame is shown. API: `sprite.setCrop(x, y, width, height)`. Source: types/phaser.d.ts:20155.
- **Scroll factor** [common]: A factor per object says how far camera scroll moves it: 0 pins it to the screen and fractions give parallax. It changes drawing only, not physics. API: `obj.setScrollFactor(x, y)`. Source: types/phaser.d.ts:19836, skills/game-object-components/SKILL.md:208.

API: `this.add.text(x, y, text, style)`, `text.setText(value)`, `text.setStyle({...})`, `text.setWordWrapWidth(width)`. Source: types/phaser.d.ts:72293, types/phaser.d.ts:27987, types/phaser.d.ts:99294, types/phaser.d.ts:89203, skills/text-and-bitmaptext/SKILL.md:414.
- **Bitmap text** [common]: Text drawn from a font texture, batched with sprites and cheap to change every frame, with size, alignment, letter and line spacing, wrap at a maximum width, drop shadow, tint per character or word and bounds per line, word and character. ## Ideas worth taking

1. **Scene operations are queued.** Every `this.scene.start`, `stop`, `pause` and so on is stored and carried out at the start of the next step. Why it works: an author can ask for a scene change from any callback, in the middle of an update, and no scene is half torn down while its own code is running. Source: skills/scenes/SKILL.md:130, types/phaser.d.ts:129455.
2. **Three named levels of "off" and one idempotent "on".** Pause stops update and keeps drawing, sleep stops both and keeps state, stop tears down; `run(key)` starts, wakes or resumes whatever the current state is. Why it works: a modal menu, an intermission and a level exit each have one call, and the caller of `run` does not need to know the target's state. Source: https://docs.phaser.io/phaser/concepts/scenes ("Scene operations"), types/phaser.d.ts:129856.
3. **A HUD is a parallel scene with its own camera, input and display list.** The game scene emits events and the UI scene listens; data arrives through `init(data)`. Why it works: the HUD does not scroll, zoom or pause with the game and needs no "ignore the camera" flags on each widget. Source: skills/scenes/SKILL.md:274, types/phaser.d.ts:129840.
4. **One filter abstraction for effects and masks, on any object or camera.** A filter is "image in, image out", held in two ordered lists (object space and screen space), and `add*` returns a controller with plain properties. Why it works: every effect composes with every other, the support matrix of v3 is gone, and a controller's properties can be tweened like any object. Source: changelog/v4/4.0/CHANGELOG-v4.0.0.md:96, skills/filters-and-postfx/SKILL.md:47.
5. **Derived effects are helper functions, not more primitives.** Bloom, shine and shape masks became `Phaser.Actions.AddEffectBloom`, `AddEffectShine` and `AddMaskShape`, which assemble threshold, blur, blend and gradient parts and return them. Why it works: the primitive set stays small and the author can still reach and adjust each part. Source: docs/Phaser 4 Rendering Concepts/Phaser 4 Rendering Concepts.md:60, types/phaser.d.ts:79.
6. **One value grammar for particle properties, and zones typed by a single method.** A property is a number, a list, `{ min, max }`, `{ start, end, ease }`, steps or callbacks, and a zone source is any object with `getRandomPoint`, `getPoints` or `contains`. Why it works: an effect is plain data that can live in a content file, and any shape or custom object can be a zone without an adapter. Source: skills/particles/SKILL.md:58, types/phaser.d.ts:98752, types/phaser.d.ts:98062.
7. **Tween config as a property map with fire-and-forget lifetime.** `{ targets, x: '+=100', alpha: { value, duration, ease }, yoyo, repeat }` starts at once and frees itself; `persist: true` is the opt-in to keep it, and `stagger()` returns a function usable wherever a value is. Why it works: the common case is one literal with no handle to manage, and per-property overrides do not need a second tween. Source: skills/tweens/SKILL.md:36, types/phaser.d.ts:104975, types/phaser.d.ts:147295.
8. **Timeline events as records with `at`, `from` or `in`.** Each record names what happens (run, tween, sound, set, event) and optional `if`, `once` and `stop`. Why it works: a cutscene is a list that can be read top to bottom, and relative `from` times let a step be inserted without renumbering. Source: skills/time-and-timers/SKILL.md:185, types/phaser.d.ts:104654.
9. **Animation definitions are global data; playback state is per sprite.** Definitions are keyed records that can come from Aseprite tags or JSON, and the sprite side has `play(key, ignoreIfPlaying)`, `chain`, `playAfterRepeat`, `stopOnFrame` and an `animationcomplete-<key>` event. Why it works: `play('walk', true)` can be called every frame without restarting, and "attack then idle" is one `chain` call instead of a completion handler. Source: skills/animations/SKILL.md:40, types/phaser.d.ts:2168, types/phaser.d.ts:2044, types/phaser.d.ts:2691.
10. **Static GPU layers trade flexibility for skipping the per-frame upload.** `SpriteGPULayer` and `TilemapGPULayer` hold their data on the GPU, and per-member motion is expressed as ease parameters the shader evaluates. Why it works: the docs name the buffer upload as the main cost of sprites, and a background of a million animated quads then costs one draw call. Source: docs/Phaser 4 Rendering Concepts/Phaser 4 Rendering Concepts.md:447, changelog/v4/4.0/CHANGELOG-v4.0.0.md:484.
11. **Camera feel as one-call effects with events, and follow that takes any `{ x, y }`.** `shake`, `flash`, `fadeOut`, `pan` and `zoomTo` take a duration, do not restart while running unless forced, and emit start and complete events; follow has a lerp per axis, an offset and a deadzone. Why it works: "fade out, then change scene" is `cam.fadeOut(1000)` plus one listener, and the follow target need not be a game object. Source: types/phaser.d.ts:3946, types/phaser.d.ts:5023, types/phaser.d.ts:4148, types/phaser.d.ts:3933.
12. **Debug views draw into an ordinary Graphics object behind one switch.** `debug: true` in the physics config, `this.input.enableDebug(obj)` and `map.renderDebug(graphics)` each show what the system believes (bodies, hit areas, colliding tiles) with the game's own renderer. Why it works: no separate tool is needed, the overlay sits in the scene where the author can place and style it, and it is one flag to remove. Source: types/phaser.d.ts:101348, types/phaser.d.ts:83986, types/phaser.d.ts:139148.

## Traps

1. **Each render subsystem managing GPU state itself.** v3 pipelines each set WebGL state on their own, and one that forgot to restore a parameter broke others ("some kinds of FX (but not all) would mess up a Mask"). v4 replaced them all with render nodes under one state manager and tells authors not to call `gl` directly. Source: docs/Phaser 4 Rendering Concepts/Phaser 4 Rendering Concepts.md:9, changelog/v4/4.0/MIGRATION-GUIDE.md:34.
2. **Two effect systems with a per-object support matrix.** v3 had `preFX` and `postFX`, available only on some objects, plus `BitmapMask` and `GeometryMask` as a separate system. v4 removed the split and made masks a filter that works on any object or camera. Source: changelog/v4/4.0/MIGRATION-GUIDE.md:66, changelog/v4/4.0/CHANGELOG-v4.0.0.md:96.
3. **One setter that changes two things.** v3's `setTint` silently switched fill mode off and `setTintFill` set colour and mode together. v4 separates `setTint` from `setTintMode`, and `setTintFill` is left as a method that does nothing. Source: changelog/v4/4.0/MIGRATION-GUIDE.md:114, types/phaser.d.ts:20361.
4. **A second renderer kept at partial parity.** The Canvas renderer is now "considered deprecated": many v3 features never worked in it and almost nothing new in v4 does, and it keeps its own mask type. Source: changelog/v4/4.0/CHANGELOG-v4.0.0.md:90, types/phaser.d.ts:19529.
5. **A draw-to-texture API with its own drawing logic.** v3's `DynamicTexture` let authors define batches and draw at once; the docs call it "too technical for most uses" and a source of compatibility problems. v4 routes it through the normal renderer, at the price of a required `render()` call that the migration guide lists as a breaking change. Source: docs/Phaser 4 Rendering Concepts/Phaser 4 Rendering Concepts.md:247, changelog/v4/4.0/MIGRATION-GUIDE.md:183.
6. **A limited 3D feature inside a 2D framework.** `Mesh`, `Plane`, the OBJ loader and the Camera3D and Layer3D plugins were removed as "limited 3D implementations", with 3D promised for later; a 2D-only `Mesh2D` came back in 4.2. Source: changelog/v4/4.0/CHANGELOG-v4.0.0.md:261, changelog/v4/4.0/MIGRATION-GUIDE.md:340, changelog/v4/4.2/CHANGELOG-v4.2.0.md:15.
7. **Duplicate and misnamed basics.** `Geom.Point` overlapped `Vector2` and was removed ("We only need one way to represent x,y coordinates"); `Math.TAU` held PI / 2 and now holds PI * 2, with `PI2` removed; the library's own `Set` and `Map` gave way to the native ones. Every user of them has to change code. Source: docs/Phaser 4 Rendering Concepts/Phaser 4 Rendering Concepts.md:86, changelog/v4/4.0/MIGRATION-GUIDE.md:266, changelog/v4/4.0/MIGRATION-GUIDE.md:305, changelog/v4/4.0/MIGRATION-GUIDE.md:317.
8. **A scene instance that is reused across restarts.** The constructor runs once and `init` on every start, so state set in the constructor, and references to objects destroyed at shutdown (often listeners still registered on an emitter), survive into the next run. The docs have a section on the bugs this causes and tell authors to reset in `init` and clean up on `shutdown`. Source: https://docs.phaser.io/phaser/concepts/scenes ("Problems restarting a scene"), skills/scenes/SKILL.md:342.
