# KAPLAY 3001.0.19

_Source paths are relative to the root of the npm package `kaplay@3001.0.19`. `dist/doc.d.ts` is the file `package.json` names as `types`. "Changelog" is https://github.com/kaplayjs/kaplay/blob/master/CHANGELOG.md (the packaged `CHANGELOG.md` only links to it). The guides at kaplayjs.com/docs/guides are labelled 3001.0.19 but in places describe API that is only in the v4000 alphas; where a guide and the 3001.0.19 types disagree, the types are followed and the difference is said._

## Shape

A game calls `kaplay(options)` once: it creates a WebGL canvas, starts the frame loop, and by default copies every API function onto the global scope (`global: false` returns a context handle instead). Assets are loaded with top-level `loadXxx(name, url)` calls that return thenable handles; a loading screen is drawn until all of them have finished. A game is divided into scenes: `scene(name, fn)` registers a function, and `go(name, ...args)` destroys the current objects and runs it. Inside a scene the author creates game objects with `add([...])`, one flat list of components, tag strings and plain data objects; the returned object carries every component's fields and methods. Objects form a tree under one root object, and children follow their parent's transform, pause state and visibility. Behaviour is attached with event handlers, global (`onUpdate`, `onKeyPress`), per tag (`onUpdate("enemy", fn)`, `onCollide("a", "b", fn)`) or per object (`obj.onUpdate`, `obj.onCollide`), and each handler returns a controller that pauses or cancels it. Components bring their own methods and events (`area()` collisions and clicks, `body()` gravity and jumping, `health()` hurt and death), and an author writes a new one as a function that returns an object with an `id`, a `require` list and lifecycle hooks. Drawing is done by components (`sprite`, `text`, `rect`) or by immediate-mode `drawXxx` calls inside `onDraw`. There is one camera and one built-in arcade physics world; there is no built-in networking, UI toolkit or save system beyond `getData`/`setData`.

```js
kaplay();
loadBean(); // Load the default sprite.

scene("red_bean", () => {
  add([sprite("bean"), color(RED)]);

  onKeyPress(() => {
    go("blue_bean");
  });
});

scene("blue_bean", () => {
  add([sprite("bean"), color(BLUE)]);
});

// Initial scene
go("red_bean");
```

Source: https://kaplayjs.com/docs/guides/starting (section "Scenes").

## Features

### loop

- **Implicit frame loop** [core]: `kaplay()` starts the loop itself; the author never calls a run or start function. Each frame runs zero or more fixed updates, then one update, then draw. API: `kaplay(opt?)`. Source: dist/doc.d.ts:10139 (the internal `run(fixedUpdate, update)` is at dist/doc.d.ts:10040).
- **Update hook** [core]: A function that runs every frame, either once (`onUpdate(fn)`), once per object with a tag (`onUpdate("tree", (tree) => ...)`), or for one object (`obj.onUpdate(fn)`). API: `onUpdate()`. Source: dist/doc.d.ts:5164, dist/doc.d.ts:5182, dist/doc.d.ts:9134.
- **Draw hook** [common]: `onDraw` handlers run after all update handlers; the `drawXxx` functions only work in this phase. API: `onDraw(fn)`, `onDraw(tag, fn)`, `obj.onDraw(fn)`. Source: dist/doc.d.ts:5193, dist/doc.d.ts:5212.
- **Fixed-step update** [common]: `onFixedUpdate` runs at a fixed 50 steps per second through an accumulator, separate from the frame rate. `fixedDt()` gives the step and `restDt()` the unconsumed remainder of the frame. API: `onFixedUpdate(fn)`, `fixedDt()`, `restDt()`. Source: dist/doc.d.ts:5140, dist/doc.d.ts:3237, dist/doc.d.ts:6349, dist/doc.d.ts:6356; step value `fixedDt:1/50` in dist/kaplay.mjs.
- **Delta time and clock** [core]: `dt()` is the time since the last frame and `time()` the total time since the start. API: `dt()`, `time()`. Source: dist/doc.d.ts:6342, dist/doc.d.ts:6363.
- **Frame-rate cap** [niche]: An option limits frames per second. API: `kaplay({ maxFPS })`. Source: dist/doc.d.ts:8815.
- **Time scale** [common]: One global multiplier slows or speeds the whole game. API: `debug.timeScale`. Source: dist/doc.d.ts:9730.
- **Global pause and frame step** [common]: `debug.paused = true` pauses the whole game, and `debug.stepFrame()` advances one frame while paused. API: `debug.paused`, `debug.stepFrame()`. Source: dist/doc.d.ts:9722, dist/doc.d.ts:9752.
- **Per-object pause** [common]: `obj.paused = true` stops an object's update events and those of its children; the object is still drawn. The pausing guide builds a pause menu by putting the whole game under one parent object and leaving the menu outside it. API: `obj.paused`. Source: dist/doc.d.ts:9217; https://kaplayjs.com/docs/guides/pausing.
- **Delayed call** [core]: `wait(seconds, action?)` runs a function later and returns a controller that can be paused, cancelled or awaited (`await wait(1)`). API: `wait(n, action?)`. Source: dist/doc.d.ts:7077, dist/doc.d.ts:9890.
- **Repeating timer** [core]: `loop(t, action, maxLoops?, waitFirst?)` runs a function every `t` seconds, optionally a limited number of times. API: `loop()`. Source: dist/doc.d.ts:7103.
- **Object-scoped timers** [common]: The `timer()` component gives an object its own `wait`, `loop` and `tween`; they pause when the object is paused and stop when it is destroyed. `maxLoopsPerFrame` stops a sub-frame interval from freezing the game. API: `timer(maxLoopsPerFrame?)`. Source: dist/doc.d.ts:4731, dist/doc.d.ts:2579; https://kaplayjs.com/docs/guides/optimization.
- **Handler controllers** [common]: Every `onXxx` call returns a `KEventController` with a `paused` flag and `cancel()`; several can be joined into one. API: `KEventController`, `KEventController.join()`. Source: dist/doc.d.ts:1402.
- **Tab visibility** [niche]: Handlers run when the browser tab is hidden or shown. API: `onHide(fn)`, `onShow(fn)`. Source: dist/doc.d.ts:5753, dist/doc.d.ts:5761.
- **Start after loading** [core]: `onLoad(fn)` runs when all assets have finished loading (or at once if they already have). API: `onLoad(fn)`. Source: dist/doc.d.ts:5319.
- **Lifetime timer** [common]: A component destroys its object after a number of seconds, with an optional fade-out. API: `lifespan(time, { fade })`. Source: dist/doc.d.ts:4832, dist/doc.d.ts:2492.
- **Shutdown** [niche]: `quit()` ends the loop and `onCleanup(fn)` registers what to run then. API: `quit()`, `onCleanup(fn)`. Source: dist/doc.d.ts:8582, dist/doc.d.ts:5381.

### scenes

- **Named scenes** [core]: A scene is a function registered under a name. `go(name)` destroys all existing objects and runs that function. API: `scene(name, def)`, `go(name, ...args)`. Source: dist/doc.d.ts:7840, dist/doc.d.ts:7859; https://kaplayjs.com/docs/guides/scenes.
- **Arguments to a scene** [core]: Everything after the name in `go()` is passed to the scene function, which is how a score or level number moves between scenes. API: `go("game", { score: 100, level: 1 })`. Source: dist/doc.d.ts:7859; https://kaplayjs.com/docs/guides/scenes.
- **Objects that survive a scene change** [common]: The `stay()` component keeps an object across `go()`, in all scenes or in a named list; it only works on children of the root. API: `stay(scenesToStay?)`. Source: dist/doc.d.ts:4773, dist/doc.d.ts:2549.
- **Leave hook** [niche]: A handler runs when the current scene ends and receives the next scene's name. API: `onSceneLeave(fn)`. Source: dist/doc.d.ts:5883.
- **Current scene name** [niche]: API: `getSceneName()`. Source: dist/doc.d.ts:5890.
- **Scene-less games** [common]: All calls work outside any scene, which suits small games; the guide warns that such code cannot be run again after the first `go()`. API: none. Source: https://kaplayjs.com/docs/guides/scenes.
- **Not in 3001.0.19** [niche]: The types have no transitions, no stacked or parallel scenes and no enter or update hook per scene. The v4000 alphas add `pushScene()`/`popScene()` and typed scene arguments. API: none. Source: Changelog, [4000.0.0-alpha.21] and [4000.0.0-alpha.22].

### entities

- **Game object from a component list** [core]: `add([...])` assembles an object from one flat array that mixes component objects (the return values of `pos()`, `sprite()`, `area()` ...), plain strings (tags) and plain object literals (their fields become fields of the object). The returned object has every property and method of every component merged onto it: `player.jump()` comes from `body()`, `player.moveTo()` from `pos()`. API: `add<T>(comps?: CompList<T> | GameObj<T>): GameObj<T>`. Source: dist/doc.d.ts:3865, dist/doc.d.ts:8649.
- **Typed merge** [core]: `GameObj<T>` is `GameObjRaw & MergeComps<T>`: TypeScript takes the union of the component types in the list, intersects them and drops the component hook keys, so `obj.pos` or `obj.hurt()` is typed from the list alone. API: `GameObj<PosComp | AreaComp>`. Source: dist/doc.d.ts:9256, dist/doc.d.ts:8642.
- **What a component may declare** [core]: A component is a function that returns an object. Reserved keys: `id` (the component's name, used by `unuse`, `has`, `c` and `require`; without it the object is not treated as a component), `require` (ids of components that must also be on the object), `add` (runs when the host object is added to the scene), `fixedUpdate`, `update`, `draw` (every frame after update), `destroy` (when the object is removed), `inspect` (a string shown in inspect mode) and `drawInspect`. Every other key is state or a method that appears on the game object. API: `interface Comp`. Source: dist/doc.d.ts:9596.
- **Writing a custom component** [common]: The author writes `function lifespan(time) { let timer = 0; return { id: "lifespan", update() { timer -= dt(); if (timer <= 0) destroy(this); } }; }`. Private state lives in the closure, and `this` inside every hook and method is the host game object. In TypeScript the component gets an interface that extends `Comp`, and `this` is typed as `GameObj<MyComp | PosComp>` when it needs other components. API: `(…args) => Comp`. Source: https://kaplayjs.com/docs/guides/custom_components.
- **Add and remove components at run time** [common]: `obj.use(comp)` adds a component, `obj.unuse(id)` removes it, `obj.has(id | ids, "and" | "or")` tests for it and `obj.c(id)` returns one component's state. `onUse` and `onUnuse` handlers observe the change. API: `obj.use()`, `obj.unuse()`, `obj.has()`, `obj.c()`. Source: dist/doc.d.ts:8998, dist/doc.d.ts:9012, dist/doc.d.ts:9035, dist/doc.d.ts:9114, dist/doc.d.ts:5264.
- **Tags** [core]: Tags are strings that group objects. They are given in the `add` list or changed with `obj.tag()`, `obj.untag()`; `obj.is(tag | tags, "and" | "or")` tests them, `obj.tags` lists them and `"*"` matches every object. In 3001 a component's id also counts as a tag unless `tagsAsComponents: false`. API: `obj.tag()`, `obj.untag()`, `obj.is()`, `obj.tags`. Source: dist/doc.d.ts:9053, dist/doc.d.ts:9071, dist/doc.d.ts:9081, dist/doc.d.ts:8957, dist/doc.d.ts:8842; https://kaplayjs.com/docs/guides/tags.
- **Behaviour for a whole tag** [core]: Handlers take a tag and run once per matching object with the object as first argument, so a group's behaviour is written once. API: `onUpdate(tag, fn)`, `on(event, tag, fn)`, `onAdd(tag, fn)`, `onDestroy(tag, fn)`, `destroyAll(tag)`, `trigger(event, tag, ...args)`. Source: dist/doc.d.ts:5164, dist/doc.d.ts:5130, dist/doc.d.ts:5223, dist/doc.d.ts:5244, dist/doc.d.ts:4018, dist/doc.d.ts:5091.
- **Queries** [common]: `get(tag | tags, opts)` returns matching objects, optionally recursive and optionally as a list that updates itself as objects come and go. `query()` filters by included and excluded tags, distance, visibility, hierarchy relation and name. API: `get(tag, { recursive, liveUpdate, only })`, `query({ include, exclude, distance, visible, hierarchy, name })`. Source: dist/doc.d.ts:3959, dist/doc.d.ts:9260, dist/doc.d.ts:3986, dist/doc.d.ts:9277.
- **Object tree** [common]: `obj.add([...])` creates a child whose position, rotation and scale are relative to its parent. Objects expose `parent`, `children`, `remove()`, `removeAll()`, `isAncestorOf()`; the global `add` is the root object's `add`. API: `obj.add()`, `obj.parent`, `obj.children`, `getTreeRoot()`. Source: dist/doc.d.ts:8890, dist/doc.d.ts:8943, dist/doc.d.ts:8950, dist/doc.d.ts:6301; https://kaplayjs.com/docs/guides/game_objects.
- **Destroying** [core]: `destroy(obj)` or `obj.destroy()` removes an object, `obj.exists()` tells whether it is still attached, and `onDestroy` handlers run on removal. API: `destroy(obj)`, `obj.destroy()`, `obj.exists()`. Source: dist/doc.d.ts:4002, dist/doc.d.ts:9106, dist/doc.d.ts:9192.
- **Hidden and paused flags** [common]: `obj.hidden` turns off an object's draw events and `obj.paused` its update events. API: `obj.hidden`, `obj.paused`. Source: dist/doc.d.ts:9211, dist/doc.d.ts:9217.
- **Detached objects** [niche]: `make([...])` creates an object without adding it; `add(obj)` attaches it later. v4000 removes it. API: `make(comps)`. Source: dist/doc.d.ts:3891; https://v4000.kaplayjs.com/docs/guides/migration-4000.
- **Re-add for ordering** [niche]: `readd(obj)` removes and re-adds an object without firing add or destroy events, which moves it to the top of the draw order. API: `readd(obj)`. Source: dist/doc.d.ts:3936.
- **Custom events on objects** [common]: `obj.on(name, fn)` listens and `obj.trigger(name, ...args)` fires any named event. Components define their events the same way and expose them as `onHurt`, `onGround` and so on; the known event names and their arguments are typed in one map. API: `obj.on()`, `obj.trigger()`, `GameObjEventMap`. Source: dist/doc.d.ts:9091, dist/doc.d.ts:9100, dist/doc.d.ts:3232.
- **State machine component** [common]: `state(initial, states, transitions?)` gives an object a current state, `enterState(name, ...args)`, and handlers for entering, leaving, updating and drawing each state. An optional transition table restricts which state may follow which, and `onStateTransition(from, to, fn)` hooks one edge. API: `state()`, `obj.enterState()`, `obj.onStateEnter()`, `obj.onStateUpdate()`, `obj.onStateEnd()`. Source: dist/doc.d.ts:4886, dist/doc.d.ts:4916, dist/doc.d.ts:2512.
- **Health component** [common]: `health(hp, maxHP?)` adds `hurt(n)`, `heal(n)`, `hp()`, `setHP()`, `maxHP()` and the events `hurt`, `heal` and `death`. API: `health()`, `obj.onDeath()`. Source: dist/doc.d.ts:4810, dist/doc.d.ts:2443.
- **Names** [niche]: `named(name)` gives an object a name that `query({ name })` can match. API: `named(name)`. Source: dist/doc.d.ts:4842, dist/doc.d.ts:9313.
- **Sentry (sight) component** [niche]: `sentry(candidates, opt)` reports objects that come into view, with a direction, a field of view, an optional line-of-sight raycast and a check frequency. API: `sentry()`, `obj.onObjectsSpotted()`, `obj.hasLineOfSight()`. Source: dist/doc.d.ts:5024, dist/doc.d.ts:2229, dist/doc.d.ts:2257.
- **Patrol component** [niche]: `patrol({ waypoints, speed, endBehavior })` moves an object along waypoints and loops, ping-pongs or stops at the end. API: `patrol()`, `obj.onPatrolFinished()`. Source: dist/doc.d.ts:5056, dist/doc.d.ts:2125.
- **Pathfinder and agent components** [niche]: `pathfinder({ graph })` computes waypoints to a target on a graph without moving; `agent({ speed, allowDiagonals })` moves an object to a target tile inside a level and reports navigation events. API: `pathfinder()`, `obj.navigateTo()`, `agent()`, `obj.setTarget()`. Source: dist/doc.d.ts:5063, dist/doc.d.ts:2117, dist/doc.d.ts:4980, dist/doc.d.ts:2085.
- **Follow and move components** [niche]: `follow(obj, offset)` keeps an object at another object's position; `move(dir, speed)` moves it in one direction forever. API: `follow()`, `move()`. Source: dist/doc.d.ts:4677, dist/doc.d.ts:4624.
- **Tile symbols as factories** [common]: `addLevel(map, { tiles })` maps each character of a text map to a function that returns a component list, the same thing `add()` takes; `level.spawn(sym | comps, tilePos)` creates more later. API: `addLevel()`, `level.spawn()`. Source: dist/doc.d.ts:7977, dist/doc.d.ts:3763, dist/doc.d.ts:9814.
- **Factories instead of prefabs** [common]: 3001.0.19 has no prefab API; the guide shows plain functions that return a component list or call `add()` themselves. v4000 adds `createPrefab()`/`addPrefab()` and `obj.serialize()`. API: `add(makeEnemy())`. Source: https://kaplayjs.com/docs/guides/game_objects; Changelog [4000.0.0-alpha.21].
- **No object pools** [niche]: Nothing in the types pools objects. The optimization guide tells authors to use `particles()`, `onDraw` or plain data instead of creating and destroying many objects. API: none. Source: https://kaplayjs.com/docs/guides/optimization.

### render

- **Sprite component** [core]: Draws a loaded sprite with options for the frame, flipping, stretching to a width or height, a texture sub-rectangle and a starting animation. API: `sprite(name, { frame, flipX, flipY, width, height, quad, anim, animSpeed, tiled, fill })`. Source: dist/doc.d.ts:4181, dist/doc.d.ts:1898.
- **Sprite sheets** [core]: A sheet is cut into frames at load time by a grid (`sliceX`, `sliceY`) or by explicit quads (`frames`). API: `loadSprite(name, src, { sliceX, sliceY, frames })`. Source: dist/doc.d.ts:1214.
- **Sprite atlas** [common]: One image holds several named sprites, each with its rectangle, slicing and animations, given inline or as a JSON URL. API: `loadSpriteAtlas(src, data | url)`. Source: dist/doc.d.ts:5980, dist/doc.d.ts:6003, dist/doc.d.ts:1354.
- **Automatic texture packing** [niche]: Loaded images are packed into shared textures by a `TexPacker`. `spriteAtlasPadding` sets the gap between them and `singular: true` keeps one image on its own texture. API: `kaplay({ spriteAtlasPadding })`, `loadSprite(name, src, { singular })`. Source: dist/doc.d.ts:1145, dist/doc.d.ts:8849, dist/doc.d.ts:1242.
- **Nine-slice** [common]: A sprite loaded with `slice9` margins (left, right, top, bottom) is drawn in nine slices "for proportional scaling" when it is given a width and height. API: `loadSprite(name, src, { slice9: { left, right, top, bottom } })`. Source: dist/doc.d.ts:1228, dist/doc.d.ts:1244.
- **Tiled sprite** [niche]: With `tiled: true` the width and height repeat the texture instead of stretching it. API: `sprite(name, { tiled: true, width, height })`. Source: dist/doc.d.ts:1906, dist/doc.d.ts:1020.
- **Text component** [core]: Draws text with a size, a font, word wrap to a width, alignment, and line and letter spacing. API: `text(txt, { size, font, width, align, lineSpacing, letterSpacing })`. Source: dist/doc.d.ts:4217, dist/doc.d.ts:2011.
- **Per-character transforms and styled tags** [common]: A transform function sets position, scale, angle, colour and opacity for each character by index. Named styles apply to chunks marked in the text as `"a [wavy]styled[/wavy] word"`. API: `text(txt, { transform, styles })`, `CharTransform`. Source: dist/doc.d.ts:2047, dist/doc.d.ts:2053, dist/doc.d.ts:771.
- **Fonts** [common]: Any font file the browser supports (ttf, otf, woff) can be loaded, with an optional outline and load size. A bitmap font is a grid image with a character width and height. API: `loadFont(name, src, { outline, size, filter })`, `loadBitmapFont(name, src, gridW, gridH, { chars })`. Source: dist/doc.d.ts:6115, dist/doc.d.ts:6139, dist/doc.d.ts:9362.
- **Text measuring** [niche]: `formatText(opt)` lays text out without drawing and returns its width, height and characters; `drawFormattedText` draws the result. API: `formatText()`, `drawFormattedText()`. Source: dist/doc.d.ts:8381, dist/doc.d.ts:8246.
- **Shape components** [core]: Rectangles (with corner radius), circles and polygons are components. `outline()` adds a stroke with width, colour, join and cap; it does not work on sprites or text. API: `rect(w, h, { radius, fill })`, `circle(r)`, `polygon(pts)`, `outline(width, color)`. Source: dist/doc.d.ts:4260, dist/doc.d.ts:4279, dist/doc.d.ts:4239, dist/doc.d.ts:4433.
- **Immediate-mode drawing** [common]: Inside `onDraw` or a component's `draw` the author calls draw functions directly, without a game object. Every call takes the same render properties: `pos`, `scale`, `angle`, `color`, `opacity`, `fixed`, `shader`, `uniform`, `outline`. API: `drawSprite()`, `drawText()`, `drawRect()`, `drawLine()`, `drawLines()`, `drawCurve()`, `drawBezier()`, `drawTriangle()`, `drawCircle()`, `drawEllipse()`, `drawPolygon()`, `drawUVQuad()`. Source: dist/doc.d.ts:8016–8222, dist/doc.d.ts:9401.
- **Gradients, arcs and line styles** [niche]: Rectangles, circles and ellipses take a two-colour gradient; circles and ellipses take start and end angles; lines take join, cap and miter limit. API: `drawRect({ gradient, horizontal, radius })`, `drawCircle({ start, end })`, `drawLines({ join, cap })`. Source: dist/doc.d.ts:886, dist/doc.d.ts:647, dist/doc.d.ts:857.
- **Textured and vertex-coloured polygons** [niche]: A polygon takes a colour and a UV per vertex and a texture, and concave polygons can be triangulated. API: `drawPolygon({ pts, colors, uv, tex, triangulate })`. Source: dist/doc.d.ts:9497.
- **Transform stack** [niche]: Push and pop translate, scale, rotate and matrix transforms around immediate-mode draws. API: `pushTransform()`, `pushTranslate()`, `pushScale()`, `pushRotate()`, `pushMatrix()`, `popTransform()`. Source: dist/doc.d.ts:8283–8340.
- **Colour and opacity** [core]: `color()` tints an object (RGB numbers, a `Color`, a hex string; CSS colour names since 3001.0.11) and `opacity()` sets its alpha. API: `color(r, g, b)`, `color("#ff00ff")`, `opacity(o)`. Source: dist/doc.d.ts:4115, dist/doc.d.ts:4147; Changelog [3001.0.11].
- **Draw order** [core]: `z(n)` orders objects within a layer. `setLayers(names, default)` defines named layers in order and `layer(name)` assigns an object to one. API: `z()`, `setLayers()`, `layer()`. Source: dist/doc.d.ts:4378, dist/doc.d.ts:7885, dist/doc.d.ts:4408.
- **Anchor** [core]: Sets the pivot of drawing and rotation by name or by vector; the default is top-left. API: `anchor("center")`. Source: dist/doc.d.ts:4350, dist/doc.d.ts:9584.
- **Masks** [niche]: A `mask()` component clips the drawing of an object's children to (or out of) its own shape; `drawMasked` and `drawSubtracted` do the same in immediate mode. API: `mask("intersect" | "subtract")`, `drawMasked(content, mask)`, `drawSubtracted(content, mask)`. Source: dist/doc.d.ts:4939, dist/doc.d.ts:8253, dist/doc.d.ts:8260.
- **Custom shaders** [common]: A shader is GLSL in a fixed form: a `vert(pos, uv, color)` and a `frag(pos, uv, color, tex)` function, with `def_vert()` and `def_frag()` giving the default result. It is attached to an object with uniforms as an object or as a function called each frame, or passed to any draw call. API: `loadShader(name, vert, frag)`, `loadShaderURL()`, `shader(id, uniform | () => uniform)`. Source: dist/doc.d.ts:6165, dist/doc.d.ts:6183, dist/doc.d.ts:4688; https://kaplayjs.com/docs/guides/shaders.
- **Full-screen post effect** [common]: One shader is applied to the whole rendered frame. API: `usePostEffect(name, uniform?)`. Source: dist/doc.d.ts:8359.
- **Render to texture** [niche]: `makeCanvas(w, h)` makes an off-screen framebuffer with `draw(fn)`, `toImageData()`, `toDataURL()` and `free()`; the `drawon()` component sends an object's drawing there. The data URL can be passed to `loadSprite` to make a procedural sprite, and the texture feeds multi-pass shaders. API: `makeCanvas()`, `drawon(canvas.fb)`. Source: dist/doc.d.ts:8389, dist/doc.d.ts:9377, dist/doc.d.ts:4960; https://kaplayjs.com/docs/guides/canvas.
- **UV quad** [niche]: A rectangle with UV coordinates and no texture, meant as a surface for a shader. API: `uvquad(w, h)`. Source: dist/doc.d.ts:4298.
- **Particles** [common]: One component emits and draws many particles from one texture. Particle options give ranges for lifetime, speed, acceleration, damping, angle and spin, and lists of scales, colours and opacities over the lifetime; emitter options give shape, rate, direction and spread. API: `particles(ParticlesOpt, EmitterOpt)`, `obj.emit(n)`, `obj.onEnd()`. Source: dist/doc.d.ts:4470, dist/doc.d.ts:1648–1700; https://kaplayjs.com/docs/guides/particles.

## Ideas worth taking

1. **One flat list declares an object, and its type follows.** `add([sprite("bean"), pos(100, 200), area(), body(), health(8), "friendly", { speed: 240 }])` mixes components, tags and data in one array, and `GameObj<T>` merges the component types so `obj.jump()` and `obj.hp()` are typed with no class or interface written by the author. It works because the whole definition of an entity is readable in one place and adding a capability is adding one line. Source: dist/doc.d.ts:3865, dist/doc.d.ts:9256, dist/doc.d.ts:8642.
2. **A component is a function that returns a plain object with a small fixed set of hook names.** `id`, `require`, `add`, `update`, `fixedUpdate`, `draw`, `destroy`, `inspect`; everything else is public state and methods, private state is the closure, and `this` is the host object. The author needs no base class, no registration and no decorator, and `require` turns a missing dependency into an immediate error instead of an undefined method later. Source: dist/doc.d.ts:9596; https://kaplayjs.com/docs/guides/custom_components.
3. **Handlers scoped by tag.** `onUpdate("enemy", (e) => ...)`, `onCollide("bullet", "enemy", (b, e) => ...)`, `on("hurt", "friend", fn)` and `trigger("shoot", "target", 140)` attach behaviour to a group once. The author keeps no lists of entities and writes no loops over them, and a new object joins the behaviour by carrying the tag. Source: dist/doc.d.ts:5164, dist/doc.d.ts:5420, dist/doc.d.ts:5130, dist/doc.d.ts:5091.
4. **Every subscription returns a controller, and subscriptions made on an object share its life.** `const ev = onUpdate(...)` gives `ev.paused` and `ev.cancel()`; `obj.onKeyPress(...)`, `obj.wait(...)`, `obj.tween(...)` pause when the object pauses and end when it is destroyed. Pausing a whole game is then `game.paused = true` on one parent object, with the pause menu left outside it. Source: dist/doc.d.ts:1402, dist/doc.d.ts:9230, dist/doc.d.ts:2579; https://kaplayjs.com/docs/guides/pausing.
5. **Timers and tweens are thenable.** `await wait(1)`, `await obj.tween(from, to, 0.5, set, easings.easeOutQuad)` and `wait(2).onEnd(fn)` come from the same controller, which also has `paused`, `cancel()` and, for tweens, `finish()`. A cutscene or an attack pattern is written as a straight async function and needs no timeline API. Source: dist/doc.d.ts:9890, dist/doc.d.ts:9910, dist/doc.d.ts:7059–7077.
6. **Actions declared once, typed by name, remappable and pressable from code.** `kaplay({ buttons: { jump: { keyboard: ["space", "up"], gamepad: "south" } } })` makes `"jump"` the only string `onButtonPress` accepts in TypeScript. `setButton("jump", { keyboard: ["w"] })` rebinds one device and keeps the others, `pressButton("jump")` drives the same handlers from a touch control or a script, and `getLastInputDeviceType()` picks the glyph set. Source: dist/doc.d.ts:8809, dist/doc.d.ts:5847, dist/doc.d.ts:6653, dist/doc.d.ts:6669, dist/doc.d.ts:6703; https://kaplayjs.com/docs/guides/input.
7. **The collider defaults to the drawn shape, and one component serves collision and pointer hit testing.** `area()` with no arguments takes the sprite's or rectangle's bounds, and the same component gives `onCollide`, `onClick`, `onHover` and `hasPoint`. The common case costs one word, and a button and a pickup use the same mechanism. Source: dist/doc.d.ts:4300–4330, dist/doc.d.ts:2610.
8. **A collision is a value with questions and a veto.** The `Collision` passed to handlers answers `isTop()`, `isBottom()`, `isLeft()`, `isRight()` and `hasOverlap()`, and `preventResolution()` called in `onBeforePhysicsResolve` lets game code decide solidity case by case (one-way platforms, pass-through while dashing) without engine flags. Source: dist/doc.d.ts:9653, dist/doc.d.ts:2878.
9. **Assets are named handles that the game may use before they resolve.** `loadSprite("bean", url)` returns an `Asset<SpriteData>` that is thenable, components take the name, `load(promise)` adds any promise to the same gate, `onLoading(progress)` draws the loading screen and `onLoadError((name, asset) => ...)` lets the game decide whether a failed asset is fatal. The author writes no preload scene and no manifest for a small game. Source: dist/doc.d.ts:1281, dist/doc.d.ts:6201, dist/doc.d.ts:5352, dist/doc.d.ts:5342.
10. **Level text maps to the same component lists `add()` takes.** `addLevel(["  $  ", "====="], { tileWidth, tileHeight, tiles: { "=": () => [sprite("floor"), area(), body({ isStatic: true })], "$": () => [sprite("coin"), area(), "coin"] } })` keeps the layout as readable text and makes a tile definition identical to an entity definition; `wildcardTile` handles unknown symbols and `level.spawn()` reuses the definitions later. Source: dist/doc.d.ts:7933–7977, dist/doc.d.ts:3763, dist/doc.d.ts:9814.
11. **Debugging is part of the component contract and on by default.** Each component may return an `inspect()` string, `debug.inspect` draws colliders and shows those strings for the hovered object, and pause, single-step, time scale and an on-screen `debug.log()` are bound to F-keys without setup; `debug: false` removes them for release. Source: dist/doc.d.ts:9628, dist/doc.d.ts:9718; https://kaplayjs.com/docs/guides/debug_mode.
12. **Lifetime policies are components.** `lifespan(1, { fade: 0.5 })`, `offscreen({ destroy: true })`, `offscreen({ hide: true, pause: true })` and `stay()` state when an object dies, sleeps or survives a scene change at the place the object is declared. A bullet is `[sprite("bullet"), pos(p), move(LEFT, 600), offscreen({ destroy: true })]` and has no update code at all. Source: dist/doc.d.ts:4832, dist/doc.d.ts:4644, dist/doc.d.ts:3132, dist/doc.d.ts:4773; https://kaplayjs.com/docs/guides/optimization.

## Traps

1. **Every function on the global scope by default.** `kaplay()` exports names such as `pos`, `sprite`, `add`, `color` and `scale` to `window` unless `global: false`. The optimization guide tells authors to turn it off ("Avoid Global Namespace") and the README says not to use globals for a published game. Source: dist/doc.d.ts:8825; https://kaplayjs.com/docs/guides/optimization; README.md.
2. **Component ids doubled as tags.** In 3001 `obj.is("sprite")` is true because a component's id is added as a tag; the v4000 migration guide says this "could cause some collisions or unexpected results", flips the default, splits the check into `has()` for components and `is()` for tags, and renames the option from `tagsAsComponents` to `tagComponentIds`. Source: dist/doc.d.ts:8842; https://v4000.kaplayjs.com/docs/guides/migration-4000; Changelog [4000.0.0-alpha.21].
3. **Accessor shapes that had to be changed.** Combined get-or-set functions `camPos()`, `camScale()`, `camRot()`, `camTransform()` and `volume()` are deprecated for `setCamPos()`/`getCamPos()` pairs and `setVolume()`/`getVolume()`. `health()`'s `hurt()`/`heal()`/`hp()`/`setHP()` methods become an `hp` property in v4000, and `worldPos()`/`screenPos()` become properties. Source: dist/doc.d.ts:6834–6909, dist/doc.d.ts:7159; Changelog [3001.0.5], [4000.0.0-alpha.26]; https://v4000.kaplayjs.com/docs/guides/migration-4000.
4. **Detached objects (`make()`).** Creating an object without adding it, changing it, then adding it is removed in v4000; the migration guide replaces it with functions that return component lists and with prefabs. Source: dist/doc.d.ts:3891; https://v4000.kaplayjs.com/docs/guides/migration-4000.
5. **Global timers and tweens that outlive what they change.** `tween()` takes a setter callback and `wait()` a callback, so a global one keeps running after its target object is destroyed. The animation guide says "your application may crash" and advises against the global `tween`; the optimization guide shows global `wait()` in state handlers creating "infinitely running state transitions". Source: https://kaplayjs.com/docs/guides/animation; https://kaplayjs.com/docs/guides/optimization.
6. **Draw order that depended on the parent, and layers removed then restored.** In 3001 `z()` sorts only among siblings; v4000 makes `z()` and layers global and the migration guide warns that children may now draw over other objects. `layer()` was removed in v3000 and re-added in 3001.0.0. Source: https://v4000.kaplayjs.com/docs/guides/migration-4000; Changelog [4000.0.0-alpha.19], [3001.0.0] ("Readded `layers()` and the `layer()` component").
7. **Handler lifetime left implicit, and handler names that meant two things.** v4000 adds explicit lifetime scopes (`app.onUpdate`, `scene.onUpdate`, `defaultLifetimeScope`), renames `onHide()`/`onShow()` to `onTabHide()`/`onTabShow()` so the old names can report an object's `hidden` flag, and removes the no-tag `onClick(fn)` in favour of `onMousePress()`. The scenes guide also warns that `go()` destroys every object, including ones made outside any scene, unless they carry `stay()`. Source: Changelog [4000.0.0-alpha.23], [4000.0.0-alpha.26], [unreleased]; https://kaplayjs.com/docs/guides/scenes.
8. **One heavyweight object per thing.** Every entity, every level tile and every text label is a game object with events and a transform. The optimization guide states "Game Object is not always the answer" and sends high-volume cases to `particles()`, `onDraw` and plain data; there is no pooling, and v4000 had to rework transforms, areas and the broad phase to recalculate only on change. Source: https://kaplayjs.com/docs/guides/optimization; Changelog [4000.0.0-alpha.25].
