# Phaser 4.2.1: its systems

Read from the published npm package `phaser@4.2.1` (`package.json` says `"version": "4.2.1"`, `"release": "Giedi"`). Paths below are relative to the package root. The package ships its type definitions (`types/phaser.d.ts`, 148,652 lines), a `skills/` folder of 28 guides written by the Phaser team, a `docs/` folder (rendering only) and every changelog since 3.1. The online API reference at https://phaser.io/oss/docs/api-documentation/api-documentation is for 4.1.0, one minor version behind the package; where the two could differ, the package is the source. This file covers the systems under a game: loop, physics, input, audio, assets, data, math, display, platform and net. The other areas are in `phaser-world.md`.

## Shape

A game is one `Phaser.Game` made from one `GameConfig` object: the renderer (`type`), the canvas size and parent, the scene classes, and one sub-object per system (`scale`, `physics`, `input`, `audio`, `loader`, `fps`, `render`, `plugins`, `dom`, `callbacks`) (`types/phaser.d.ts:95718-95954`). The constructor parses the config into a `Phaser.Core.Config`, creates the global managers (animations, textures, cache, input, scenes, scale, sound, the `TimeStep` loop, plugins), waits for `DOMContentLoaded`, creates the renderer, adds the canvas to the page and emits `boot`; when the texture manager is ready it emits `ready`, starts the loop and calls `postBoot` (`skills/game-setup-and-config/SKILL.md:39-46`). The loop calls `Game.step(time, delta)` once per `requestAnimationFrame`: it updates the global managers, then each scene, then renders each scene (`types/phaser.d.ts:5836-5848`). Game code lives in scenes: a class that extends `Phaser.Scene` with the optional hooks `init`, `preload`, `create` and `update(time, delta)`; only the first scene in the config's array starts by itself (`skills/game-setup-and-config/SKILL.md:197`). A scene reaches every system through a property on `this`: its own instances of the per-scene systems (`add`, `make`, `cameras`, `input`, `load`, `time`, `tweens`, `physics` or `matter`, `data`, `events`, `lights`, `scene`) and references to the global ones (`game`, `anims`, `cache`, `registry`, `sound`, `textures`, `scale`, `plugins`, `renderer`) (`types/phaser.d.ts:130450-130612`). Those systems are plugins: a global plugin exists once in the game's `PluginManager`, a scene plugin is instantiated for each scene, and a scene's config can choose which ones it gets (`types/phaser.d.ts:120472-120500`, `103612-103628`). Assets are queued in `preload` under string keys, land in game-wide caches, and are ready when `create` runs (`skills/loading-assets/SKILL.md:30-48`, `107-109`). Systems talk through event emitters with lowercase string event names, each also exported as a constant (`skills/events-system/SKILL.md:8`, `79-89`). The `delta` a scene's `update` gets is a smoothed, capped frame time in milliseconds; only the physics worlds run on a fixed step (`types/phaser.d.ts:5846`, `112813-112817`). Physics is off until the config names a default engine, for the game or for one scene (`https://phaser.io/oss/docs/phaser/concepts/physics`).

The smallest complete game in the package's own guide (the Guide's page on `Game` has a seven-line one with a single `create` function: https://phaser.io/oss/docs/phaser/concepts/game):

```js
// skills/game-setup-and-config/SKILL.md:16-33
class MyScene extends Phaser.Scene {
  preload() {
    this.load.image("logo", "assets/logo.png");
  }

  create() {
    this.add.image(400, 300, "logo");
  }
}

const config = {
  type: Phaser.AUTO,
  scene: MyScene,
};

const game = new Phaser.Game(config);
```

## Features

### loop

- **Frame loop on requestAnimationFrame** [core]: `Phaser.Core.TimeStep` runs the game from `requestAnimationFrame` and calls the game step once per browser frame; it is reachable as `game.loop`. API: `game.loop` (`Phaser.Core.TimeStep`). Source: types/phaser.d.ts:6647-6660, 5801.
- **Smoothed, capped variable delta** [core]: The step's `delta` is the frame time in ms, described as "a smoothed and capped value based on the FPS rate": it is averaged over the last frames (`fps.deltaHistory`, default 10) unless `fps.smoothStep` is `false`, and `loop.rawDelta` keeps the unsmoothed value. `fps.min` (default 5) is the lowest rate the loop treats as in sync. API: `fps: { min, deltaHistory, panicMax, smoothStep }`, `game.loop.delta`, `game.loop.rawDelta`. Source: types/phaser.d.ts:95687-95715, 5846, 6691-6697, 6812-6866; skills/game-setup-and-config/SKILL.md:340-350.
- **Frame rate cap** [common]: `fps.limit` makes the game step run at most that many times per second; it can only slow the game down, and `fps.target` is advisory. Since 4.2.0 the cap can be changed while running. API: `fps: { limit: 30 }`, `game.loop.setFPSLimit(limit)`. Source: types/phaser.d.ts:6708-6730, 6994; changelog/v4/4.2/CHANGELOG-v4.2.0.md:43 ("`Timestep#setFPSLimit`"); skills/game-setup-and-config/SKILL.md:442-444.
- **setTimeout loop** [niche]: The loop can run on `setTimeout` instead of `requestAnimationFrame`. API: `fps: { forceSetTimeOut: true }`. Source: types/phaser.d.ts:95703, 6767.
- **Frame and time counters** [common]: The measured frame rate (an exponential moving average), the frame number and the timestamp of the current step are readable. API: `game.loop.actualFps`, `game.getFrame()`, `game.getTime()`, `game.loop.getDuration()`. Source: types/phaser.d.ts:6744, 5910-5916, 6974.
- **Scene update hook** [core]: A scene's `update(time, delta)` runs every frame while the scene is active; the scene also emits `preupdate`, `update`, `postupdate`, `prerender` and `render` in that order. `update` does not run while the scene is still loading. API: `update(time, delta)`, `this.events.on(Phaser.Scenes.Events.UPDATE, fn)`. Source: types/phaser.d.ts:130623; skills/events-system/SKILL.md:127, 187-203; skills/loading-assets/SKILL.md:387.
- **Game step events** [niche]: The game emits `prestep`, `step`, `poststep`, `prerender` and `postrender` once per frame for code that is not in a scene. API: `game.events.on(Phaser.Core.Events.STEP, fn)`. Source: types/phaser.d.ts:6576-6624.
- **Pause and resume the whole game** [common]: `game.pause()` stops every system and rendering and emits `pause`; in-flight loader requests continue. The Guide notes the game cannot be resumed from Phaser's own input events, since they are paused too. API: `game.pause()`, `game.resume()`, `game.isPaused`. Source: types/phaser.d.ts:5870-5890, 5822; https://phaser.io/oss/docs/phaser/concepts/game.
- **Automatic pause when hidden or blurred** [core]: A visibility handler pauses the loop when the page is hidden or the window loses focus and resumes it after; the game emits `hidden`, `visible`, `blur` and `focus`. The docs say the browser stops the loop when hidden and nothing can prevent it. API: `game.events.on('hidden' | 'visible' | 'blur' | 'focus', fn)`, `game.loop.sleep()`, `game.loop.wake()`. Source: types/phaser.d.ts:6548-6559, 6961-6968, 7025; skills/game-setup-and-config/SKILL.md:367-380.
- **Manual stepping** [niche]: The loop can be advanced by one step from code, and `Game.step` and `Game.headlessStep` are public. API: `game.loop.tick()`, `game.step(time, delta)`, `game.headlessStep(time, delta)`. Source: types/phaser.d.ts:6952-6956, 5848, 5862.
- **Scene clock** [core]: Each scene has a `Clock` with the current time, the scene's start time, a `paused` flag and a `timeScale`; it stops with the scene. API: `this.time.now`, `this.time.startTime`, `this.time.paused`, `this.time.timeScale`. Source: types/phaser.d.ts:144480-144539.
- **Delayed call** [core]: One call schedules a callback after a delay in ms and returns the timer. API: `this.time.delayedCall(delay, callback, args?, scope?)`. Source: types/phaser.d.ts:144568.
- **Repeating and looping timers** [core]: A timer config sets `delay`, `repeat` (a count; `-1` for ever) or `loop`, `startAt` (pre-filled elapsed time, so the first fire comes sooner), `args`, `callbackScope`, `paused` and a per-timer `timeScale`. A timer with zero delay and a repeat throws. API: `this.time.addEvent({ delay, callback, repeat, loop, startAt, timeScale, paused })`. Source: types/phaser.d.ts:104705-104741, 144556; skills/time-and-timers/SKILL.md:117-128, 473.
- **Timer handle** [common]: The returned `TimerEvent` reports progress and remaining time for the current repeat and overall, can be paused, removed (optionally firing one last time) and reset for reuse. API: `timer.getProgress()`, `timer.getOverallProgress()`, `timer.getRemainingSeconds()`, `timer.getRepeatCount()`, `timer.paused`, `timer.remove(dispatchCallback?)`, `timer.reset(config)`. Source: types/phaser.d.ts:145026-145109.
- **Timeline sequencer** [common]: A timeline is an array of timed entries; each entry is placed with `at` (ms from start), `in` (ms from now) or `from` (ms after the previous entry) and can run a callback, create a tween, play a sound, set properties on a target and emit a named event, guarded by an `if` function. It can repeat, pause, resume, stop and reset, starts paused, and pauses with its scene. API: `this.add.timeline([{ at, run, tween, sound, set, target, event, if, once, stop }]).play()`. Source: types/phaser.d.ts:104654-104702, 144698-144955; skills/time-and-timers/SKILL.md:59-72, 212-226.
- **Time scale, one per system** [common]: Speed is scaled per system, not for the game: the scene clock, a timer, a timeline, the tween manager and a single tween, the animation manager, the Arcade world and a sound's rate each have their own factor. `TimeStep` has no time scale member. API: `this.time.timeScale`, `timer.timeScale`, `timeline.timeScale`, `this.tweens.timeScale`, `this.anims.globalTimeScale`, `this.physics.world.timeScale`, `this.sound.rate`. Source: types/phaser.d.ts:144532, 145009, 144732, 147055-147061, 1376, 112824-112831, 131023; TimeStep members at 6660-7006.
- **Fixed step, for physics only** [common]: The Arcade world steps at a fixed rate (60 per second by default) independent of the render rate, reports how many steps ran in the last frame, and can be stepped by hand (`customUpdate: true` stops its automatic update). Matter has a runner config (`fps`, `delta`, `maxUpdates`, `maxFrameTime`, delta smoothing) and `autoUpdate: false` with a manual `step`. API: `physics: { arcade: { fps, fixedStep, customUpdate } }`, `this.physics.world.setFPS(120)`, `this.physics.world.step(deltaSeconds)`, `this.matter.step(delta)`, `this.matter.set60Hz()`. Source: types/phaser.d.ts:112806-112822, 113132-113166, 101352-101356, 101440, 102428-102460, 117016-117048.
- **Destroying the game** [niche]: `game.destroy(removeCanvas, noReturn)` flags the game for destruction on the next frame and emits `destroy`; `noReturn` also frees the core plugins, after which no other game can be created on the page. API: `game.destroy(true)`. Source: types/phaser.d.ts:5917-5930.

### physics

Phaser bundles two engines that do not interact: Arcade Physics (rectangles and circles only) and a customised Matter.js (https://phaser.io/oss/docs/phaser/concepts/physics).

- **Arcade world** [core]: A lightweight world of axis-aligned rectangles and circles with gravity, bounds and an R-tree broad phase, enabled in the game config or per scene (a scene's config is merged over the game's). API: `physics: { default: 'arcade', arcade: { gravity: { y: 300 } } }`, `this.physics.world`. Source: types/phaser.d.ts:112758-112920, 101348-101440; skills/physics-arcade/SKILL.md:316-340.
- **Dynamic bodies** [core]: A body has velocity, acceleration, drag (linear, or a damping multiplier with `useDamping`), its own gravity, bounce, friction, `maxVelocity` and `maxSpeed`, mass, and angular velocity, acceleration and drag. API: `sprite.setVelocity(x, y)`, `sprite.body.acceleration`, `body.setDrag()`, `body.setDamping(true)`, `body.setBounce()`, `body.setMaxSpeed()`. Source: types/phaser.d.ts:109726-110020, 110452-110699.
- **Static bodies** [core]: A static body never moves, has no velocity or gravity, and is indexed in its own R-tree; after its game object is moved or scaled the author calls `refreshBody()`. API: `this.physics.add.staticImage(x, y, key)`, `this.physics.add.staticGroup()`, `gameObject.refreshBody()`. Source: types/phaser.d.ts:112036; skills/physics-arcade/SKILL.md:105-112, 431.
- **Physics factory** [core]: One factory creates a sprite or image with a body, adds a body to an existing game object, or makes a body with no game object. API: `this.physics.add.sprite()`, `.image()`, `.staticSprite()`, `.existing(gameObject, isStatic?)`, `.body(x, y, w, h)`, `.staticBody(x, y, w, h)`. Source: types/phaser.d.ts:111628-111762.
- **Body shape and offset** [common]: A body is a rectangle of any size with an offset from its game object, or a circle; `syncBounds` keeps it the size of the texture. API: `body.setSize(w, h, center?)`, `body.setOffset(x, y)`, `body.setCircle(radius, offsetX?, offsetY?)`. Source: types/phaser.d.ts:110255-110290, 110145.
- **Physics groups** [core]: A group gives every member a dynamic (or static) body and applies default body settings when a member is added; group-wide setters change all members. API: `this.physics.add.group({ maxSize, collideWorldBounds, bounceX, velocityX, allowGravity })`, `group.setVelocity(x, y)`. Source: types/phaser.d.ts:111819, 112520, 101528-101742; skills/physics-arcade/SKILL.md:204-234.
- **Persistent colliders and overlaps** [core]: A collider is declared once and checked every physics step; either side can be a body, a game object, a group, a tilemap layer or an array of those. It returns a `Collider` with `active`, `name` and `destroy()`. `collider` separates the bodies, `overlap` only reports. API: `this.physics.add.collider(a, b, onCollide?, process?, context?)`, `this.physics.add.overlap(a, b, onOverlap?, process?, context?)`. Source: types/phaser.d.ts:111659-111670, 110829-110904, 101344; skills/physics-arcade/SKILL.md:168-202.
- **One-shot collision checks** [common]: The same checks can be called by hand in `update`, with no collider object. API: `this.physics.collide(a, b, cb?, process?, ctx?)`, `this.physics.overlap(a, b, cb?, process?, ctx?)`. Source: types/phaser.d.ts:107555-107583.
- **Process callback** [common]: The fourth argument of a collider is a function that returns a boolean; returning `false` skips the pair (the guide's example: an invincible player). API: `this.physics.add.collider(player, enemies, onHit, canCollide, this)`. Source: skills/physics-arcade/SKILL.md:188-192.
- **Triggers** [core]: An overlap is the trigger: it fires its callback without moving either body; a body made with `add.body` has no game object and can serve as a zone. API: `this.physics.add.overlap(player, coins, collect)`, `this.physics.add.body(x, y, w, h)`. Source: skills/physics-arcade/SKILL.md:137-139, 433.
- **Collision categories and masks** [common]: Bodies and groups carry a category bit and a mask of the categories they collide with; the plugin hands out up to 32 category values. API: `this.physics.nextCategory()`, `body.setCollisionCategory(cat)`, `body.setCollidesWith([catA, catB])`, `body.addCollidesWith()`, `body.willCollideWith()`. Source: types/phaser.d.ts:107544, 110159-110166, 110769-110818; skills/physics-arcade/SKILL.md:279-314.
- **Contact state** [core]: Each step a body records which sides touch another body (`touching`, `wasTouching`), which are blocked by a tile or the world bounds (`blocked`), and whether it is embedded; helpers answer the usual platformer questions. API: `body.touching.down`, `body.blocked.left`, `body.onFloor()`, `body.onWall()`, `body.onCeiling()`, `body.embedded`. Source: types/phaser.d.ts:110112-110140, 110325-110337.
- **Per-side collision** [common]: Collision can be switched off per side of a body (a one-way platform) and per edge of the world. API: `body.checkCollision.up = false`, `this.physics.world.setBoundsCollision(left, right, up, down)`. Source: types/phaser.d.ts:110123, 113061.
- **World bounds** [core]: The world has a bounds rectangle; a body can collide with it, bounce off it with its own factor, use a custom rectangle instead, and report the hit as an event. Objects can also wrap around the bounds. API: `this.physics.world.setBounds(x, y, w, h)`, `body.setCollideWorldBounds(true)`, `body.setBoundsRectangle(rect)`, `body.worldBounce`, `this.physics.world.wrap(object, padding?)`. Source: types/phaser.d.ts:113051, 110444, 110240, 109930, 113341-113348.
- **Immovable, pushable and slide factor** [common]: `immovable` bodies are never moved by a collision; a body with `pushable: false` reflects the velocity back to the other body; `slideFactor` sets how much velocity a pushed body keeps (0 stops it when the push ends, as in Sokoban). API: `body.setImmovable()`, `body.pushable = false`, `body.setSlideFactor(x, y)`. Source: types/phaser.d.ts:110042-110075, 110518.
- **Direct control** [niche]: A body moved by a tween or a path derives its velocity from its change of position, so it still collides. API: `body.setDirectControl(true)`. Source: types/phaser.d.ts:110168-110176, 110432.
- **Collision events** [common]: The world emits `collide`, `overlap`, `worldbounds`, `tilecollide`, `tileoverlap`, `worldstep`, `pause` and `resume`; the first three fire only for bodies that opt in. API: `body.onCollide = true; this.physics.world.on('collide', (go1, go2, body1, body2) => {})`. Source: types/phaser.d.ts:111523-111620, 109946-109956; skills/physics-arcade/SKILL.md:342-357.
- **Tile collisions** [core]: Tiles are marked as colliding by index, index range, property, exclusion or Tiled collision group; a collider between a sprite and the layer then separates them. A callback can be attached to a tile index or a tile area, and single tiles have per-side collision flags. API: `layer.setCollisionByProperty({ collides: true })`, `layer.setCollision(indexes)`, `layer.setCollisionBetween(a, b)`, `this.physics.add.collider(player, layer)`, `layer.setTileIndexCallback(indexes, cb, ctx)`, `tile.setCollision(left, right, up, down)`, `this.physics.collideTiles(sprite, tiles)`. Source: types/phaser.d.ts:142752-142828, 138065-138074, 137837-137861, 107607-107626, 101392.
- **Spatial queries** [common]: The plugin returns the bodies inside a rectangle or a circle, the closest or furthest body or game object to a point, and tests a point against one body. API: `this.physics.overlapRect(x, y, w, h, includeDynamic?, includeStatic?)`, `this.physics.overlapCirc(x, y, r)`, `this.physics.closest(source, targets?)`, `this.physics.furthest()`, `body.hitTest(x, y)`. Source: types/phaser.d.ts:107687-107703, 107773-107791, 110319.
- **Steering helpers** [common]: Helpers set a velocity or an acceleration toward a point or an object, and convert an angle and a speed to a velocity vector. API: `this.physics.moveTo(go, x, y, speed?, maxTime?)`, `this.physics.moveToObject()`, `this.physics.accelerateTo()`, `this.physics.velocityFromAngle(deg, speed)`, `this.physics.velocityFromRotation(rad, speed)`. Source: types/phaser.d.ts:107655-107671, 107719-107754.
- **Custom separation and tuning** [niche]: A body can skip the built-in separation on an axis and read the overlap amounts itself; the world exposes the overlap and tile bias and which axis is separated first. API: `body.customSeparateX`, `body.overlapX`, `arcade: { overlapBias, tileBias, forceX }`. Source: types/phaser.d.ts:110086-110107, 112838-112852.
- **Pause, enable and disable** [common]: The world pauses and resumes; one body can be taken out of the simulation and put back, optionally hiding its game object. API: `this.physics.pause()`, `this.physics.resume()`, `sprite.disableBody(true, true)`, `sprite.enableBody(reset, x, y, enableGameObject, showGameObject)`, `body.setEnable(false)`. Source: types/phaser.d.ts:107632-107638, 110706; skills/physics-arcade/SKILL.md:270-272.
- **Physics debug draw** [common]: A config flag draws bodies, static bodies and velocities with configurable colours; Matter has a larger set of toggles (collisions, sensors, joints, sleeping, axes). API: `arcade: { debug: true, debugShowVelocity }`, `matter: { debug: { showCollisions: true } }`, `this.physics.world.drawDebug`. Source: types/phaser.d.ts:101404-101428, 102232, 112862.
- **Matter world** [common]: A rigid-body world with gravity, solver iteration counts, optional sleeping and optional walls around the bounds. API: `physics: { default: 'matter', matter: { gravity: { y: 1 }, enableSleeping: true, setBounds: true } }`, `this.matter.world.setBounds()`, `this.matter.world.setGravity()`. Source: types/phaser.d.ts:102556-102668, 119881-119923.
- **Matter body shapes** [common]: Bodies are rectangles, circles, regular polygons, trapezoids, vertex lists (concave shapes are decomposed), or data from PhysicsEditor, SVG paths or JSON; corners can be chamfered and parts combined into a compound body. API: `this.matter.add.rectangle()`, `.circle()`, `.polygon()`, `.trapezoid()`, `.fromVertices()`, `.fromPhysicsEditor()`, `.fromSVG()`, `.fromJSON()`. Source: types/phaser.d.ts:114420-114573; skills/physics-matter/SKILL.md:249-263, 357-369.
- **Matter game objects** [common]: A sprite or image is created with a body, or a body is added to any game object; the object gains methods for velocity, force and thrust, bounce, three kinds of friction, mass and density, static and sensor flags. API: `this.matter.add.sprite(x, y, key, frame, { shape })`, `this.matter.add.gameObject(go, options)`, `sprite.applyForce()`, `sprite.thrust()`, `sprite.setFriction(value, air, static)`. Source: types/phaser.d.ts:114819-114870, 113534-114041.
- **Constraints** [common]: Two bodies, or one body and a world point, are joined by a constraint with a length and a stiffness (rigid joint, spring, pin). API: `this.matter.add.constraint(bodyA, bodyB, length, stiffness, options)` (aliases `joint`, `spring`), `this.matter.add.worldConstraint()`. Source: types/phaser.d.ts:114703-114773.
- **Composites** [niche]: Factories build stacks, pyramids, chains, meshes, soft bodies, a car and a Newton's cradle. API: `this.matter.add.stack()`, `.imageStack()`, `.pyramid()`, `.chain()`, `.mesh()`, `.softBody()`, `.car()`, `.newtonsCradle()`. Source: types/phaser.d.ts:114589-114679.
- **Sensors** [common]: A sensor body reports collisions and has no physical response. API: `{ isSensor: true }`, `sprite.setSensor(true)`. Source: types/phaser.d.ts:113752-113764.
- **Matter collision filtering** [common]: A body has a category, a mask and a group (same positive group always collides, same negative group never does). API: `this.matter.world.nextCategory()`, `this.matter.world.nextGroup(isNonColliding?)`, `sprite.setCollisionCategory()`, `sprite.setCollidesWith()`, `sprite.setCollisionGroup()`. Source: types/phaser.d.ts:120000-120007, 113555-113572; skills/physics-matter/SKILL.md:292-314.
- **Matter collision callbacks and events** [common]: Callbacks are set per body for the start, the duration and the end of a collision, or for one specific other body; the world emits `collisionstart`, `collisionactive` and `collisionend` with the pairs. API: `sprite.setOnCollide(cb)`, `.setOnCollideEnd(cb)`, `.setOnCollideActive(cb)`, `.setOnCollideWith(body, cb)`, `this.matter.world.on('collisionstart', (event, bodyA, bodyB) => {})`. Source: types/phaser.d.ts:113582-113613, 114225-114283.
- **Queries and raycast (Matter)** [common]: Matter answers which bodies contain a point, lie in a rectangle, cross a ray segment of a given width, or overlap a body. Arcade has no ray query; `Phaser.Geom.Intersects.GetLineToPolygon` and `GetRaysFromPointToPolygon` cast rays against polygons as plain geometry. API: `this.matter.intersectPoint(x, y)`, `.intersectRect()`, `.intersectRay(x1, y1, x2, y2, rayWidth?)`, `.intersectBody()`, `.overlap(target, bodies?, cb?)`, `.containsPoint()`. Source: types/phaser.d.ts:117065-117148, 79807, 79836; Arcade plugin members at 107475-107803.
- **Sleeping** [niche]: Bodies at rest stop being simulated; sleep can be forced, and start and end are events when opted in. API: `matter: { enableSleeping: true }`, `sprite.setToSleep()`, `sprite.setAwake()`, `sprite.setSleepEvents(true, true)`. Source: types/phaser.d.ts:113844-113887, 114351-114371.
- **Pointer constraint** [niche]: One call lets the pointer drag any Matter body; the world emits `dragstart`, `drag` and `dragend`. API: `this.matter.add.mouseSpring({ stiffness })` (alias `pointerConstraint`). Source: types/phaser.d.ts:114789-114803, 119577, 114293-114313.
- **Matter tile bodies** [common]: A tile layer's colliding tiles are converted to static bodies, using the collision shapes drawn in Tiled when present. ## Ideas worth taking

1. **One config object, with the same sub-objects accepted per scene.** `physics`, `loader` and `plugins` appear in the game config and again in a scene's config; for physics the docs state that the scene's config is merged over the game's. The author states defaults once and overrides them where a scene differs, without code. Source: types/phaser.d.ts:95718-95954, 103588-103628; skills/physics-arcade/SKILL.md:340.
2. **Queue in `preload`, use in `create`.** Load calls only queue; the loader starts by itself after `preload` and `create` is not called until every file is in. The author writes no promise, callback or ready check for the common case, and the same calls work later with an explicit `start()`. Source: skills/loading-assets/SKILL.md:30-62.
3. **A manifest that also unloads.** A pack file is data: sections of typed entries with their own base URL, path and key prefix. `removePack` walks the same data and removes every asset it lists, including nested packs, so loading and unloading a level are symmetric and neither is hand-written. Source: types/phaser.d.ts:91134-91158; skills/loading-assets/SKILL.md:270-292.
4. **Event names that carry the key.** `'filecomplete-image-hero'`, `'changedata-score'`, `'keydown-SPACE'`, `'animationcomplete-walk'`, `'addtexture-mapKey'`: a listener subscribes to exactly one thing and its handler has no filter. The generic event (`'changedata'`) stays available for code that wants all of them. Source: skills/events-system/SKILL.md:91-105; skills/data-manager/SKILL.md:255-265.
5. **A collision rule is an object declared once.** `this.physics.add.collider(a, b, onHit, canCollide)` is checked every step from then on and returns a handle with `active` and `destroy()`. Each side can be a sprite, a group, an array or a tile layer, so "bullets against enemies" and "player against the map" are the same call, and the optional fourth argument is the place for rules such as invincibility. Source: types/phaser.d.ts:111659-111670, 110829-110904, 101344; skills/physics-arcade/SKILL.md:168-202.
6. **A cutscene as an array literal.** A timeline entry has three ways to say when (`at` from the start, `in` from now, `from` the previous entry) and its actions are fields (`run`, `tween`, `sound`, `set`, `event`, guarded by `if`, ended by `stop`). The whole sequence can be read top to bottom, loops, pauses with its scene, and reports completion as an event. Source: types/phaser.d.ts:104654-104702; skills/time-and-timers/SKILL.md:212-226, 277-325.
7. **A timer handle that answers the HUD's questions.** `addEvent` returns an object with `getProgress()`, `getOverallProgress()`, `getRemainingSeconds()` and `getRepeatCount()`, and `startAt` pre-fills the first interval. A cooldown bar or a wave countdown reads the timer instead of keeping a second counter. Source: types/phaser.d.ts:145040-145102; skills/time-and-timers/SKILL.md:117-128, 171-183.
8. **The same observable store at three scopes.** A game object, a scene and the game each have a data manager with one API, and each emits `changedata-<key>` with the new and the previous value. A HUD scene listens to the registry and never holds a reference to the game scene. Source: skills/data-manager/SKILL.md:8, 166-180; https://phaser.io/oss/docs/phaser/concepts/scenes/cross-scene-communication ("Exchange Data via the Game Registry").
9. **Screen fitting is a declaration.** The author gives a design size, a mode (`FIT`, `ENVELOP`, `RESIZE`, `EXPAND`), a centring constant and optionally `MAX_ZOOM`, `min`, `max` and `snap`. One `resize` event carries the game size, the canvas size and the displayed size, so UI code has a single place to re-layout. Source: types/phaser.d.ts:128187-128259, 96283-96335, 128298; skills/scale-and-responsive/SKILL.md:52-92.
10. **Audio unlock with a visible state.** The manager resumes the audio context on the first gesture without any call from the game, and exposes `locked` and an `unlocked` event for the one case that needs them (starting music at boot). Pausing on blur is on by default. Source: skills/audio-and-sound/SKILL.md:369-386; types/phaser.d.ts:130815-130826.
11. **A seeded generator whose state is a string.** The game config takes a `seed`; the generator offers the calls games use (`between`, `pick`, `weightedPick`, `shuffle`, `sign`, `normal`), and `state()` both returns and restores a serialisable state, which the guide ties to saving and deterministic replay. Source: types/phaser.d.ts:93480-93636, 95766; skills/geometry-and-math/SKILL.md:354-377, 464.
12. **A hit area is a shape and a contains function.** `setInteractive(shape, containsFn)` takes any object and any `(shape, x, y, gameObject) => boolean`; the geometry classes ship matching `Contains` functions, the default is the texture frame, and pixel-perfect testing is one flag. The same call turns on hover, press, drag and drop, and the events come at three levels with `stopPropagation`. Source: types/phaser.d.ts:25957, 99767-99801; skills/input-keyboard-mouse-touch/references/REFERENCE.md:176-250.

## Traps

1. **A constant that was wrong for a major version.** `Math.TAU` was PI / 2 in v3; v4 changed it to PI * 2, removed `Math.PI2` and added `Math.PI_OVER_2`, so code that used the old name still runs with a different value. Source: changelog/v4/4.0/MIGRATION-GUIDE.md:305-313; changelog/v4/4.0/CHANGELOG-v4.0.0.md:252-254.
2. **A sequencer bolted onto the tween system.** The 3.60 changelog says the tween Timeline of 3.55 "never quite worked as intended"; it was removed from tweens and replaced by tween chains plus a separate `Time.Timeline` that sequences any action. Source: changelog/v3/3.60/Timeline.md:9.
3. **A config key that was never implemented.** The `resolution` game config property existed from early 3.x, broke zooming cameras, was forced to 1 in 3.16 and removed from the whole API in 3.50; the changelog describes it as "taunting developers and confusing new comers". v4's scale config still has no pixel-ratio option. Source: changelog/v3/3.50/CHANGELOG-v3.50.md:1236-1253; types/phaser.d.ts:96283-96335.
4. **A polling call that consumes what it reads.** `JustDown(key)` and `JustUp(key)` return `true` once and clear the flag, so a second caller in the same frame gets `false`; the docs tell authors to store the result. Source: skills/input-keyboard-mouse-touch/references/REFERENCE.md:326.
5. **Listeners that outlive the scene that added them.** Listeners added with `on()` to the input plugin, `game.events` or the registry are not removed when a scene restarts, so each restart adds a duplicate; the docs call it the most common source of bugs and require manual removal in the `shutdown` handler, with the same function reference and context. Source: skills/events-system/SKILL.md:371-382, 424-448; skills/data-manager/SKILL.md:344-356.
6. **The same setting in two places.** `width`, `height`, `zoom` and `parent` are accepted at the top of the config and under `scale`, and render options at the top and under `render`; the nested value wins. The Guide gives the reason as "For historical reasons" and the package's guide tells authors not to set both. Source: https://phaser.io/oss/docs/phaser/concepts/game ("Game configuration"); skills/game-setup-and-config/SKILL.md:48-52, 434.
7. **One audio API over backends that differ silently.** On HTML5 audio a spatial `source` config is ignored without an error, `pan` fires its event with no audible effect, and overlapping playback needs an `instances` count given at load time; on iOS and Safari `pan` is also inaudible. The docs advise against relying on these for gameplay cues. Source: skills/audio-and-sound/SKILL.md:46, 151, 392-400, 414-416.
8. **Time scale spread over systems, with one inverted.** There is no game-wide time scale: the clock, tweens, animations, the Arcade world and sounds each have one. A timeline's `timeScale` does not affect the tweens it creates, and the Arcade world's factor runs the other way (2.0 is half speed) from the clock's and the tweens' (2 is double speed). Source: skills/time-and-timers/SKILL.md:48, 475; types/phaser.d.ts:112824-112831, 145609-145615.
