# melonJS 18.2.2

_Source paths are relative to the root of the npm package `melonjs@18.2.2`. `build/index.d.ts` is the file `package.json` names as `types`; `build/index.js` is the bundle, which is not minified and keeps its JSDoc, so it is cited where a `.d.ts` file lost a comment or where behaviour had to be read. "Changelog" is https://raw.githubusercontent.com/melonjs/melonJS/master/packages/melonjs/CHANGELOG.md (the tarball lists a `CHANGELOG` file in `package.json` but does not contain one). "Upgrade guide" is https://github.com/melonjs/melonJS/wiki/Upgrade-Guide. The API reference at https://melonjs.github.io/melonJS/ and the wiki now describe 20.x (an `Application`-first API with WebGPU, 3D, physics adapters, audio sprites and more UI widgets); where they and the 18.2.2 package disagree, the package is followed and the difference is said._

## Shape

melonJS is one ES module, by convention imported as `me`; importing it boots the engine when the DOM is ready and creates one global `Application`, `me.game`, which owns the renderer, the default camera (`me.game.viewport`) and the root container (`me.game.world`). A game starts inside `me.device.onReady`, calls `me.video.init(width, height, options)` to create the canvas and a WebGL renderer with a Canvas fallback, and gives `me.loader.preload` a list of `{ name, type, src }` assets, which shows a loading stage until the list is loaded. Screens are `Stage` subclasses registered under numeric ids with `me.state.set` and switched with `me.state.change`; a stage builds its scene in `onResetEvent` and cleans up in `onDestroyEvent`, and the world container is emptied at each switch except for objects marked `isPersistent`. Everything on screen is a `Renderable` (a rectangle with a position, anchor, transform, tint, opacity, optional mask, optional shader and optional physics `Body`) held in a tree of `Container`s; a container sorts its children by z, updates only what a camera sees, and the frame is redrawn only when some `update(dt)` returned `true`. Game objects are written by subclassing `Sprite`, `Renderable` or `Container` and overriding `update(dt)`, `draw(renderer)` and `onCollision(response, other)`; there is no component system. Levels come from the Tiled editor: `me.level.load(name)` adds the map's tile and image layers to the world, creates each Tiled object by looking its name up in the object pool (`me.pool.register("name", Class)`) and passing its Tiled properties as `settings`, and turns the shapes of an object layer whose name contains "collision" into static bodies. Input is polled as named actions bound to keys with `bindKey`, and pointer buttons and gamepad buttons or axes are mapped onto those same keys. Audio (through Howler), tweens, particles, a `localStorage` save object, pause-aware timers, a typed event bus and three UI classes are built in. There is no networking; the debug panel, the decoder for compressed Tiled maps and the Spine runtime are separate plugin packages.

```js
import * as me from "https://cdn.jsdelivr.net/npm/melonjs/+esm";

me.device.onReady(function () {
  // initialize the display canvas once the device/browser is ready
  if (!me.video.init(1218, 562, { parent: "screen", scale: "auto" })) {
    alert("Your browser does not support HTML5 canvas.");
    return;
  }

  // set a gray background color
  me.game.world.backgroundColor.parseCSS("#202020");

  // add a font text display object
  me.game.world.addChild(
    new me.Text(609, 281, {
      font: "Arial",
      size: 160,
      fillStyle: "#FFFFFF",
      textBaseline: "middle",
      textAlign: "center",
      text: "Hello World !",
    })
  );
});
```

Source: README.md:165-188 of the package ("Basic Hello World Example"). The unpinned CDN URL in it now resolves to a 20.x build, where `me.video.init` no longer exists (upgrade guide, "19.x.x to 20.0.0").

## Features

### loop

- **Engine-owned frame loop** [core]: The author never writes a loop. `requestAnimationFrame` starts when the first stage becomes current; each frame emits `TICK`, on which the application runs its update and then its draw. API: `me.state.change(id)` (starts it), `me.event.TICK`. Source: build/index.js:22756-22774 (`_startRunLoop`, `_renderFrame`), build/index.js:27544-27547.
- **Fixed-step update** [core]: `Application.update` adds the frame's elapsed time to an accumulator and runs world updates in steps of `1000 / world.fps` ms (60 per second by default), with the backlog capped at ten steps. The `dt` an object receives in `update(dt)` is that step in milliseconds. API: `me.game.world.fps`, `Renderable.update(dt)`. Source: build/physics/world.d.ts:33-38, build/index.js:27604-27611, build/index.js:27629-27650.
- **Variable-step mode** [niche]: With `me.timer.interpolation = true` the application runs exactly one update per frame with the measured delta, and `me.timer.tick` becomes the ratio of that delta to the nominal step, which `Body.update` multiplies into forces and friction. API: `me.timer.interpolation`, `me.timer.tick`. Source: build/system/timer.d.ts:6-9, build/index.js:23092-23095, build/index.js:23249, build/index.js:12711-12741.
- **Frame-rate target** [niche]: `me.timer.maxfps` (60 by default) sets the target rate; the application then updates every `round(60 / maxfps)`-th animation frame, and `updateFrameRate()` re-reads both rates after a change. API: `me.timer.maxfps`, `me.game.updateFrameRate()`. Source: build/system/timer.d.ts:8, build/application/application.d.ts:122-127, build/index.js:27604-27611.
- **Redraw only when dirty** [core]: `update(dt)` returns `true` when the object changed; the frame is drawn only if some update returned `true` (or always, when `maxfps` is above `world.fps`). `repaint()` forces one redraw. API: `Renderable.update(dt): boolean`, `me.game.repaint()`. Source: build/renderable/renderable.d.ts:391-396, build/application/application.d.ts:133-136, build/index.js:27659; https://github.com/melonjs/melonJS/wiki/MelonJS-Core ("Draw Phase").
- **Frame hooks on the event bus** [common]: The bus emits `GAME_BEFORE_UPDATE`, `GAME_UPDATE` (not while paused), `GAME_AFTER_UPDATE`, `GAME_BEFORE_DRAW`, `GAME_AFTER_DRAW` and `WORLD_STEP`, so code outside the scene tree can run every frame. API: `me.event.on(me.event.GAME_UPDATE, fn)`. Source: build/system/event.d.ts:88-123, build/index.js:27639-27641.
- **Clock and delta** [core]: The timer gives the current timestamp, the time since the last frame and a measured frame rate; `me.game.lastUpdate` is offered for frame prediction in draw code. API: `me.timer.getTime()`, `me.timer.getDelta()`, `me.timer.fps`, `me.game.lastUpdate`. Source: build/system/timer.d.ts:71-81, build/system/timer.d.ts:7, build/application/application.d.ts:34-40.
- **Pause and resume** [core]: `me.state.pause()` keeps the frame loop running but skips every object whose `updateWhenPaused` is false and holds pauseable timers; `resume()` emits `STATE_RESUME` with the paused duration. Both take a flag that also pauses or resumes the music track. API: `me.state.pause(music?)`, `me.state.resume(music?)`, `me.state.isPaused()`, `Renderable.updateWhenPaused`. Source: build/state/state.d.ts:61-85, build/renderable/renderable.d.ts:100-105, build/index.js:14688-14690.
- **Stop and restart** [niche]: `me.state.stop()` cancels the animation-frame loop altogether, so nothing updates or draws, and `restart()` starts it again. API: `me.state.stop()`, `me.state.restart()`, `me.state.isRunning()`. Source: build/state/state.d.ts:56-80, build/index.js:22775-22778.
- **Pause on window blur** [common]: By default the application pauses, and pauses the music track, when the window loses focus and resumes when it gains it; flags switch each half off or stop the loop instead. API: `me.game.pauseOnBlur`, `me.game.resumeOnFocus`, `me.game.stopOnBlur`. Source: build/application/application.d.ts:57-74, build/index.js:27548-27563.
- **Timers on the game clock** [common]: `setTimeout` and `setInterval` take milliseconds, extra arguments for the callback and a `pauseable` flag, return an id, and are cancelled by id. In 18.2.2 `setInterval` stores `pauseable` as always true (build/index.js:23179); the changelog records the fix under 20.3.0. API: `me.timer.setTimeout(fn, delay, pauseable?, ...args)`, `me.timer.setInterval(...)`, `me.timer.clearTimeout(id)`, `me.timer.clearInterval(id)`. Source: build/system/timer.d.ts:33-70.
- **Deferred and throttled calls** [niche]: `defer` runs a function once the call stack is empty (the engine uses it for state switches and child removal), and `throttle` wraps a function so it runs at most once per interval. API: `me.utils.function.defer(fn, thisArg, ...args)`, `me.utils.function.throttle(fn, wait)`. Source: build/utils/function.d.ts:4-23.

No global time-scale setting was found: `timer.tick` is computed each frame, not set by the author (build/index.js:23249).

### scenes

- **Stage** [core]: A screen is a `Stage` subclass, or a `Stage` built from an object with the two callbacks. `onResetEvent(...args)` runs when the stage becomes current and is where a level is loaded and objects are added; `onDestroyEvent()` runs before the switch away. API: `class Play extends me.Stage { onResetEvent() {} onDestroyEvent() {} }`. Source: build/state/stage.d.ts:8-19, build/state/stage.d.ts:98-114.
- **State manager** [core]: Stages are registered under numeric ids and switched by id. Ten ids are predefined (`LOADING`, `MENU`, `READY`, `PLAY`, `GAMEOVER`, `GAME_END`, `SCORE`, `CREDITS`, `SETTINGS`, `DEFAULT`) and `USER` (100) is the base for the author's own. API: `me.state.set(id, stage, start?)`, `me.state.change(id)`, `me.state.current()`, `me.state.get(id)`, `me.state.isCurrent(id)`. Source: build/state/state.d.ts:5-55, build/state/state.d.ts:86-171.
- **Arguments to a stage** [common]: Extra arguments of `change` are passed to the stage's `onResetEvent`. In 18.2.2 the second positional parameter is `forceChange`, and the JSDoc example `me.state.change(me.state.PLAY, "level_1", 3)` puts `"level_1"` in that slot. API: `me.state.change(id, forceChange?, ...extraArgs)`. Source: build/state/state.d.ts:155-165, build/index.js:23031.
- **Deferred switch** [core]: A change is applied after the current frame's stack has unwound, unless `forceChange` is true; the old stage is destroyed, the new one reset, and `STATE_CHANGE` is emitted. API: `me.state.change(id, true)`. Source: build/index.js:22779-22796, build/index.js:23031-23060.
- **World reset between stages** [core]: Resetting a stage resets the application, which empties the world container; children with `isPersistent = true` (and their bodies) are kept. API: `renderable.isPersistent = true`. Source: build/renderable/renderable.d.ts:106-111, build/index.js:14108-14123, build/index.js:24814-24830; https://github.com/melonjs/melonJS/wiki/Adding-and-maintaining-your-game-objects ("Object Persistence").
- **Fade transition** [common]: One global transition can be set: the camera fades to a colour, the switch happens, and the camera fades back. `"fade"` is the only effect, and a state can opt out. API: `me.state.transition("fade", color, duration)`, `me.state.setTransition(id, enable)`. Source: build/state/state.d.ts:142-154, build/index.js:23036-23050.
- **Built-in loading stage** [core]: A default loading screen (logo and progress bar) is registered under `LOADING` at boot and shown by `loader.preload`; registering another stage under that id replaces it. API: `me.state.set(me.state.LOADING, new MyLoadingStage())`. Source: build/index.js:22798-22804, build/loader/loadingscreen.d.ts:1-26, build/loader/loader.d.ts:116-161.
- **Default stage** [niche]: A bare `Stage` under `DEFAULT` becomes current as soon as the video is initialised, so objects added to `me.game.world` are drawn before the game defines any stage (the hello-world example relies on it). API: `me.state.DEFAULT`. Source: build/state/state.d.ts:42-46, build/index.js:22798-22804.
- **Per-stage cameras and lights** [niche]: A stage holds a map of cameras drawn in order (marked experimental as a constructor setting), a map of 2D lights and an ambient light colour. API: `new me.Stage({ cameras: [...] })`, `stage.cameras`, `stage.lights`, `stage.ambientLight`. Source: build/state/stage.d.ts:9-61.
- **State events** [common]: The bus reports pause, resume, stop, restart, a state change and a stage reset. API: `me.event.STATE_PAUSE`, `STATE_RESUME`, `STATE_STOP`, `STATE_RESTART`, `STATE_CHANGE`, `STAGE_RESET`. Source: build/system/event.d.ts:35-68.
- **Levels inside one stage** [common]: A stage can swap Tiled levels without a state change: loading a level empties the target container, resets the game and adds the new map. API: `me.level.load(id)`, `me.level.next()`, `me.level.previous()`, `me.level.reload()`. Source: build/level/level.d.ts:13-123, build/index.js:20593-20610.

Parallel or stacked scenes: Nothing. One stage is current at a time (build/state/state.d.ts:136-141); a pause menu is built from objects with `updateWhenPaused`.

### entities

- **Renderable base class** [core]: Every game object extends `Renderable`, a rectangle with `pos` (an observable 3D vector whose `z` is the draw order), `anchorPoint`, `currentTransform`, `alpha`, `tint`, `name` and an optional `body`. Behaviour is added by overriding `update(dt)`, `draw(renderer)` and `onCollision`. API: `class Player extends me.Sprite { update(dt) { ...; return super.update(dt); } }`. Source: build/renderable/renderable.d.ts:15-74, build/index.js:12787-12795.
- **Container tree** [core]: A `Container` is a renderable that holds children; a child has one parent, and adding it elsewhere removes it from the first. Children are drawn inside the container's transform. API: `container.addChild(child, z?)`, `container.addChildAt(child, index)`, `child.ancestor`. Source: build/renderable/container.d.ts:23-34, build/renderable/container.d.ts:107-129, build/renderable/renderable.d.ts:155-160.
- **World root** [core]: `me.game.world` is the root container and the physics world; adding an object there puts it in the update and draw loop. API: `me.game.world.addChild(obj)`. Source: build/application/application.d.ts:23-27, build/physics/world.d.ts:5-9.
- **Lifecycle hooks** [core]: A child gets `onActivateEvent()` when it is added to a tree attached to the root, `onDeactivateEvent()` when removed, `onDestroyEvent()` before deletion, and `onVisibilityChange(inViewport)` when it enters or leaves a camera; a container gets `onChildChange(index)`. API: `onActivateEvent()`, `onDeactivateEvent()`, `onDestroyEvent()`, `onVisibilityChange`. Source: build/renderable/container.d.ts:115-116, build/renderable/container.d.ts:76-80, build/renderable/container.d.ts:245-246, build/renderable/renderable.d.ts:82-93, build/renderable/renderable.d.ts:463-467.
- **Deferred and immediate removal** [core]: `removeChild` waits until the update and draw stack has finished, so an object can remove itself during its own update; `removeChildNow` is immediate. A `keepalive` flag skips `destroy()`. API: `container.removeChild(child, keepalive?)`, `container.removeChildNow(child, keepalive?)`. Source: build/renderable/container.d.ts:244-258.
- **Finding objects** [common]: Children are found by `name` (string or RegExp, the Tiled object name), by any property value, by class, or by generated id; the search walks the tree and the docs say not to call it every frame. `name` is the only tag; there are no tag sets or groups. API: `container.getChildByName(name)`, `getChildByProp(prop, value)`, `getChildByType(Class)`, `getChildByGUID(guid)`, `getChildren()`, `forEach(fn)`. Source: build/renderable/container.d.ts:130-229, build/renderable/renderable.d.ts:75-81.
- **Bulk property set** [niche]: One call assigns a property on every child, optionally recursively. API: `container.setChildsProperty(prop, value, recursive?)`. Source: build/renderable/container.d.ts:259-265.
- **Activity flags** [core]: A renderable is updated only while a camera sees it unless `alwaysUpdate` is set, is skipped while the game is paused unless `updateWhenPaused` is set, and survives level and stage changes when `isPersistent` is set. API: `alwaysUpdate`, `updateWhenPaused`, `isPersistent`, `inViewport`. Source: build/renderable/renderable.d.ts:94-111, build/renderable/renderable.d.ts:297-303, build/index.js:14681-14710.
- **Kinematic flag** [common]: `isKinematic` is true by default on a `Renderable`; while true, collision detection and pointer events ignore the object. A container sets it false in its constructor. API: `renderable.isKinematic = false`. Source: build/renderable/renderable.d.ts:234-239, build/index.js:14100, build/index.js:24332.
- **Object pool and class registry** [core]: A class is registered under a name; `pull(name, ...args)` constructs it or, when recycling is on, reuses an instance by calling its `onResetEvent(...args)`. Removing a pooled child from a container pushes it back to the pool. The same registry is what Tiled object names are resolved against. API: `me.pool.register(name, Class, recycling?)`, `me.pool.pull(name, ...args)`, `me.pool.push(obj)`, `me.pool.exists(name)`, `me.pool.poolable(obj)`, `me.pool.purge()`, `me.pool.getInstanceCount()`. Source: build/system/legacy_pool.d.ts:17-114, build/index.js:14515; https://github.com/melonjs/melonJS/wiki/Adding-and-maintaining-your-game-objects ("The Object Pool").
- **Typed pools for engine values** [niche]: `getPool(key)` returns a typed pool with `get`, `release`, `purge`, `size` and `used` for vectors, matrices, colours, bounds, shapes, tweens and bitmap font data, so temporaries in update code need not allocate. `createPool` exists in the bundle but is not exported from the package entry in 18.2.2. API: `me.getPool("vector2d").get(x, y)`, `.release(v)`. Source: build/pool.d.ts:18-38, build/system/pool.d.ts:1-7, build/index.d.ts:41.
- **Collectable and Trigger** [common]: `Collectable` is a sprite with a static body of type `COLLECTABLE_OBJECT` that only tests against the player type. `Trigger` is a static region that loads another level, optionally through a camera fade, when the player type touches it. Both are registered in the pool, so a Tiled object named `Collectable` or `Trigger` creates one. API: `new me.Collectable(x, y, settings)`, `new me.Trigger(x, y, { to, duration, ... })`. Source: build/renderable/collectable.d.ts:1-16, build/renderable/trigger.d.ts:5-47, build/index.js:28285-28294, build/index.js:31239-31251.
- **Entity (deprecated)** [niche]: `Entity` pairs a body with a child renderable reached through `entity.renderable`. It is deprecated since 18.1.0 in favour of a `Sprite` or `Renderable` that owns its `Body`. API: `new me.Entity(x, y, settings)`. Source: build/renderable/entity/entity.d.ts:10-37, build/renderable/entity/entity.d.ts:152-195.
- **Aim and distance helpers** [niche]: A renderable can measure the angle and distance to another renderable or vector and rotate itself to face it. API: `renderable.angleTo(target)`, `distanceTo(target)`, `lookAt(target)`. Source: build/renderable/renderable.d.ts:349-366.

Components or an ECS, prefabs other than registered classes, state machines and AI helpers: Nothing.

### render

- **Two renderers behind one drawing API** [core]: `renderer: AUTO` tries WebGL (2, or 1 with `preferWebGL1`) and falls back to Canvas 2D; `WEBGL` and `CANVAS` force one, and a custom renderer class can be passed. Game code draws through the same methods on either. API: `me.video.init(w, h, { renderer: me.video.AUTO })`, `me.video.renderer`. Source: build/application/settings.d.ts:14-37, build/const.d.ts:1-13, build/video/video.d.ts:1-39, build/index.js:27265-27275.
- **Sprite** [core]: `Sprite` draws an image, a spritesheet frame, an atlas region, a canvas, a video element or a compressed texture, with flip, tint, anchor point and a source offset. The region can be changed at run time. API: `new me.Sprite(x, y, { image, framewidth, frameheight, region, tint, flipX, flipY, anchorPoint })`, `sprite.setRegion(region)`. Source: build/renderable/sprite.d.ts:7-64, build/renderable/sprite.d.ts:243-252.
- **Texture atlas** [core]: `TextureAtlas` reads TexturePacker, Free Texture Packer, ShoeBox and Aseprite JSON, multi-file atlases and fixed-cell spritesheets (with spacing and margin). Trimmed and rotated frames and per-frame pivots are handled; sprites and animations are created from region names. API: `new me.TextureAtlas(json, image)`, `atlas.createSpriteFromName(name, settings?, nineSlice?)`, `atlas.getRegion(name)`, `atlas.addRegion(name, x, y, w, h)`. Source: build/video/texture/atlas.d.ts:34-72, build/video/texture/atlas.d.ts:126-188, build/index.js:16117-16270.
- **Nine-slice sprite** [common]: `NineSliceSprite` stretches the centre and edges of an image to a given width and height while keeping the four corners unscaled; `insetx`/`insety` set the corner size (a quarter of the image by default). API: `new me.NineSliceSprite(x, y, { image, region, width, height, insetx, insety })`. Source: build/renderable/nineslicesprite.d.ts:6-53.
- **Tile layers** [core]: A Tiled tile layer is a `TMXLayer` renderable drawn by an orthogonal, isometric, hexagonal, staggered or oblique map renderer. It supports several tilesets, image-collection tilesets, flipped and rotated tiles, animated tiles, tile offsets, render order, and the layer's opacity, visibility, tint and blend mode. API: `me.level.load(name)`, `me.TMXLayer`, `me.TMXOrthogonalRenderer` (and `Isometric`, `Hexagonal`, `Staggered`). Source: build/level/tiled/TMXLayer.d.ts:1-86, build/level/tiled/TMXTileMap.d.ts:53-77, build/index.js:19531-19548, build/index.js:18332-18375.
- **Tile layer pre-rendering** [niche]: A static tile layer can be drawn once into an offscreen canvas instead of tile by tile every frame, for the whole world or per layer through a Tiled boolean property; layers with animated tiles are always drawn dynamically. API: `me.game.world.preRender = true`, Tiled layer property `preRender`. Source: build/physics/world.d.ts:45-53, build/index.js:18393-18406.
- **Tile queries and edits** [common]: A layer returns the tile at a world position or at a column and row, sets or clears a tile, and the map renderer converts between pixels and tile coordinates. A tile gives a sprite of itself, and a tileset gives a tile's Tiled properties. API: `layer.getTile(x, y)`, `layer.getTileId(x, y)`, `layer.cellAt(col, row)`, `layer.setTile(tile, x, y)`, `layer.clearTile(col, row)`, `layer.getRenderer().pixelToTileCoords(x, y)`, `tile.getRenderable()`, `tileset.getTileProperties(gid)`. Source: build/level/tiled/TMXLayer.d.ts:87-143, build/level/tiled/renderer/TMXRenderer.d.ts:30-45, build/level/tiled/TMXTile.d.ts:65-70, build/level/tiled/TMXTileset.d.ts:178-183.
- **Image layers and parallax** [common]: `ImageLayer` draws an image anchored to the viewport, repeated on x, y, both or neither, scrolling at a ratio of the camera movement. Tiled image layers map onto it, including `parallaxx`/`parallaxy`, `repeatx`/`repeaty` and the map's parallax origin. API: `new me.ImageLayer(x, y, { image, repeat, ratio, z })`. Source: build/renderable/imagelayer.d.ts:5-58, build/index.js:20197-20240.
- **Colour layer and backgrounds** [common]: `ColorLayer` fills the whole canvas with a colour at a z position; a container has a `backgroundColor` (set from the Tiled map's background colour on load) and the renderer has the colour used to clear each frame. API: `new me.ColorLayer(name, color, z)`, `me.game.world.backgroundColor`, `renderer.backgroundColor`. Source: build/renderable/colorlayer.d.ts:8-23, build/renderable/container.d.ts:89-97, build/video/renderer.d.ts:70-76, build/index.js:20389-20391.
- **System-font text** [core]: `Text` draws a CSS font with fill and stroke colours, stroke width, alignment, baseline, line height, word wrap and multi-line strings, and can be measured. It renders into its own offscreen canvas texture. API: `new me.Text(x, y, { font, size, fillStyle, strokeStyle, lineWidth, textAlign, textBaseline, lineHeight, wordWrapWidth, text })`, `text.setText(v)`, `text.setFont(font, size)`, `text.bold()`, `text.italic()`, `text.measureText(renderer, str)`. Source: build/renderable/text/text.d.ts:1-131.
- **Bitmap text** [common]: `BitmapText` draws from an AngelCode `.fnt` description and its image, loaded as a `binary` and an `image` asset under the same name, with scale, tint, alignment, baseline, line height, word wrap and kerning. API: `new me.BitmapText(x, y, { font, fontData, size, fillStyle, textAlign, text })`, `bitmapText.setText(v)`, `bitmapText.resize(scale)`, `bitmapText.measureText(str)`. Source: build/renderable/text/bitmaptext.d.ts:1-139, build/renderable/text/bitmaptextdata.d.ts:1-19, build/index.js:11363-11366.
- **Immediate-mode shapes** [core]: Inside `draw(renderer)` the author strokes or fills rectangles, rounded rectangles, ellipses, arcs, lines, polygons and points, or builds a path with `beginPath`, `moveTo`, `lineTo`, `rect`, `roundRect`, `closePath`. `stroke(shape)` and `fill(shape)` take the engine's geometry objects directly. ### physics

- **Built-in arcade physics, optional** [core]: The world steps a built-in solver unless the application setting `physic` is `"none"`; it is collision detection with push-out and simple velocity integration, not a rigid-body engine. API: `me.video.init(w, h, { physic: "builtin" | "none" })`, `me.game.world.physic`. Source: build/application/settings.d.ts:64-68, build/physics/world.d.ts:22-31; https://raw.githubusercontent.com/wiki/melonjs/melonJS/BuiltinAdapter-Quirks.md (section 10).
- **Body on a renderable** [core]: A `Body` is constructed with its owner and one or more shapes and assigned to `renderable.body`; the world picks it up when the renderable is added to the tree. API: `this.body = new me.Body(this, new me.Rect(0, 0, w, h))`, `world.addBody(body)`, `world.removeBody(body)`. Source: build/physics/body.d.ts:10-21, build/renderable/renderable.d.ts:38-74, build/physics/world.d.ts:69-82, build/index.js:14173-14178.
- **Collision shapes** [core]: A body holds several shapes: rectangles (stored as polygons), convex polygons, ellipses, lines, rounded rectangles and points. Shapes are added, removed, replaced by vertices and iterated; the body keeps a bounding box. API: `body.addShape(shape)`, `body.removeShape(shape)`, `body.getShape(i)`, `body.setVertices(points, i?)`, `body.forEach(fn)`, `body.getBounds()`. - **Shapes from PhysicsEditor** [niche]: A body loads its shapes and physics properties from a PhysicsEditor JSON export. API: `body.fromJSON(json, id?)`. Source: build/physics/body.d.ts:199-212.
- **Motion model** [core]: A body has `vel`, a `force` applied this step and then cleared, per-axis `friction` (a damping applied every step), `maxVel`, `mass`, `bounce`, and `gravityScale` or `ignoreGravity` against the world gravity (0, 0.98 by default). Values are per update step, not per second. API: `body.force.x = ...`, `body.vel`, `body.setMaxVelocity(x, y)`, `body.setFriction(x, y)`, `body.bounce`, `body.mass`, `body.gravityScale`, `me.game.world.gravity`. - **Static bodies** [core]: A static body never moves and is not tested against other static bodies. API: `body.setStatic(true)`, `body.isStatic`. Source: build/physics/body.d.ts:123-131, build/physics/body.d.ts:168-173, build/index.js:24332.
- **Falling and jumping flags** [common]: The body keeps `falling` (moving along gravity) and `jumping` flags for platformer logic. API: `body.falling`, `body.jumping`. Source: build/physics/body.d.ts:148-166, build/index.js:12739-12740.
- **Collision filtering** [core]: Each body has a `collisionType` bit and a `collisionMask`; two bodies are tested only when each type is in the other's mask. Seven types are predefined (`PLAYER_OBJECT`, `NPC_OBJECT`, `ENEMY_OBJECT`, `COLLECTABLE_OBJECT`, `ACTION_OBJECT`, `PROJECTILE_OBJECT`, `WORLD_SHAPE`), with `NO_OBJECT` and `ALL_OBJECT` as the empty and full masks, and the author adds more by shifting `USER`. API: `body.collisionType = me.collision.types.PLAYER_OBJECT`, `body.setCollisionMask(a | b)`, `me.collision.types.USER << n`. Source: build/physics/body.d.ts:42-61, build/physics/body.d.ts:236-258, build/index.js:12232-12296.
- **Custom pair rule** [niche]: The detector's `shouldCollide(a, b)` can be replaced for rules the bitmask cannot express. API: `me.game.world.detector.shouldCollide = fn`. Source: build/physics/detector.d.ts:17-24.
- **Broadphase quadtree** [core]: The world rebuilds a quadtree of its children on every update and uses it for collision candidates and for pointer hit tests; its node capacity and depth are settings, and it can be queried. API: `me.game.world.broadphase.retrieve(item)`, `me.collision.maxChildren`, `me.collision.maxDepth`, `me.QuadTree`. API: `response.a`, `response.b`, `response.overlap`, `response.overlapV`, `response.overlapN`, `response.aInB`, `response.indexShapeA`. Source: build/physics/response.d.ts:1-42, build/physics/sat.d.ts:1-48.

The base `Renderable.onCollision` returns `false`. API: `onCollision(response, other) { return true; }`, `body.respondToCollision(response)`. Source: build/renderable/renderable.d.ts:437-457, build/physics/body.d.ts:259-264, build/index.js:24381-24386, build/index.js:13223-13225; https://raw.githubusercontent.com/wiki/melonjs/melonJS/Frequently-Asked-Questions.md (item 8).

Source: changelog 18.1.0 ("Physics: collision response is now mass-proportional"), build/index.js:24387-24418; https://raw.githubusercontent.com/wiki/melonjs/melonJS/BuiltinAdapter-Quirks.md (section 10).
- **Ray cast** [common]: A `Line` is tested against all bodies and the intersecting renderables are returned in an array; no hit point, distance or normal is given. API: `me.collision.rayCast(line, result?)`. Source: build/physics/collision.d.ts:16-42, build/index.js:24454-24486.
- **Point and pair tests** [niche]: A body tells whether any of its shapes contains a point, and the detector tests two bodies on demand and fills a response. API: `body.contains(x, y)`, `me.game.world.detector.collides(bodyA, bodyB, response?)`. Source: build/physics/body.d.ts:283-297, build/physics/detector.d.ts:25-31.
- **World collision from Tiled** [core]: Objects on an object layer whose name contains "collision" become static bodies of type `WORLD_SHAPE`: rectangles, ellipses, polygons (concave ones are split into triangles), polylines (one line shape per segment), capsules and points. A `type` property set in Tiled reaches the game's `onCollision`, where platforms and slopes are handled. Tile layers themselves are not collidable. API: Tiled layer named `collision`; `other.type` in `onCollision`. Source: build/index.js:20435, build/index.js:20517-20520, build/index.js:19640-19720, build/level/tiled/constants.d.ts:6; https://github.com/melonjs/melonJS/wiki/How-to-define-world-collision-shapes-in-Tiled.

Source: build/renderable/trigger.d.ts:5-47, build/renderable/collectable.d.ts:1-16, build/index.js:30053-30058.

## Ideas worth taking

1. **Every device funnels into one action layer.** `bindKey(key, "jump", lock)` names an action, and `bindPointer(button, key)` and `bindGamepad(index, { type, code, threshold }, key)` map other devices onto the same key, so game code has one poll, `isKeyPressed("jump")`, for keyboard, mouse, touch and pad. Edge triggering is declared once at bind time instead of being tracked in every update. Source: build/input/keyboard.d.ts:38-51, build/input/pointerevent.d.ts:55-69, build/input/gamepad.d.ts:68-90.
2. **The collision callback's return value is the response.** `onCollision(response, other)` returns `true` for "solid, push me out" and `false` for "pass through", so detection, filtering and response are three separate steps and a pickup, a trigger, a one-way platform and a wall differ by one boolean decided per contact. Source: build/renderable/renderable.d.ts:437-457, build/index.js:24381-24386.
3. **Type bit and mask per body, with a reserved range for the game.** `body.collisionType` and `body.setCollisionMask(a | b)` filter pairs before any shape test, and `collision.types.USER << n` gives the author new types that compose with the built-in ones. The author writes one line per object and no pair table. Source: build/physics/body.d.ts:236-258, build/index.js:12232-12296.
4. **The map editor is the scene format.** A Tiled object's name selects a registered class, its custom properties arrive as the constructor's `settings` with their types already converted, its shape arrives as `settings.shapes`, and a layer named "collision" becomes the static world. The author writes no level-loading code, and designers add or tune objects without a programmer. Source: build/index.js:20427-20531, build/index.js:18017-18075, build/system/legacy_pool.d.ts:19-52.
5. **`update` returns whether anything changed, and that gates the draw.** A menu, a paused game or a turn-based board that reports no change is not redrawn at all, and the author gets this by returning a boolean, not by managing invalidation. Source: build/renderable/renderable.d.ts:391-396, build/index.js:27659; https://github.com/melonjs/melonJS/wiki/MelonJS-Core.
6. **Four booleans on the base class cover the usual lifetime questions.** `alwaysUpdate` (keep running off screen), `updateWhenPaused` (pause menu), `isPersistent` (survive level and stage changes) and `floating` (screen space, HUD) replace code the author would otherwise write in each object and each stage. Source: build/renderable/renderable.d.ts:94-127.
7. **A shader effect is one function.** `new ShaderEffect(renderer, "vec4 apply(vec4 color, vec2 uv) { ... }")` asks only for the colour transform and any uniforms; the vertex shader, sampling and attribute plumbing are generated, and on the Canvas renderer the effect is a no-op, not an error. Source: build/video/webgl/shadereffect.d.ts:1-49.
8. **One vocabulary of shapes for drawing, masking, hit-testing and physics.** `Rect`, `Ellipse`, `Polygon`, `Line` and `RoundRect` are accepted by `renderer.fill(shape)`, by `renderable.mask`, by `registerPointerEvent(type, shape, fn)` and by `body.addShape(shape)`, and the renderer's own calls mirror the Canvas 2D context on WebGL too. An author learns one set of objects and one drawing API. Source: build/video/renderer.d.ts:188-198, build/renderable/renderable.d.ts:161-182, build/input/pointerevent.d.ts:94-112, build/physics/body.d.ts:174-185.
9. **Scaling is a named preset.** `scaleMethod: "fit" | "fill-min" | "fill-max" | "flex" | "flex-width" | "flex-height" | "stretch"` with `scale: "auto"` covers letterboxing and resolution-growing layouts in one option, with `scaleTarget` and CSS `max-width` as the only other knobs. Source: build/application/scaleMethods.d.ts:1-43, build/index.js:27305-27351.
10. **An asset's `src` can be a fallback chain.** `src: ["t.astc.ktx", "t.dds", "t.png"]` lets the loader pick the first source the device can load, so format negotiation lives in the manifest and the rest of the game uses one name. Source: build/loader/loader.d.ts:51-53, build/loader/parsers/image.d.ts:9-20.
11. **Event constants carry their listener's type.** The `Events` interface maps each constant to a signature, so `event.on(event.LOADER_PROGRESS, (progress, asset) => ...)` and `event.on(event.KEYDOWN, (action, keyCode, edge) => ...)` are checked by the compiler without the author writing a type. Source: build/system/event.d.ts:294-366.
12. **Saved values are declared once and then are plain properties.** `me.save.add({ score: 0, lives: 3 })` states the keys and their defaults in one place; after that `me.save.score = 1000` persists, with no explicit save or load call to forget. Source: build/index.js:6751-6787.

## Traps

1. **A wrapper object that owns a body and a child renderable.** `Entity` is deprecated since 18.1.0: its own anchor point and draw pipeline differed from every other renderable, which caused lasting alignment bugs, and every visual call had to go through `entity.renderable`. The replacement is a `Sprite` or `Renderable` that holds its `Body` directly. Source: build/renderable/entity/entity.d.ts:10-37; changelog 18.1.0.
2. **A string-keyed pool that is also the class registry and the recycler.** `pool.register(name, Class, true)` plus an `onResetEvent` contract made removal from a container silently recycle the object, and the engine's own `pool.pull("me.Sprite")` lookups never pooled anything. The changelog deprecates the legacy pool in 20.9.0 in favour of constructors, typed `getPool()` pools and an exported `createPool`, and stops removal from recycling registered classes. Source: build/system/legacy_pool.d.ts:17-52, build/index.js:14515; changelog 20.9.0.
3. **Settings as assignable module exports.** `loader.onload`, `loader.onProgress` and `loader.onError` are `export let` bindings, deprecated in 18.2.0; the changelog (20.3.0) removes them and states that assigning to them through the module namespace threw a `TypeError`, so the documented callback API could never be used. The same release adds `input.setPreventDefault()` because assigning `input.preventDefault` had no effect. Source: build/loader/loader.d.ts:322-357, build/input/input.d.ts:4-8; changelog 20.3.0.
4. **A pre-built global application and a global init call.** `me.video.init()`, `me.video.renderer`, `me.video.getParent()` and `me.device.onReady()` are deprecated in 18.3.0 in favour of `new Application(...)` held by the author, and 20.0.0 removes the `video` calls and the pre-created `me.game` application; the 18.3.0 changelog also records that the shared default settings object was mutated by each init. Source: build/index.d.ts:55-60, build/video/video.d.ts:1-17; upgrade guide ("18.2.x to 18.3.x", "19.x.x to 20.0.0"); changelog 18.3.0.
5. **A per-frame collision callback with a pair-fixed response.** The legacy `onCollision` fires twice per frame per side for two dynamic bodies, `response.a` is not always the receiver, "return false" doubles as the sensor flag, and an object with no handler is implicitly non-solid. The wiki adds `onCollisionStart`/`onCollisionActive`/`onCollisionEnd` with a receiver-relative response and an explicit `isSensor` in 19.5 and says they are not drop-in replacements. Source: https://raw.githubusercontent.com/wiki/melonjs/melonJS/Migrating-to-the-Physics-Adapter-API.md; https://raw.githubusercontent.com/wiki/melonjs/melonJS/BuiltinAdapter-Quirks.md (section 9).
6. **A body configured by setters and public vectors.** `new Body(this, shape)` followed by `setMaxVelocity`, `setFriction` and direct writes to `body.vel` and `body.force` ties game code to the built-in solver; the wiki replaces it with a declarative `bodyDef` and body methods in 19.5. The wiki also says that `friction` is really per-step damping (renamed `frictionAir`), and the changelog (20.7.0) records that collision shapes ignored the renderable's `anchorPoint` until then, so hitboxes sat where the object was not drawn. Source: https://raw.githubusercontent.com/wiki/melonjs/melonJS/Migrating-to-the-Physics-Adapter-API.md; https://raw.githubusercontent.com/wiki/melonjs/melonJS/BuiltinAdapter-Quirks.md (section 5); changelog 20.7.0.
7. **Helpers that add themselves to the global world, and methods with two modes.** In 18.2.2 a started `Tween` adds itself to `game.world` as a child (`Container.addChild` accepts one) and `Text.draw(renderer, text, x, y)` can draw without a parent. 19.0.0 makes tweens event-driven with no world membership and removes the standalone `draw` form (deprecated since 10.6.0), both as breaking changes. Source: build/renderable/container.d.ts:117-121, build/index.js:11836, build/renderable/text/text.d.ts:132-139; upgrade guide ("18.x.x to 19.0.0").
8. **Two input tables sharing one numeric code space.** `GAMEPAD.AXES.LX` and `GAMEPAD.BUTTONS.FACE_1` are both 0, and `unbindGamepad(index, button)` only reached the button table, so an axis could not be unbound; the axis `threshold` was also added to the deadzone, not used in its place. The changelog (20.9.0) adds a `type` argument and corrects the documentation. Source: build/input/gamepad.d.ts:20-66, build/input/gamepad.d.ts:91-99; changelog 20.9.0.
