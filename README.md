# arcadekit

`arcadekit` is one package of reusable primitives for building browser games with **Effect 4**, **Foldkit** and **Three.js**. This repository holds it, plus two demo games built on it, each with its genre's code inside it: a survivors-like and a push-puzzle (Sokoban-like).

**Status: alpha.** Interfaces, stored data and the package's entries change whenever that improves the code, with no compatibility layers or migrations. Each release's changelog says what broke.

**Docs:** [arcadekit.dev](https://arcadekit.dev): getting started, the concepts, a guide for each task, and a reference page for each entry of the package. The site is built from [`docs/`](docs) and the entries' READMEs.

```bash
pnpm install
pnpm dev         # play the survivors demo, co-op included, under `alchemy dev` (http://localhost:1337)
pnpm dev:puzzle  # play the push-puzzle demo
pnpm dev:docs    # read the docs site as you write it (Astro's dev server)
pnpm test        # all tests
pnpm test:browsers  # the long determinism run in Chromium, Firefox and WebKit
pnpm typecheck   # every package, each against its own rules
pnpm check       # lint + format check (Ultracite: Oxlint + Oxfmt)
pnpm fix         # apply lint fixes and formatting
pnpm build       # typecheck + production build of both demos and the docs site
pnpm build:docs  # build the docs site alone; it fails on a dead link in a page
pnpm build:packages  # build the arcadekit package to dist/ (dev, test and typecheck don't need it)
pnpm lint:packages   # publint and arethetypeswrong on the packed arcadekit package
pnpm smoke       # build, pack and install the kit outside the workspace, then typecheck and build a game with it
```

`pnpm fix` applies Oxlint's autofixes. Run the tests afterwards: a few rules that don't fit this codebase are turned off in `oxlint.config.ts`, each with the reason.

## Install

The kit publishes to npm as one package, `arcadekit`, whose entries you import by subpath (`arcadekit/core`, `arcadekit/game/browser`, ...). The demo apps don't publish: copy from them. Install it with the peer libraries the entries you use need:

```bash
pnpm add arcadekit effect three foldkit @effect/platform-browser
pnpm add -D @types/three
```

- Peer libraries: `effect` (~4.1) is required. The rest are optional: `three` (^0.187) and `@types/three` for `arcadekit/render-three`, `foldkit` (~0.170) for `arcadekit/foldkit`, `@effect/platform-browser` (~4.1) for `arcadekit/save/browser` and Foldkit, and `@cloudflare/workers-types` (^5) for `arcadekit/net/worker`'s types. They are peers so your app has one copy of each: Effect services and Three.js `instanceof` checks need that.
- The package is ESM only, with no root export. It needs TypeScript 5.4 or later, and Node 22 or later for tooling. TypeScript 5.4 to 5.6 need `skipLibCheck`, since Effect 4.1's own type files need 5.7.
- Each entry's README (linked in the table below) has an example, and [the package's README](packages/arcadekit/README.md) lists all twenty entries.

**Versions.** While below 1.0, a minor version (0.3 to 0.4) may break the interface, and its changelog says how; a patch doesn't. Use a `~` range to take only patches.

**Before 0.3.0** the kit was nine packages, `@arcadekit/core` to `@arcadekit/foldkit`. In 0.3.0 each became the entry of the same name, with the same exports: `@arcadekit/net/browser` became `arcadekit/net/browser`. One of them has no entry any more: `@arcadekit/runtime`. What a declared game still uses of it is `arcadekit/game`'s, and [the changelog](packages/arcadekit/CHANGELOG.md) has the table from each of its names.

## Entries and demos

The first nine rows are the entries of the `arcadekit` package ([`packages/arcadekit`](packages/arcadekit)); each also has the `./browser` and other subpaths its row names. Lower layers have fewer dependencies, and nothing depends on a layer above it.

| Package or entry | What it gives you | Depends on |
| --- | --- | --- |
| [`arcadekit/core`](packages/arcadekit/src/core) | The data a step keeps and the arithmetic it calls, each module a namespace in Effect's shape. `FixedStepClock`, the seeded `Rng` (with `Rng.pickDistinct`, several items without repeats), `EntityPool` (struct-of-arrays entities, and `EntityPool.makeIdentified`, whose entities keep stable ids, with `EntityPool.visit` over a pool's live fields), `SpatialGrid`, `EventBuffer`. `Ring`, a fixed ring of records in typed arrays that a step pushes to, and `RingReader`, with which a view takes the records written since it last looked. `TileMap`, a level's grid of static cells in typed arrays, with a cell's neighbour on each `TileMap.Side` and a flood fill. `Layout`, what each record of those holds. `StateHash`, which folds the numbers a game lists from its state into 32 bits. `ExactMath`, the exact math a step calls: `hypot2`, `sin`, `cos` and `powInt` in place of the `Math` functions each engine approximates, with `clamp`, `lerp` and `hashCell` (two whole numbers to an unsigned 32-bit one); `Point2`, which `clampLength` and `moveToward` write into. `Timer`, timers as numbers in the state (`countDown`, `takeWhole`), and `Tween`, tweens as functions of time (`progress` and the eases `easeIn`, `easeOut`, `easeOutCubic` and `smoothstep`) | Effect, for its module shape (not the DOM) |
| [`arcadekit/input`](packages/arcadekit/src/input) | `InputController`, a namespace in Effect's shape: keyboard, gamepad, touch-drag and swipes read as a game's named axes and buttons (`InputController.make`, `axis`, `isDown`, `wasPressed`), with `InputController.moveAxes`, a pair of movement axes on every device | DOM, Effect for its module shape |
| [`arcadekit/content`](packages/arcadekit/src/content) | `Content` and `Asset`: a game's content files, checked by an Effect Schema, and what the app loads once for it, such as a sprite sheet, each declared as a class that keys its own service (`.layer`, `.load`); the first success is kept and a failed load can be retried. A content's `read(source)` reads and checks the files once and keeps nothing, for a test. `ContentSource`, a namespace in Effect's shape: where a content's files come from (`ContentSource.fromRecord` for a test's files, `ContentSource.make` for a source of the app's own), and the `ContentSource.ContentError` every source and load fails with. `FetchContentSource.fromUrl` is in `arcadekit/content/browser` | Effect |
| [`arcadekit/save`](packages/arcadekit/src/save) | `Save`, a declaration: a game's records by id under one versioned key, merged with the stored save on each write, with a corrupt save backed up and storage failures logged rather than raised. `Setting`, a declaration: one value kept apart from the save under its own key, where the last write wins, such as the audio settings. What both services give is `Stored`, a namespace in Effect's shape: a `read` and a `write`, each traced under the declared name. `BrowserSaveStorage.layer` (localStorage, or memory if the browser refuses) is in `arcadekit/save/browser` | Effect |
| [`arcadekit/audio`](packages/arcadekit/src/audio) | `AudioSystem`, the sound a game's views and app play: one-shots with pitch and volume jitter, a voice cap and minimum gap per sound, `setLoop` for a loop held from state, music with crossfades, master, sfx and music buses, mute and ducking. Silent until the first gesture and while the tab is hidden. A namespace in Effect's shape: `AudioSystem.AudioSystem` is also the service's key, with `AudioSystem.layerSilent` and `AudioSystem.make` for a test. `AudioMixer`, the mixer behind the browser's, which plays into whatever output it is unlocked with. `CueTable`, a declaration: a genre's cues, for the app to say which of its sounds each plays. The audio settings' Schema and default (`AudioSettings.AudioSettings`, `AudioSettings.defaults`: volumes and mute, which an app keeps with a `Setting`). `BrowserAudioSystem.layer` (Web Audio) is in `arcadekit/audio/browser` | Effect |
| [`arcadekit/render-three`](packages/arcadekit/src/render-three) | Three.js drawing, each module a namespace in Effect's shape: loading a sheet is an Effect, drawing is plain. `Stage` (a renderer, a scene and a perspective, orthographic or pixel camera that resize with their container; `Stage.dispose` and `Stage.disposeObject` skip textures marked with `Stage.keepTexture`, such as a sheet's), `MeshInstances` (copies of one mesh in one draw call, each with a matrix, a color and the attributes its view declares for a shader of its own), `Camera` (`Camera.follow`, `Camera.orbit` and `Camera.fit` place a 3D stage's camera over the ground). Pixel-art sprites: `SpriteSheet` (`SpriteSheet.fromUrl` loads an Aseprite PNG + JSON as an Effect, failing with `SpriteSheet.SpriteSheetError`; `SpriteSheet.resolveTags` picks each tag a view draws, with its fallbacks, and lists the ones the sheet lacks; `SpriteSheet.frameAt` gives a tag's frame at a time), `InstancedSprites` (many sprites from one sheet in one draw call, pushed each frame into a batch that grows, each with frame, flip, tint, flash, lift and layer, rounded to sprite pixels or to screen pixels; lower on screen draws in front), `TileLayer` (a grid of cells drawn from a sheet's frames in one draw call, only the cells on screen, from a function of the cell), `Gait` (whether a character a view draws is walking, from the positions it is shown at), `PixelCamera` (straight down, whole screen pixels per sprite pixel, snapped; `PixelCamera.groundOnScreen` gives the rectangle of ground it shows). In `arcadekit/render-three/testing`, for a view's tests: `TestSpriteSheet` (a sheet with no image), `DrawnSprites` (what a batch or a tile layer shows), and `Png`, whose `Png.size` and `Png.framesWithSoftAlpha` check a sheet's PNG | Three.js, Effect (Node for `render-three/testing`) |
| [`arcadekit/game`](packages/arcadekit/src/game) | A game as declarations: `Game.Event` (what a run reports), `Game.Command` (what a player decides; applied at the start of the next step), `Game.Rejection` (why the rules may refuse one) and `Game.Simulation` (the DOM-free rules: `create`, `step`, `apply`, `sample`), with `Game.makeLoop`, the loop that steps one anywhere. `Game.PlayerInputs` declares the step input of a simulation several players can play (each player's input by slot, plus the slots leaving), and `Game.soloInput` fills it for one player. In `arcadekit/game/browser`: `Game.Engine`, a simulation with the `view` and `input` that draw it and read its input and what they `uses`; the class is the engine service's key and its `layer` provides it, and its `attach` steps and draws the run on animation frames (`Game.Frames`). `Game.combineViews` makes one view of several, such as a drawing view and a sound view. In `arcadekit/game/scenario`: scenarios that check a simulation (given a run, after these steps, it reported these events). In `arcadekit/game/testing`: `ManualFrames`, the frames a test drives an engine on | Effect, core |
| [`arcadekit/foldkit`](packages/arcadekit/src/foldkit) | A game's engine in a Foldkit app, each module a namespace in Effect's shape: `Viewport.make` (the element an engine draws into), `EngineEntry.make` (the Subscription entry that runs the engine there and turns its events into Messages; with `onError`, the Message sent if the engine fails to load or to attach, or crashes), `KeyPresses.make` (the app's own keys as Messages) and `ShortcutPresses.make` (a key that works on any screen, ignoring modifiers and text fields) | Effect, Foldkit, game |
| [`arcadekit/net`](packages/arcadekit/src/net) | Lockstep multiplayer: `LockstepSession.host` / `LockstepSession.join` run one declared `Game.Simulation` on 2 to 4 peers, stepping each step once the host has confirmed every player's input for it, comparing state hashes and removing a player who stalls the run. The simulation's step input is a `Game.PlayerInputs`: the session sends each player's own input, as its one-player Schema encodes it, and puts each at its slot. A player's command (`session.send`) rides that player's next step, so every peer's rules take or refuse it at one step, and its sender hears which. `arcadekit/net/browser` has the `Coop` declaration, a game's engine played by several players from a lobby: its class is the key of the Co-op client, which runs the lobby, the run and its drawing for one player, over the app's rooms (`CoopRooms`, from `CoopRooms.layer`), and its `match` turns what a seat reports into an app's Messages. `arcadekit/net/testing` has what a game's own tests need: `FakeCoopRooms`, `ManualTicker`, `PageTimers` (the Clock and scheduler of a test on fake timers) and a small `TestGame`. `ScopedLockstepSession.host` / `ScopedLockstepSession.join` make the same session owned by a scope, run on Effect's `Clock` or a `Ticker` until it fails with its `LockstepError`. They talk through a `Transport`; a `MemoryNetwork` is the in-memory one for tests, with seeded latency, jitter and loss. In `arcadekit/net/browser`: `SignallingRoom.host` / `SignallingRoom.join`, the signalling client that turns a join code into WebRTC links (host to each guest), and `RtcTransport.fromLinks`, the WebRTC `Transport` over them. `arcadekit/net/signalling` is the protocol they speak with a signalling worker, as Effect Schemas (`ClientMessage`, `ServerMessage`, `Signal`, `JoinCode`). [`arcadekit/net/worker`](packages/arcadekit/src/net/worker) is that signalling worker, for Cloudflare: `SignallingWorker.room` (the Durable Object class of a room, with its room size) and `SignallingWorker.make` (the Worker's `fetch`), so an app's Worker is a few lines | Effect, core, game (Workers types for `net/worker`) |
| [`examples/survivor-demo`](examples/survivor-demo) | The survivors demo. Its genre, in `src/survivors/`, as declarations: its events (`Hud`, `LeveledUp`, `HeroLeft`, `RunEnded`), its upgrade pick (the command `ChooseUpgrade`, refused with `OfferClosed` or `NoSuchChoice`), its co-op pause (`HoldPause`, refused with `NotPlaying`), its rules (`Survivors`, for one hero or several), its content (`SurvivorsContent`) and, in `src/survivors/browser/`, its engine for one player (`SurvivorsEngine`: a pixel-art sprite view, a sound view and its input), which uses the app's sheet (`SurvivorsSheet`), its sounds for the genre's cue table (`SurvivorsCueTable`) and its audio. Cue counters for sound in a `World.Arena`'s `cues`, played by the engine's sound view. Co-op for 2 to 4 players: one hero per player, shared team XP, a level-up that waits for every player's pick. It is declared in `src/survivors/browser/` as `SurvivorsCoop`, a `Coop` made from `SurvivorsEngine`, which `arcadekit/net/browser`'s Co-op client runs in lockstep: the run steps the same `Survivors`, whose step input is `World.Input`, a `Game.PlayerInputs` of `Hero.Input` (`Game.soloInput` fills it for one player, and a lockstep session from each confirmed step). A co-op pick is the same `ChooseUpgrade` one player sends, and the pause a player holds for everyone is `HoldPause`: each rides its sender's step to every peer. The HUD says which heroes are choosing and which hold the pause; the engine's view reads the local player's slot on every frame, for one player and in co-op, and draws from the same sheet. Its app, in `src/app/`: JSON content, Foldkit screens, a save of each hero's best run, sound and music with a volume panel, and co-op for 2 to 4 players: a lobby by join code, then a lockstep run over WebRTC. Deployed with Alchemy as one Cloudflare Worker that serves the site and is the kit's [signalling worker](packages/arcadekit/src/net/worker) (a Durable Object per join code) | audio, content, save, foldkit, net, render-three, game, input, core (Alchemy and Workers types to run, deploy and check its Worker) |
| [`examples/push-puzzle-demo`](examples/push-puzzle-demo) | The push-puzzle demo. Its genre, in `src/push-puzzle/`, as declarations: its events (`Hud`, `LevelSolved`), its rules (`PushPuzzle`: a turn-based simulation with undo, holes and cue counters), its levels (`PushPuzzleContent`) and, in `src/push-puzzle/browser/`, its engine (`PushPuzzleEngine`: a pixel-art sprite view, a sound view and its input), which uses the app's sheet (`PushPuzzleSheet`, with the tags in `Art.tags`), its sounds for the genre's cue table (`PushPuzzleCueTable`) and its audio. Its other modules are namespaces: a run's state and step (`World`, whose state is `World.Puzzle`), a level read from its text (`Level`) and the levels' Schema (`PuzzleContent`). Its app, in `src/app/`: three levels, level select, HUD, solved screen, a save of solved levels, sound with a volume panel, and pixel art from a sprite sheet it loads at startup | audio, content, save, foldkit, render-three, game, input, core |
| [`website`](website) | The docs site, [arcadekit.dev](https://arcadekit.dev): the pages in [`docs/`](docs), each entry's README as its reference page, and the glossary, read where they are, so nothing is copied. A new page is listed as soon as it exists, and a dead link in one fails `pnpm build`. Deployed with Alchemy as static files on Cloudflare | Astro and Starlight (Alchemy to deploy) |

The typecheck sets which environment each entry may use. `packages/arcadekit/tsconfig.root.json` compiles `core` and the root entries of `content`, `save`, `audio`, `game` (with `game/scenario`) and `net` (and `net/signalling`) without DOM types, so browser code there fails the typecheck; only their `./browser` entries may use the DOM. `tsconfig.worker.json` compiles `net/worker` with Cloudflare's Workers types and no DOM, and `tsconfig.json` leaves it out, so Workers globals reach no other entry. `tsconfig.node.json` compiles `render-three/testing`, which only a test or a script imports, with Node's types beside the DOM's, and `tsconfig.json` leaves it out too, so Node's built-ins reach no other entry. Each demo checks its genre's rules the same way: `tsconfig.rules.json` compiles `src/<genre>/index.ts` without DOM types. That keeps the simulation runnable in a Web Worker or on a game server.

## Making a new game

Copy the demo app closest to your game (`examples/survivor-demo` or `examples/push-puzzle-demo`), then change the JSON in `public/content/` and the screens in `src/app/`. For a new genre, [Making a game](docs/making-a-game.md) walks through its declarations and the app around them, as the push-puzzle demo writes them.

## The survivors demo

Content lives in `examples/survivor-demo/public/content/`: rules, heroes, enemies, weapons (`bolt` or `aura`, with an optional `sound`: the id of a bolt's shot sound), passive upgrades and the wave schedule. Heroes, enemies and weapons have an optional `sprite`: an enemy's or bolt's tag in the sprite sheet (`slime/move`, `bolt/arc`), or a hero's tag prefix (`spark` for `spark/walk`, `spark/idle` and `spark/down`); without one, or if the sheet lacks it, a generic sprite is drawn in the content's `color`. It's checked against `src/survivors/game-content.ts` at load and by `examples/survivor-demo/test/content.test.ts`.

Hero select shows each hero's best time and most kills. The save keeps them in localStorage under `arcadekit/survivors/save`. `src/app/hero-records.ts` says what a hero's record holds, `src/app/save.ts` declares the save and how two records merge, and `arcadekit/save` does the rest.

Sound: `src/app/sounds.ts` lists the sounds in `public/sounds/` (each id is its file name, `Sounds.list`) and which one each cue plays (`Sounds.byCue`); the genre's sound view plays them as its cue counters rise, and the aura hums while a hero carries it and the run is moving. The menus have one music loop and a run another (`Sounds.music`), crossfading as a run starts and ends; pausing turns the music down. The menu and pause screens have volume sliders and a mute button, kept in localStorage under `arcadekit/survivors/settings` (`SurvivorsAudioSettings`, in `src/app/audio-settings.ts`), apart from the save; M mutes on any screen. Nothing plays until the first click or key press. In co-op every player hears the whole fight, their own hero's hurt and down loudest.

Art: one sprite sheet, `public/sprites/survivors.png` and `.json` (Aseprite's export format), made by `pnpm sprites`. `src/app/main.ts` provides it as the genre's `SurvivorsSheet` asset (with `Sheet.url` in `src/app/sheet.ts`), and `LoadContent` loads it beside the content; if it can't be loaded, the loading screen shows the error and a "Try again" button, which loads again only what failed and goes to the menu. The engine and the co-op client draw from the same loaded sheet. The view draws pixel art seen straight down: a 24 px hero standing on a ring in its player slot's colour (how co-op players tell their heroes apart), 16 px enemies, gems by value, bright projectiles with a trail, the aura in whole pixels, and a calm arena with a stone wall. `public/sprites/README.md` lists the tags and how to replace the art; `test/app/sheet.test.ts` checks the sheet has every tag the content names.

With about 750 enemies, three maxed weapons and 480 XP gems on screen, one simulation step takes about 0.3 ms.

### Co-op

2 to 4 players, each in their own browser, play one run in lockstep. `pnpm dev` runs the demo under `alchemy dev`, which serves the site and the signalling worker together, with no Cloudflare account ([the demo's README](examples/survivor-demo/README.md) has the details, and how to deploy). Pick **Co-op** in two windows. One player hosts and reads out the join code; the others join with it. Everyone picks a hero, and the host starts. The host sends the run's seed and content hash at the start; a player whose content differs refuses to start, with a message naming both hashes, and the host's run goes on without them. The view follows your own hero. A level-up freezes the run until every player has picked; Escape pauses it for everyone until you resume, while your hero is playing: a hero that is down holds no pause. If a player's input stops arriving, everyone sees "Waiting for …", and the host removes that player after about 10 s. A desync, being removed or losing the host stops the run with a message saying which. Co-op runs aren't saved as records.

The kit's Co-op client ([`arcadekit/net/browser`](docs/guides/coop.md)) runs co-op: the lobby over the signalling worker, then a lockstep session it ticks on a worker's timer and draws on animation frames. The genre declares it: `SurvivorsCoop` in `src/survivors/browser/` is a `Coop` made from `SurvivorsEngine` (a lobby pick is a hero id), so the engine's view follows the local player's hero in both. The app keeps the screens and the Foldkit glue: `SurvivorsCoop.layer` provides the client over the app's rooms (`src/app/main.ts`), Commands call it, and a Subscription turns what it reports into Messages with `SurvivorsCoop.match`. The banner over a frozen run names who it waits on from the HUD's flags: who is choosing an upgrade, and who holds the pause. A player's pick and pause are the genre's commands, `ChooseUpgrade` and `HoldPause`, sent with the client's `send`: each rides the player's next step, and every peer's rules take or refuse it there. Escape opens the run's menu, which asks the run for the pause and follows the rules' answer: it says the run is paused only while they hold the pause for this player, and it stays up either way, since it is the way to leave the run (a player whose hero is down gets it without a pause). A guest whose game lacks a hero the host started with refuses the start, with a message. The app's rooms are on the signalling worker at the page's own origin, since one Worker serves both (`src/app/rooms.ts`); `VITE_STUN_URLS` sets the STUN servers (default `stun:stun.l.google.com:19302`; comma-separated, or empty for none).

`pnpm test:e2e` checks co-op end to end: it starts the demo under `alchemy dev` (in a stage of its own, `e2e`), opens two Chromium pages that host and join, plays with different inputs on each until both have picked an upgrade, has each hold the co-op pause in turn (the other page says who paused, and the run's clock stands on both), and checks that both report the same state hashes at the same steps with no error (each page's run, as the app puts it on a global in development: `CoopDebug`, in `src/app/coop-debug.ts`). Then it hides the guest's tab for real (a Chromium of its own, with a second tab in front, so its main-thread timers drop to about once a second) and checks that the run keeps stepping at full rate past the host's 10 s drop-out, with no one removed. It isn't part of `pnpm test`, since it needs Chromium and workerd and takes about a minute. It skips itself when Playwright or Chromium is missing, or when `alchemy dev` doesn't start.

`pnpm test:browsers` checks that every browser engine computes the same run. It bundles survivors' simulation, `Game.Loop` and the long run that `examples/survivor-demo/test/survivors/determinism.test.ts` pins in Node (`src/survivors/internal/long-run.ts`: three seeds, 20,000 steps each, a full horde under an analog stick), serves the bundle to Chromium, Firefox and WebKit through Playwright with no network, and checks that each gives the recorded final hash and the same trace hash after every step. On a mismatch it names the first step whose state differs from Node's. It takes about 15 s with Chromium alone. A browser Playwright can't launch is skipped with a message; with `CI` set it fails instead. Install the browsers with `pnpm exec playwright install --with-deps chromium firefox webkit`. CI runs it in all three browsers through `.github/workflows/cross-browser.yml`, which caches the browsers by Playwright version.

## The push-puzzle demo

Levels live in `examples/push-puzzle-demo/public/content/levels.json`, as rows of standard Sokoban text plus `^` for a hole: `#` wall, space floor, `@` player, `+` player on goal, `$` box, `*` box on goal, `.` goal. A box pushed into a hole fills it. They're checked against `src/push-puzzle/puzzle-content.ts` at load, and `examples/push-puzzle-demo/test/content.test.ts` plays a known solution for each level, as a scenario.

Arrows, WASD or the d-pad move one cell per press (hold to repeat), and so does a swipe on a touch screen; Z, Backspace or B undo; R restarts; Escape goes back to level select; M mutes on any screen.

Level select marks each solved level with its best move count, and the Solved screen says when a solve is a new best. The save keeps them in localStorage under `arcadekit/push-puzzle/save`. `src/app/level-records.ts` says what a level's record holds, `src/app/save.ts` declares the save and how two records merge, and `arcadekit/save` does the rest.

Sound: `src/app/sounds.ts` lists the sounds in `public/sounds/` (each id is its file name, `Sounds.list`) and which one each cue plays (`Sounds.byCue`: `move`, `push`, `hole`, `undo`, `solved`); the genre's sound view plays them as its cue counters rise. One music loop starts with the app and is heard after the first click or key press. Level select has volume sliders and a mute switch, kept in localStorage under `arcadekit/push-puzzle/settings` (`PushPuzzleAudioSettings`, in `src/app/audio-settings.ts`), apart from the save.

Art: one sprite sheet, `public/sprites/push-puzzle.png` and `.json` (Aseprite's export format), made by `pnpm sprites`. `src/app/main.ts` says where the genre's sheet comes from (`PushPuzzleSheet.layer`, with `Sheet.url` in `src/app/sheet.ts`), and `LoadContent` loads it beside the levels; if it can't be loaded, the loading screen shows the error, as for levels that can't be loaded, and a "Try again" button, which loads again only what failed and goes to level select. The view draws the board at the largest whole pixel scale that fits, and needs the tags in the genre's `Art.tags` (the first of each name; the ones after are what it draws without it); `public/sprites/README.md` lists them and how to replace the art.

## Releasing

The `arcadekit` package releases with [Changesets](https://github.com/changesets/changesets).

- A PR that changes the package adds a changeset: `pnpm changeset` ([.changeset/README.md](.changeset/README.md)). Below 1.0, a breaking change is a minor bump, and its changeset says how it breaks.
- On `main`, the release workflow (`release.yml`) opens a "Version packages" PR. Merging it publishes to npm with trusted publishing (OIDC from GitHub Actions, with provenance), so no npm token is stored.
- `package-checks.yml` runs `pnpm build:packages`, `pnpm lint:packages` and `pnpm smoke` on every PR. `pnpm release` builds and lints before it publishes.
- npm can only trust a workflow for a package that exists, so the name `arcadekit` is claimed once from the maintainer's machine with a placeholder `0.0.0`. `bash scripts/npm-setup.sh` walks through it step by step: the placeholder, the trusted publisher, the first real release (`0.3.0`, from CI), and deprecating the nine `@arcadekit/*` packages it replaces.

## Not done yet

- **The one-package release.** `arcadekit` 0.3.0 isn't on npm until `scripts/npm-setup.sh` has been walked through: see [Releasing](#releasing). Until then npm has the nine `@arcadekit/*` packages at 0.2.3.
- Real art and sounds: the demos draw generated pixel art and play generated placeholders.
- A public deployment, and TURN. `alchemy deploy` puts the demo and its signalling worker on Cloudflare, but none is public yet (the worker needs rate limits first: see its README), and two peers behind symmetric NATs can't connect without TURN.
- Cross-browser lockstep: the end-to-end co-op test runs in Chromium only. `pnpm test:browsers` checks the simulation itself in Chromium, Firefox and WebKit, but Linux WebKit isn't Safari (whose JavaScriptCore uses Apple's libm), and nothing runs on Windows or macOS yet.
- More in the save. A `Save` holds records by id only: no unlocks and no run in progress. A `Setting` holds one value beside it. Every save is at version 1, so there is no migration API yet.
- Foldkit's Vite plugin for keeping UI state across live reloads. It's left out because engine state isn't preserved, so a reload mid-run would show a "Playing" UI with no run.
- Browsers pause `requestAnimationFrame` in hidden tabs, so a single-player run pauses when you switch tabs. A co-op run keeps going: it steps on a timer in a Web Worker, which a hidden tab doesn't throttle, and only stops drawing. A player whose game really stalls (closed, or frozen by the browser) holds the others up until the host removes them after about 10 s.
