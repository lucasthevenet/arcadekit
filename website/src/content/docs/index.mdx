## Declare the rules. Step them. Ship.

Most game libraries give you a renderer and a loop, and leave the rules to callbacks on objects. arcadekit gives a game its shape, so you can spend your time on how it plays.

<CardGrid>
  <Card title="The same run, everywhere">
    A fixed-step clock, a seeded random generator and exact math. The same seed
    and inputs give the same run on every peer, in every replay and in every
    test. [Explore determinism](/concepts/determinism)
  </Card>
  <Card title="A game is declared">
    Each part of a game is one named class: its events, its commands, its rules
    and its engine. The rules have no DOM, so they run in a test, a worker or on
    a server. [Explore declarations](/concepts/declarations)
  </Card>
  <Card title="Fast where it counts">
    A step is plain code over typed arrays, and allocates nothing per entity.
    Loading, saves, sound and connections are Effect, with typed errors and
    scopes. [Explore steps and frames](/concepts/steps-and-frames)
  </Card>
</CardGrid>

## Tests that read like the rules.

A scenario steps the real simulation: given a run, after these steps and commands, it reported these events. No browser, no mocks, no waiting on frames.

```ts
import * as Game from "arcadekit/game";
import * as Scenario from "arcadekit/game/scenario";
import { Schema } from "effect";
import { it } from "vitest";

class DoorOpened extends Game.Event("DoorOpened", { atStep: Schema.Int }) {}

class Door extends Game.Simulation("Door", {
  input: Schema.Struct({ lever: Schema.Boolean }),
  events: [DoorOpened],
  create: (config: { readonly needed: number }) => ({
    needed: config.needed,
    held: 0,
    open: false,
  }),
  step: (door, input, { report, step }) => {
    door.held = input.lever ? door.held + 1 : 0;
    if (!door.open && door.held === door.needed) {
      door.open = true;
      report(new DoorOpened({ atStep: step }));
    }
  },
}) {}

const scenario = Scenario.make(Door);

it("opens once the lever has been held long enough", () =>
  scenario(
    Scenario.given({ needed: 3 }),
    Scenario.step({ lever: true }, 2),
    Scenario.reported(),
    Scenario.step({ lever: true }),
    Scenario.reported(new DoorOpened({ atStep: 2 }))
  ));
```

## Co-op in lockstep.

Two to four players, each in their own browser, play one run. Peers send each other nothing but their inputs: a step runs once every player's input for it is in, and state hashes catch a desync at the step it happens. Players join with a code, through a signalling worker you deploy beside your site.

## Everything a game needs.

Input, drawing, sound, content and saves, each in the same shape: declared once, provided by a Layer, and plain where a frame runs.

<CardGrid>
  <Card title="Input">
    Keyboard, gamepad, touch drags and swipes, read as your game's named axes
    and buttons. A step never sees a device. [Explore input](/guides/input)
  </Card>
  <Card title="Pixel art">
    Sprite sheets with animated tags, tile layers that draw only what is on
    screen, and thousands of sprites in one draw call. [Explore

  </Card>
  <Card title="Sound">
    One-shots with pitch and volume jitter, loops held from state, music with
    crossfades, and buses for the player's volumes. [Explore

  <Card title="Content">
    Levels, waves and heroes as JSON, checked by a Schema as they load, and

## Effect, inside and out.

If your app already uses Effect, arcadekit carries the same tools into the game. If Effect is new to you, it is part of the learning curve.

- Every load, save, attach and connection is an Effect, with its errors in its type.
- Events, commands, content and saves are Schemas, so what crosses a boundary is checked.
- A game's parts are services, provided by Layers and closed with their scope.

<p class="eyebrow">Fit</p>

## Is it a fit?

arcadekit asks for a shape: the rules as a deterministic simulation, and Effect around them. That is a real commitment.

<div class="fit">
<div>

### A strong fit

- **Effect developers who want to make games.** The services, Schemas and Layers you know carry into the game.
- **Games that need replays, tests or co-op.** Determinism is the default, so all three come with the shape.
- **Arcade, action and puzzle games for the web.** Games that load fast in a tab and step at a fixed rate.

</div>
<div>

### Think twice when

- **You want a visual editor.** arcadekit is code first: there is no scene editor and no asset pipeline.
- **Your game needs physics.** There is no physics engine: a collision is what your step computes over a spatial grid.
- **You would rather not use Effect.** It is throughout: its services, Schemas and Layers hold a game together.

</div>
</div>
