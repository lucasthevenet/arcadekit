## Systems are Effects. Loops are plain.

A system is one Effect per tick: it asks for the time, the world's random numbers and the game's services with `yield*`, and fails with typed errors. Inside it, the loop over entities is a plain function over typed arrays, because an Effect per entity would be 25 times slower.

```ts
const Position = Component.define("game/Position", {
  x: Field.f32,
  y: Field.f32,
});
const Velocity = Component.define("game/Velocity", {
  x: Field.f32,
  y: Field.f32,
});

const Moving = Query.all(Position, Velocity).pipe(Query.reads(Velocity));

const Movement = System.make("game/Movement", function* () {
  const { delta } = yield* Time;
  (yield* Moving).each((position, velocity) => {
    position.x += velocity.x * delta;
    position.y += velocity.y * delta;
  });
});

Browser.runMain(App.run({ systems: [Movement] }, { hz: 60 }), {
  target: canvas,
});
```

## The same inputs, the same game.

A tick reads its time from `Time`, its randomness from a seeded `Random`, and its input from actions that are logged. Nothing else reaches it. So the world's hash after a tick is the same on every machine, and everything below comes from that.

## Drawing never changes the game.

The rules tick at a fixed rate. What draws, plays sound and tells a UI runs between ticks, in the frame stage, with the world frozen. What the devices say reaches the game as actions, before a tick. A game that is drawn is the same game as one that is not, so a server or a replay runs the rules alone, under Node.

## Is it a fit?

arcadekit asks for a shape: the rules as systems over a world, and Effect around them.

<div class="fit">
<div>

### A strong fit

- **Games that need replays, saves or network play.** Determinism is the default, so all three come with the shape.
- **Games with many things moving.** Typed-array columns and raw loops keep a hundred thousand entities in a quarter of a millisecond.
- **Developers who already use Effect.** Services, layers, schemas and typed errors hold a game together.

</div>
<div>

### Think twice when

- **You want a visual editor.** arcadekit is code first: there is no scene editor and no asset pipeline.
- **Your game needs physics.** There is no physics engine: a collision is what your systems compute.
- **You need it stable.** The design is a first cut and changes when that improves it.

</div>
