## Systems are Effects. Loops are plain.

A system is one Effect per tick. It gets the time, random numbers and your services with `yield*`, and fails with typed errors. Inside it, the loop over entities is a plain function over typed arrays, which runs about 25 times faster than an Effect per entity.

```ts
const Position = Component.define("game/Position", {
  x: Field.f32,
  y: Field.f32,
});
const Velocity = Component.define("game/Velocity", {
  x: Field.f32,
  y: Field.f32,
});

const Moving = Query.all(Position, Velocity).pipe(Query.writes(Position));

const Movement = System.make("game/Movement", function* () {
  const { delta } = yield* Time;
  (yield* Moving).each((position, velocity) => {
    position.x += velocity.x * delta;
    position.y += velocity.y * delta;
  });
});

Browser.runMain(
  App.run(App.make(App.define({ systems: [Movement] })), { hz: 60 }),
  {
    target: canvas,
  }
);
```

## The same inputs, the same game.

A tick reads its time from `Time`, its randomness from a seeded `Random`, and its input from logged actions, and nothing else. The world's hash after each tick is identical on every machine, and the features below are built on that guarantee.

  <Card title="Replays">

  <Card title="Saves">

<p class="eyebrow">Ticks and frames</p>

## Drawing never changes the game.

Your rules tick at a fixed rate. Rendering, sound and UI updates run between ticks, in the frame stage, where the world is read-only. Device input reaches the game as actions before each tick. Drawing never affects the simulation, so a server or a replay runs the rules alone, under Node.

## Is it a fit?

arcadekit expects a particular shape: your rules as systems over a world, with Effect around them.

<div class="fit">
<div>

### A strong fit

- **Games that need replays, saves or online play.** Determinism is the default, so all three come with the shape.
- **Games with many moving things.** Typed-array columns and raw loops move a hundred thousand entities in a quarter of a millisecond.
- **Developers who already use Effect.** Services, layers, schemas and typed errors structure the whole game.

</div>
<div>

### Think twice when

- **You want a visual editor.** arcadekit is code-first, with no scene editor and no asset pipeline.
- **Your game needs physics.** arcadekit has no physics engine: your systems compute collisions.
- **You need a stable API.** arcadekit is alpha, and its API changes between minor versions.

</div>
